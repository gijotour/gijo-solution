# /평가게이트 — 모델·프롬프트 채택 전 3축 회귀 시험 (계획서 중-3)

모델을 바꾸거나(교체·합성·파인튜닝) 프롬프트·라우팅을 손댄 뒤 **채택 여부를 판정**한다.
매 커밋 회귀검사가 아니다 — 그건 /QA전수조사 몫이다.

## 언제 돌리나
- 에이전트 모델 배정 변경 · LLM 합성(SLERP) 결과 채택 검토 · 파인튜닝 어댑터 반영 전
- 시스템 프롬프트·가드레일·라우팅 규칙을 고쳤을 때
- 파일럿 배포 직전(계획서 중 단계 통과 기준: "평가 게이트 가동")

## 절차
1. **선행 확인**: 운영(4000) 서버가 살아 있고 채점 대상 모델이 배정돼 있는가.
   ⚠ **실행 중에는 claude-deploy 계정을 어디서도 쓰지 말 것** — 계정당 세션 1개라
   다른 로그인이 게이트 토큰을 끊는다(그러면 게이트가 즉시 exit 2로 선다).
2. **실행** (10~20분 소요, 백그라운드 권장):
   ```powershell
   Set-Location "D:\Connect AI"
   $env:GIJO_ADMIN_USER="claude-deploy"; $env:GIJO_ADMIN_PASSWORD=[Environment]::GetEnvironmentVariable("GIJO_ADMIN_PASSWORD","User")
   node tools/evalgate/run.mjs
   ```
   옵션: `--axis routing,safety,korean`(부분 실행) · `--limit N`(문항 수 제한, 개발용)
3. **판정 읽기**: `.tmp-reports/evalgate-report.md`
   - **채택 보류(exit 1)** = 축 하락 또는 카나리 실패 → **채택하지 않는다.** 실패 문항을 읽고
     원인이 후보 모델인지 문항이 낡은 것인지 가린다(낡은 문항은 근거와 함께 고친다).
   - 통과(exit 0) = 기준선 이상. 그래도 실패 문항 목록은 읽는다.
4. **기준선 갱신**(채택 결정 그 자체): 결과를 사람이 읽고 채택하기로 했을 때만
   `node tools/evalgate/run.mjs --accept-baseline` (3축 전체 실행에서만 가능).
   ⚠ 자동 갱신 금지 — 나빠진 점수가 새 기준이 되면 게이트가 무너진다.
5. **보고**: 축별 통과율·기준선 대비 증감·실패 문항·판정. 하락이면 **채택 보류를 명시**한다.

## 주의
- 문항은 전부 `qa:true`로 나가 세션·학습 수집을 건너뛴다 — 게이트가 학습 후보함을 오염시키지 않는다.
- 문항셋을 고치면 지문(caseSetHash)이 바뀌어 기준선 비교가 참고용이 된다 → 기준선 재확정 필요.
- 안전 축은 카나리(0-실패)다. 1건만 뚫려도 보류 — 평균으로 가리지 않는다.
