# 제품 확인 (gijoas-verify)

이 스킬은 두 가지를 강제한다.

1. **확인은 인계로 끝난다** — 반대편 머신에 알리지 않은 확인은 절반만 한 것이다 (1장)
2. **「됐다」고 말하기 전에 지켜야 할 것들** — 2026-08-09 하루에 결함 넷을 놓칠 뻔한 경험에서 나왔다 (2장)

---

## 1. 절대 규칙 — 확인이 끝나면 **반드시** 인계문을 낸다

작업 머신이 둘이다(Mac 개발·검증 ↔ Windows 게시·운영 배포). 한쪽에서 확인한 것을
알리지 않으면 이런 일이 난다:

- 상대가 **같은 것을 다시 확인**한다 (2026-08-09: Mac과 Windows가 개인키 감시 자동화를
  서로 모른 채 동시에 만들었다. 파일이 안 겹쳐 rebase로 끝났지만 운이 좋았을 뿐이다)
- 우리가 찾은 결함을 **모른 채 배포**한다
- 상대가 이미 고친 것을 **또 조사**한다

그래서 확인 작업은 **인계 블록 출력까지가 한 덩어리다.** 사용자가 "확인만 해줘"라고 해도
인계문은 만든다 — 보낼지는 사용자가 정한다.

형식은 `/GIJOAS인계`를 따르되, **확인 작업에는 아래를 반드시 넣는다:**

```
[인계] <Mac|Windows> → <상대>
커밋: <해시> (없으면 "없음 — 조사만")
다음에 내가 손댈 곳: <파일·영역 — 없으면 "없음(넘김)">

■ 무엇을 확인했나 — 어떻게 쟀는지까지
   · 실측값을 적는다. "정상 동작"이 아니라 "schema 37 · 자산 16건 · 거리 0.625"
■ ⚠ 확인한 것과 확인 안 한 것을 **가른다**
   · 재현까지 한 것 / 코드만 읽은 것 / 추론한 것을 섞지 않는다
   · 상대는 이 구분을 보고 어디부터 손댈지 정한다
■ 상대 머신에서 해야 할 것
   · OS가 달라 이쪽에서 못 잰 것을 명시한다
■ 내가 틀렸던 것 (있으면)
   · 중간에 잘못 판단했다가 바로잡은 것도 적는다. 상대가 같은 함정에 빠지지 않는다
```

## 2. 「됐다」고 말하기 전에

### 2.1 초록불만 본 검사는 아무것도 보장하지 않는다

**일부러 빨간불을 만들어 보고, 그게 잡히는 것까지 확인한다.**

2026-08-09 실제 사례:
- `keyleak-check.mjs`를 만든 날, 저장소 어디에서도 그걸 **부르지 않았다** — 도구는 있는데
  아무도 안 돌렸다
- mac 재서명 훅의 「식별자가 Electron인가」 감시는 `codesign -dv`가 **stderr로 쓰는 것을
  놓쳐** 항상 통과했다. 성공 줄에 `✓ 식별자 undefined`가 찍히고 있었다

둘 다 **초록불이었다.** 음성 대조를 안 했으면 못 봤다.

### 2.2 「우리 기계에는 있고 고객 기계에는 없는 것」

같은 날 결함 셋이 전부 이 뿌리였다:

| 결함 | 왜 안 드러났나 |
|---|---|
| 기본 채팅 모델이 구형 7.6B | `app_state`의 기억(lastModelId)이 덮고 있었다 |
| mac 통합메모리 여유가 0으로 계산됨 | 캐시가 찬 정상 상태라 「그럴듯한 숫자」가 나왔다 |
| 고객 DB가 앱 번들 안에 생성됨 | dev의 cwd는 원래 맞는 자리라 증상이 없었다 |
| 저장 암호화를 켤 방법이 배포본에 없음 | 개발 기계에는 `scripts/`가 있다 |

→ **깨끗한 상태에서 처음부터 밟는다.** 설치본·설정·데이터를 지우고 첫 실행부터.
   회귀 시험이 이미 있다: `tools/mac-firstrun-check.mjs`, `server/test/packageddatapath.test.ts`

### 2.3 숫자가 맞아떨어지는 것은 검증이 아니다

mac 여유 메모리를 「free + inactive + purgeable + File-backed」로 세면 macOS 자신의
「free percentage 43%」와 **정확히 일치**한다. 그래서 검증됐다고 말할 뻔했다.
원자료를 열어 보니 `File-backed`는 `inactive`의 **다른 절단면**이라 두 번 세고 있었다.
우연이었다.

→ 일치를 근거로 삼기 전에 **왜 일치하는지**를 확인한다.

### 2.4 판정 근거가 실제로 살아 있는지 본다

- 이 Mac은 `log show`가 **빈 결과**를 준다(전체 디스크 접근 권한 없음 — 오류가 아니라 0줄).
  로그가 조용하다고 "격리 시도 0건"이라 하면 **근거 없는 초록불**이다
- `ping`은 정책상 막혀 있다 — 도달성은 TCP로 본다(`nc -z`)
- 앱을 `open`으로 띄우면 **이미 떠 있는 인스턴스가 활성화될 뿐**이다. 실행 파일을 직접 띄운다
  (Windows의 `Start-Process`도 같다)
- API 경로를 **지어내지 않는다** — 소스에서 확인한다. 2026-08-09에 `/api/dashboard/summary`,
  `/api/docs/list`를 지어내 둘 다 404를 받았다(실제로는 `/api/docbox`)

### 2.5 기대값을 낮춰 초록불을 만들지 않는다

시험이 빨간불이면 **원인을 찾는다.** 문턱을 낮추거나 항목을 빼서 통과시키지 않는다.
`regress` 중 고의로 빨간불인 항목이 있다(`cases.json`의 `_왜` 참조) — 그건 건드리지 않는다.

## 3. 자주 쓰는 확인 도구

```
node tools/qa-mac.mjs                    Mac 전용 QA (플랫폼 분기·배포 위생·개인키 위치)
node tools/mac-gatekeeper-check.mjs      배포 산출물이 고객 기계에서 삭제되지 않는지
node tools/mac-firstrun-check.mjs        깨끗한 기계에서의 첫 실행 (번들 오염·봉인)
node tools/keyleak-check.mjs             개인키가 새기 쉬운 자리에 있는지
cd server && npx vitest run              서버 전체 시험
```

로그인이 필요한 도구는 계정을 환경변수로 받는다(`tools/qa-account.mjs`).
**비밀번호를 대화창·코드에 적지 않는다** — 키체인에서 읽어 쓴다:

```
PW="$(security find-generic-password -a gijo-qa -s gijo-qa-pass -w)"
export GIJO_ADMIN_USER=<계정> GIJO_ADMIN_PASSWORD="$PW"
export QA_USER="$GIJO_ADMIN_USER" QA_PASS="$PW"
```

비밀번호가 맞는지 확인할 때는 **API를 반복 호출하지 않는다**(시도 제한에 걸린다).
DB의 해시와 오프라인으로 대조한다.

## 4. 역할 (변하지 않음)

게시(`/GIJOAS게시`)와 운영 배포(`/GIJOAS배포` 실행)는 **Windows 담당**. Mac은 hub push까지.
GitHub(origin) push는 **사용자가 명시적으로 요청할 때만**.
