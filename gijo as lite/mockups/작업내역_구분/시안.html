한눈에 — 핵심 결정 3가지
  1. 기본값을 뒤집는다 — "다 남기고 문제되는 걸 뺀다" → "담당자가 실행한 일만 기본 표시, 시스템이 한 일·조회·QA는 접힘(토글 한 번으로 열림)".
  2. 화면은 그대로, 축만 얹는다 — 새 화면·새 탭을 만들지 않는다. 지금 있는 sessions.html 뼈대(검색·필터·목록·상세) 위에 주체(내가/시스템) · 종류(실행/조회) 두 축과 QA 표시 하나를 얹는다.
  3. State Folding — 대화가 아니라 값으로 접는다 — 목록 한 줄·상세 첫 화면은 "자산·대상·조치·결과"를 그대로 이어붙인 한 줄이다. AI가 새로 요약하지 않는다 — 지어낼 수 없는 값 조합이라서다.
⚠ 정직한 구현 고지 — 아래 재현(D절)은 실제로 작동한다: 검색·축 필터·QA 토글·행 선택·접기/펼치기는 이 파일 안에서 진짜로 눌러집니다(가짜 데이터 20건). 다만 삭제·이름변경·리포트 만들기·대화창 이동·감사 화면 이동처럼 화면 밖으로 나가거나 데이터를 바꾸는 동작은 자리만 있고 눌러도 동작하지 않습니다(회색 점선 표시) — client/·server/는 이 작업에서 한 줄도 고치지 않았습니다.

❌ 버린 안 1 — 탭으로 가르기(예: [작업내역][시스템기록][QA] 세 개의 별도 탭)

탭은 서로 다른 세계로 완전히 갈라놓는다 — 다른 탭에 가지 않는 한 "거기 몇 건 있는지"조차 기본 화면에서 안 보인다. 이번 시안의 핵심 원칙(감췄으면 감췄다고 보이게, hidden-note가 실시간 숫자를 곁에 둠)을 탭 구조는 태생적으로 어긴다. 이미 sessions.html엔 상태 칩(전체/진행중/완료/무시)이 있어 탭까지 얹으면 "칩이야 탭이야"가 헷갈린다.

❌ 버린 안 2 — 필터칩만 추가하고 기본값은 그대로 "전체"

이러면 "선택적으로 남긴다"는 지시의 핵심(기본값 뒤집기)이 빠진다. 필터가 있어도 기본이 "전체"면 담당자는 굳이 필터를 쓸 이유를 모른 채 예전처럼 뒤섞인 목록을 계속 본다 — 지금도 상태 칩이 있는데 로그인 도배·재귀 사고가 3번 났다는 사실 자체가 "필터만으론 안 됐다"는 증거다(A절).

❌ 버린 안 3 — 화면을 완전히 새로 쪼갠다(예: "시스템기록.html"을 새로 만든다)

감사(audit.html)와 작업내역(sessions.html)은 이미 나뉜 화면이다 — 다시 쪼개는 게 아니라, 지금 작업내역 안에 824건이 사람·시스템·조회·QA 뒤섞인 채로 쌓이는 게 문제다. 새 화면을 또 만들면 nav 메뉴가 다시 늘어 ("메뉴 29→26 정리" 성과를 되돌리는 셈), 담당자가 "이건 어느 화면에서 찾지"를 다시 배워야 한다. 축 필터는 한 화면 안에서 답을 준다 — 새 화면보다 학습 비용이 낮다.

G무엇을 포기했는지

뺀 것왜
기억(AI 학습) 계층으로 보내는 화면상 버튼(예: "학습 후보로 보내기") 파이프라인 배지(3층 표시)까지만 이번 범위 — 그 계층은 이미 memory 화면이 따로 있고, 이번 요청은 감사↔작업내역 경계다. 새 액션을 더하면 범위가 부풀어 검토가 늦어진다. 다음 과제 후보로 남긴다.
기존 상태(진행중/완료/무시) 필터 줄 화면에 이미 필터 줄이 3개(검색·축①·축②) + 토글 1개다. 상태까지 5번째 줄로 넣으면 오히려 복잡해진다 — 상태는 각 행의 점(●)으로 계속 보이고, 필요성이 확인되면 다음에 되살린다.
오래된 내역 정리(prune)·전체 삭제·골라서 리포트 같은 기존 부속 기능의 재설계 자리는 그대로 두되(회색 점선) 새로 설계하지 않았다 — 이번 범위는 "분류 축"이지 "정리 기능"이 아니다.
운영 DB에서 QA·시스템·조회 실제 건수를 다시 세는 것 mockups/ 밖에 쓰기·서버(4000) 접속이 이 에이전트 권한 밖이다. 대신 코드를 직접 읽어(worksessions.ts· dispatcher.ts·actioncheck.ts) 근거로 삼았다 — 추측이 아니라 코드 확인.
audit.html 쪽 변경(예: "여기서 숨겨진 걸 보려면 →" 역방향 안내) 이번 시안은 sessions.html(작업내역) 하나만 다룬다. audit.html은 검색+CSV 내보내기만 있는 단순 화면이라 지금 상태로도 3층 모델의 "감사" 축에 문제가 없다고 판단했다 — 손대지 않았다.
