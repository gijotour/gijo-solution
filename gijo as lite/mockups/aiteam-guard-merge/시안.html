① 왜 이 안인지 — 별도 메뉴 유지 대안과 비교
  • 이미 있는 "허브+탭" 계약을 그대로 쓴다. AI 허브(aihub.html)는 이미 4탭 구조로 팀·지식·학습·안전장치를 담고 있다 — 새 시각 언어·새 창을 만들지 않고, 유일하게 허브 밖에 남아 있던 「AI 팀 감독」 하나만 안으로 들인다. 변경 표면이 nav.js 1줄 삭제 + TAB_REDIRECT 2줄 + grouppanels.js 판 하나 교체로 끝난다(저위험).
  • 엑셀형(.g-rows)은 이미 승인된 부품이다. 2026-08-20 지식 패널(mockups/knowledge-rows)에서 같은 부품·같은 색 토큰으로 이미 검증됐다 — 새 CSS 구조를 발명하지 않는다.
  • 요약(읽기)과 실행(쓰기)을 화면 단위로 분리한다. 조사 [1]의 요약 우선/드릴다운 원칙을 그대로 따라, 실행·모드변경·모델배정은 각자의 전용 화면에 남기고 새 화면은 "다 보여주되 아무것도 바꾸지 않는" 순수 요약 층으로 만든다 — "화면에 새 실행 버튼·입력칸 금지"라는 이번 요청의 경계와도 정확히 맞는다.
기각한 대안
  • 현행 유지(안전장치·감독을 지금처럼 따로 둠) — 사장님 요청을 정면으로 안 따르는 선택지라 기각. "AI팀 메뉴에 다 통합"이 명시적 지시다.
  • 팀·감독·안전을 완전히 한 화면·한 스크롤로 합치되 agent.html·redteam.html 화면 자체를 없앰 — 모델 배정 select·레드팀 실행 버튼 같은 쓰기 조작까지 옮기면 "메뉴는 보기용" 원칙(project_console_is_the_input)이 깨진다. 또 파일 삭제는 wiringcontract·screenguide·menu-scenarios 등 감시 목록 전부를 동시에 건드려야 해 변경 표면이 커진다 — 기각.
  • 안전장치 탭 내용만 엑셀형으로 바꾸고 「AI 팀 감독」은 그대로 독립 메뉴로 둠 — "엑셀처럼 촘촘하게"는 만족하지만 "AI팀 메뉴에 통합"은 절반만 만족한다(감독이 여전히 허브 밖). 이번 요청의 핵심 문장("한 자리에서 읽히게")을 못 채워 기각.
② 무엇을 포기했는지
  • 카테고리별 취약률 막대 그래프. "한눈에 비율을 본다"는 값어치가 있지만 엑셀형 요청과 정면으로 상충한다(막대=디자인 요소). 심각도·판정을 문자 컬럼으로 대체 — 정렬·스캔은 오히려 더 쉬워진다.
  • 공격 프롬프트·모델 응답 원문 전문. 통합 화면은 "무엇이 걸렸는지"까지만 보여주고, "정확히 뭘 물었고 뭐라 답했는지"는 redteam.html 원본에서만 — 원문은 화면이 아니라 실행 로그의 몫이라 판단.
  • 팀원 협업 로그(누가 누구에게 무엇을 넘겼는지, agent.html chat-feed). 팀 사무실(office.html)이 이미 실시간으로 담당한다 — 같은 것을 두 번 만들지 않는다.
  • 완화 — 필요하면 링크 한 번. 원문·막대·협업 로그 전부 "없앤" 게 아니라 "이 화면 밖으로 뺀" 것이다. §1·§3 하단 링크(구성 바꾸기 → agent.html / 실행 화면 열기 → redteam.html)로 1클릭 이동한다.

④ 제품 원칙 자가점검
  • ✅새 입력칸 0개. 통합 화면 어디에도 텍스트 입력·모드 토글·실행 버튼이 없다. 유일한 조작은 그룹 접기·행 클릭(📌)·기간 칩(표시만)뿐 — 전부 "고르기/펼치기"이지 "값 넣기·실행"이 아니다.
  • ✅쓰기는 결재판·전용 화면 경로 그대로. 레드팀 실행·가드레일 모드 변경·팀원 모델 배정은 옮기지 않고 agent.html·redteam.html에 남겼다. (다만 redteam.html 자체의 ▶ 버튼은 예전부터 결재판을 거치지 않는 화면-직접 호출이다 — 이 시안이 만든 문제가 아니고, 고치는 것도 이 시안의 범위가 아니다. 정직하게 위 "현행 확인"에 적었다.)
  • ✅설명은 ⓘ/screenguide로. 이 문서(왜·근거·대응표)는 시안에만 있는 결정 문서이지 제품 화면 문구가 아니다. 실제 구현 화면엔 "감독 관점" 같은 규칙 계산 결과만 남고 사용법 설명은 넣지 않는다.
  • ✅제품 룩앤필 그대로. 색 토큰은 pro-white.css(L13-49) 확정값, .g-rows는 gijo-ui.css(L347-369) 그대로 복사 — 새 색·새 부품 0개.
  • ⚠파일명(구현 시 결정 필요). supervision.html 유지 vs 새 파일 분리는 이 시안이 정하지 않고 "유지 권고"만 남겼다 — wiringcontract.test.ts 등 감시 목록이 걸려 있어(위 ⑤ 참고) 결정에 따라 후속 변경 범위가 달라진다.
  • ⚠가드레일 로그 밀도는 이미 조밀했다. "엑셀형이 항상 더 조밀하다"고 과장하지 않는다(밀도표 참고) — 이미 30px에 가까운 행은 이득이 거의 없다는 것을 숨기지 않았다.
다크(표준)에서도 같은 구조가 성립한다
.g-rows는 색을 하드코딩하지 않고 var(--panel)·var(--border)·var(--zebra) 등 토큰만 쓴다. 표준(다크)은 각 화면 자체 :root(agent.html·supervision.html·redteam.html 전부 --panel:#30302e·--border:rgba(255,255,255,.08) 등 이미 정의)를 그대로 쓰면 새 CSS 구조 없이 아래처럼 성립한다 — 같은 마크업에 다크 토큰만 덮어씌운 것이다(글자 하나 안 고침).
