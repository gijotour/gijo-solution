2. 왜 이 안인지

왜 화면을 하나로 모았나 — mydocs.html 자체 주석이 "격리가 이 화면의 전부다"라고 말하는데, 정작 개인 문서 목록은 문서함(창)이 따로 또 부르고 있었다(docbox.html:245-250). 같은 데이터를 두 창이 각자 불러오면 "내가 올린 게 다 어디 갔지"를 담당자가 직접 기억해야 한다 — 그 탐색 비용이 이번 QA 질문("연관성이 있다면 하나로")의 실체다. 조사 결과(외부1)도 "여러 화면에 흩어진 업로드 관련 인터페이스를 하나로 모으면 마찰이 준다"는 같은 결론이다.

왜 3부류를 유지했나(전부 개인화도, 전부 지식창고화도 안 함):

  • ✓ 전부 「내 것」으로 만들지 않은 이유 — personalDocs는 검색이 내 질문에만 근거로 나오게 하드 격리한다(mydocs.html:11). 취약점 스캔 원본·보안제품 매뉴얼을 개인 것으로 넣으면, 인수인계 때 다음 담당자에게 "그런 문서가 없습니다"(404)로 보인다 — 회사 자산인데 개인 소유가 되어 버리는 사고다.
  • ✓ 전부 「회사 지식(RAG)」으로 만들지 않은 이유 — 개인 메모(초안· 잡담성 조사노트)까지 전역 검색 근거로 들어가면 다른 담당자 질문에 부정확한 개인 견해가 섞인다. 이 제품은 이미 그 사고를 겪었다(타사 문서 53%가 낌 — RAG 오염 전례, project_rag_contamination). 조사 결과(외부2)도 "지식 베이스는 큐레이션된, 통제된 모음" 이어야 하고 "보안 등급별로 분리 운영"을 권고한다 — 아무거나 다 넣는 것과 정반대다.
  • ✓ 스캐너 원본을 「문서(마크다운)」로 다루지 않은 이유 — Nessus CSV·syslog는 사람이 읽는 문서가 아니라 파싱해서 finding/이벤트로 바뀌는 원료다. 문서 뷰어에 넣으면 정작 쓸모 있는 형태(우선순위 표·이벤트 목록)를 감춘다. 그래서 반입 원본 탭은 "무엇으로 판정됐고 어디로 갔는지"만 보여주는 영수증이고, 실제 데이터는 기존 화면(발견·수집/통합 분석/보안제품 등록부)에서 본다 — 새 뷰어를 만들지 않았다.

3. 무엇을 포기했는지

  • △ 완전한 단일 입구는 포기했다 — 콘솔 ＋(2026-07-27 "파일은 ＋ 한 곳으로")는 그대로 두고, 이 화면에 업로드 버튼을 하나 더 놓았다. 다만 새 개념은 아니다 — mydocs.html의 📥 가져오기가 이미 personalDocsCreate를 목적지 확정 상태로 직접 호출하는 선례다(mydocs.html:142-163, 분류를 거치지 않음). 역할을 나눴다: 콘솔 ＋는 "대화 중 자연스러운 투입"(추측 후 확인), 이 화면 버튼은 "정리해서 넣기"(목적지 직접 지정). 완전히 겹치지 않는다.
  • △ 문서함의 「요청 만들기」는 새 자리를 못 찾았다 — 문서 저장이 아니라 버그·기능 요청 산출물을 만드는 도구라 이번 통합 대상이 아니다. 문서함(창)을 실제로 없애려면 이 기능이 옮겨갈 자리를 별도로 결정해야 한다(이 시안 범위 밖).
  • △ memory.html의 고급 기능을 전부 재현하지 않았다 — 지식 그래프 관계("이 파일이 만든 연결")·위생 점검(kbHygiene 중복/충돌 탐지)은 회사 지식 탭 상세 패널에 자리만 그렸다. 세부 상호작용·문구는 구현 단계에서 그대로 옮긴다(재발명 안 함).
  • △ 반입 원본의 「원본 다시 내려받기」는 조건부다 — 서버가 스캐너 원본 파일 자체를 얼마나 보존하는지 이 시안 조사로는 확인하지 못했다. 있다면 붙이고 없다면 "원문은 파싱 후 보관하지 않습니다"로 정직하게 표시해야 한다 — 구현 착수 전 반드시 확인할 것(가짜 버튼 금지 원칙).
  • △ 검색은 필터 전용으로 고정했다 — 자유 명령어를 받지 않는다 (지시는 대화창 원칙). "최근 것만", "김보안이 올린 것" 같은 자연어 질의는 이 화면이 아니라 콘솔에서 묻게 유도한다(챗봇 라우팅 범위, 이 시안이 새로 만들지 않음).

4. 밀도 숫자

5. 제품 원칙 자가점검

  • ✓ 격리 원칙 — 「내 것」은 여전히 personalDocs 그대로다. 남의 문서는 404(personaldocs.ts:126, "그런 문서가 없습니다") — 화면을 합쳐도 서버 격리 계약은 한 글자도 안 바꾼다.
  • ✓ 회사 지식 전환 전 경고 — 「🏢 회사 지식」목적지를 고르면 업로드 전에 "전 담당자와 AI가 함께 봅니다" 경고가 먼저 뜬다(destNote 데모, 기존 docbox.html toggleRag 경고 문구·패턴 재사용 — 새로 안 지음).
  • ✓ 지시는 대화창 · 새 입력칸 금지 — 이 화면의 유일한 텍스트 칸은 검색(필터 전용, readonly 취급). 목적지 선택도 자유 텍스트가 아니라 칩 3개 중 고르는 것이다.
  • △ 화면 설명은 챗봇/ⓘ로 — 화면엔 정체성 한 줄("개인 메모부터 회사 지식·스캐너 파일까지…")과 격리 경고 한 줄만 뒀다. ⓘ 아이콘 자리는 그렸지만 실제 screenguide 패널 문구는 구현 단계에서 쓴다(이 시안이 미리 지어내지 않음).
  • ✓ 자체완결 HTML — 외부 CDN·웹폰트·원격 이미지 없음. 색은 pro-white.css의 확정 토큰(2026-08-20)을 그대로 복사했다.
  • ✓ 정직한 구현 — 상단 배너로 "탭·검색·목적지 칩만 동작"을 고지했다. 행 안의 개별 버튼은 실제 동작하지 않는다고 표기했다(§안 하는 일).
  • △ 파일은 ＋ 한 곳으로(2026-07-27) — 완전 준수는 아니다. 입구가 하나 늘었다는 사실을 §포기에 명시했고, 역할(대화 중 투입 vs 정리해서 넣기)로 구분해 충돌을 줄였다 — 최종 판단은 사장님 승인 몫으로 남긴다.
