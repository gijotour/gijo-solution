# OCR — 스캔 PDF·이미지 한국어 (2026-08-21 사장님 「OCR 포함 끝까지」).
#   Windows 설치본에는 이 부품들이 **동봉돼 나간다**(tools/stage-python.mjs가 이 파일을 읽어 심는다).
#   그 밖의 환경(운영 WSL·mac·분산 모드 서버)에서는 아래 명령으로 직접 깐다:
#     cd server && venv/bin/pip install -r requirements-ocr.txt
#   ⚠ 안 깔면 extract_doc.py가 이미지를 정직하게 거절하고, 스캔 PDF는 pypdf 결과로 degrade한다
#     (기존 텍스트 PDF 추출은 회귀하지 않는다).
#   실측 크기(2026-08-22, Windows 동봉본): OCR 부품 약 270MB.
#
# ⚠ PP-OCRv6는 한국어 미지원 — extract_doc.py가 코드에서 **PP-OCRv5 한국어 모델을 핀 고정**한다.
# ⚠ 폐쇄망 배포: 한국어 v5 모델을 미리 담아야 런타임 다운로드 없이 돈다.
#   담는 것은 **2개**다(det + rec) — 각도분류(cls) 모델은 rapidocr 꾸러미에 이미 들어 있다.
#
# ── 판을 고정하는 이유 (2026-08-22 검토관 [중] 수리) ────────────────────────────
#   범위(>=)로 두면 **같은 커밋에서 빌드해도 날마다 다른 물건이 고객에게 나간다** — 「고객 A와 B가
#   다른 OCR 엔진을 받는」 상태다. 실측치(크기·속도·인식률)도 그날부터 근거가 못 된다.
#   pypdf는 이미 stage-python.mjs가 고정하고 있었는데, 정작 훨씬 큰 OCR 쪽에 그 잣대를 안 썼다.
#   ⚠ 판을 올릴 때는 **wheel이 있는지 먼저 확인**할 것 — stage-python이 `--only-binary=:all:`로
#     심어서, 그 판에 cp312·win_amd64 wheel이 없으면 빌드가 그 자리에서 죽는다.
rapidocr==3.9.2
onnxruntime==1.29.0

# ── PDF를 그림으로 바꾸는 부품 (스캔 PDF OCR 전용) ────────────────────────────
#   ⚠ **PyMuPDF(fitz)를 쓰지 말 것.** 2026-08-22에 걷어냈다.
#     PyMuPDF는 **AGPL-3.0**(또는 Artifex 상용 라이선스)이라 **우리가 배포하는 설치본에 실을 수 없다** —
#     공공·금융 납품 심사나 SBOM 점검에서 잡히면 **제품 소스 공개** 또는 **상용 라이선스 구매**를
#     요구받는다. AI-BOM·SBOM을 파는 제품이 자기 SBOM에서 걸리는 모양이 된다.
#     「고객이 알아서 pip install 하는 옵션」이던 동안에는 우리가 배포하는 물건이 아니었는데,
#     설치본에 동봉하면서 지위가 바뀐 것을 놓쳤다(게시 전 검토관이 잡았다).
#   pypdfium2는 구글 PDFium 기반이고 **BSD-3-Clause + Apache-2.0**이라 재배포에 그 의무가 없다.
#   실측: fitz와 같은 배율에서 같은 크기(±2px), 한국어 OCR 정상, import 시 stdout 오염 없음.
pypdfium2==5.13.0
