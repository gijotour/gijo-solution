# 인계 — `max` → `win` (2026-08-19) · 우리 전용 LoRA 어댑터 착수

## 0. 한 줄

사장님 결정: **한국어·보안 특화 「GIJO 전용 두뇌」를 LoRA 어댑터로 만든다.** 밑바닥 프리트레인이 아니라 **지금 쓰는 베이스에 어댑터(수십 MB)만 얹는** 최소 경로. **작업 시작은 2026-08-20부터.** v0 훈련은 max, 데이터 채굴은 양쪽, 측정은 교차.

---

## 1. 왜 되는가 — max 정찰 실측 (2026-08-19)

- **베이스 정체 확인**: `gijo-main-orchestrator.gguf` = **Qwen2.5-7B-Instruct-1M 계열**(GGUF 메타데이터 실측: `general.base_model.0 = Qwen/Qwen2.5-7B-Instruct-1M`). **Apache 2.0 — 상용 자유**, 파인튜닝 생태계 1급.
- **우리 llama-server(b9982)가 이미 어댑터를 삼킨다**: `--lora`, `--lora-scaled`, `--lora-init-without-apply` + **실행 중 POST /lora-adapters로 켬/끔** → **같은 서버에서 어댑터 on/off A/B 측정** 가능. 배관 무변경.
- **병합·변환·양자화 도구 전부 repo 안**: `server/llama.cpp`(소스 빌드본). 어댑터가 이기면 병합→양자화→`gijo-main-orchestrator.gguf` 슬롯 교체(라이트·표준 같은 슬롯).
- max Mac(32GB, Metal)으로 **7B 4bit QLoRA(MLX)** 가능 — v0(≤2천 쌍) 몇 시간~하룻밤.
- **원칙: 지식은 RAG, 버릇은 파인튜닝.** 목표는 ①한국어 보안 말투 ②조치문·보고서 양식 ③도구 호출 안정(13/78 도구 스키마 준수). 지식 주입 아님 — 그건 지식창고가 계속 한다.

## 2. 분담 (사장님 승인)

| 누가 | 무엇 |
|---|---|
| **max** | v0 훈련 파이프라인(MLX QLoRA) · 시나리오 대장 채굴 · 라이트 게이트 측정 |
| **win** | **하던 게시 계속**(이 프로젝트로 흐름 끊지 말 것). 짬 나는 대로 두 가지만: ① **GPU VRAM 사양 회신**(훈련 이관 판단용 — 8GB면 빠듯, 16GB+면 이관 가치 있음) ② **운영 QA 로그·끊김 93건의 「고쳐진 정답」 채굴**(실데이터가 win 쪽에 있다) — 형식은 max가 내일 스키마 올리면 그걸로 |
| **교차 검증** | max 훈련본을 win이 표준 게이트로도 측정(검토 관문 그대로) |

**승격 기준**: 반복이 주 2~3회 넘고 데이터 1만 쌍+ 되면 훈련을 **win WSL+CUDA**(unsloth 등)로 이관 — NVIDIA가 2~5배 빠르다. 그전엔 max MLX로 충분.

## 3. 데이터 규칙 ⚠ (셋 다 지킬 것)

1. **정답문 출처 1순위 = 우리 실데이터** — 시나리오 대장(3d434ae)의 기대 응답, 끊김 93건(bdd6ad5)의 수정본, QA에서 다듬은 문장. 부족하면 **오픈 모델 증류**(Qwen2.5-72B 등 Apache 계열 — gb10 GPU에서).
2. **Claude 출력물은 훈련 데이터로 쓰지 않는다**(Anthropic 약관 — 출력물의 모델 학습 사용 금지). Claude의 역할은 추출 코드·스키마·형식 변환·검수 리포트까지.
3. **베이스 후보 넓힐 땐 라이선스부터** — Qwen2.5-7B는 Apache 확인됨. EXAONE류 상용 제한 모델은 거른다.

## 4. 내일(2026-08-20) max 착수 목록

1. `mlx-lm` 설치 + MLX 4bit 베이스(~4.4GB) 준비
2. 대장·끊김 → **훈련쌍 스키마** 설계 + 표본 추출 → hub에 올림(win 채굴 형식 통일용)
3. 표본으로 **파이프라인 관통 검증**: 훈련→어댑터→`llama-server --lora`→게이트 측정까지 한 바퀴
