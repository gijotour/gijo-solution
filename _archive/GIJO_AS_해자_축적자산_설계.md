# GIJO AS — 해자(후-6) 축적 자산 설계

> 2026-08-06 제정. 계획서 **후-6 「해자 강화」** 착수 문서.
> 근거: 정찰 전수 조사(코드 실태) + 외부 사례 3건. 구현 전 사용자 승인 대기.

## 0. 조사 결론 — 계획서 전제 vs 코드 실태

계획서: "인수인계·규정 대조에 쌓이는 고객별 지식 자산(이관 이력·오탐 족보·규정 매핑)은
이전 비용이 커서 대형사 진입에도 남는다."

| 계획서가 말한 자산 | 실태 (파일:줄) | 판정 |
|---|---|---|
| 오탐 족보 | `finding_approvals` — 재스캔에도 "이미 오탐"을 자동 인식·제외(approvals.ts:97, sbom.ts:148) | ✅ **유일하게 작동** (단 동일 자산+동일 해시 한정) |
| 이관 이력 | 브라우저 localStorage/메모리만. 서버엔 완료 1줄 감사기록뿐. 주석 스스로 "서버가 알지 못합니다" | ❌ **서버에 사실상 없음** |
| 규정 매핑(행동 대조) | 판정문이 세션 대화록에 원문으로만. 전용 테이블 없음, **재질문 시 이전 판정을 찾아보는 코드 0건**(actioncheck.ts:123 — 매번 새로 계산) | ❌ **쌓이지도 재사용되지도 않음** |

**부수 발견(결함성)**: 세션 전문이 100건 초과분부터 `data/session-archive/*.jsonl`로
빠져나가는데 **backup.ts가 이 폴더를 복사하지 않는다** — 재해복구 시 조용히 소실.
chat_logs 캡(10,000) 초과 정리분은 아카이브조차 없이 영구 소실.

외부 사례가 방향을 확인해 준다: SOAR/EDR의 오탐 튜닝 이력이 "조직 고유 자산 = 실질
전환비용"이라는 원칙(Securaa·isectech·CMR Berkeley — 조사 보고에 링크). 업계는 오탐
판정을 **규칙으로 승격**까지 가는데 우리는 필터에 머물러 있다 — 여지가 있다.

## 2. 슬라이스 1 상세 — 행동 대조 판정 이력

**왜 이것부터**: 규정 대조는 4대 시나리오의 ③이고 해자 자산 셋 중 유일하게
"쌓지도 않는" 상태다. 이관 이력(슬라이스 2)은 개인정보 논점이 있어 뒤로.

### 무엇을 쌓나 — `action_check_history` 테이블

```
id · askedAt · question(원문) · verdict(○/△/×) · basisRefs(인용 문서 id들)
· verdictText(판정문) · askedBy · qa(게이트/QA 오염 배제 플래그)
```

저장 지점: `actioncheck.ts` 판정 완료 직후 1곳. **qa:true 호출은 저장하되 표시·집계에서
제외**(평가 게이트 오염 방지 — eval_gate의 qa 플래그와 같은 계약).

### 되먹임 — 자동 판단 변경은 하지 않는다

확립 원칙("여기서 나온 결과를 자동으로 어디에 먹이지 않는다")을 지킨다. 세 가지만:

1. **재질문 병기** — 같은/비슷한 질문이 오면 새 판정 아래에 한 줄:
   「※ 지난 판정: 2026-07-30 △ (근거: 정보보안규정 §4) — 이번과 다르면 규정이
   바뀌었거나 상황이 다른 것입니다.」 **판정 자체는 매번 새로 한다**(규정이 바뀌면
   답도 바뀌어야 하므로 캐시 아님). 유사 판정은 결정적으로: 질문 정규화 후 완전 일치
   + 같은 basisRefs 집합만 "같은 사안"으로 본다(임베딩 유사도는 오판 위험 — 1차 제외).
2. **대화창 조회 도구(읽기)** — "규정 대조 이력 보여줘": 최근 판정 목록·×가 나온 사안.
   강제 라우팅으로 결정화(서랍 원칙).
3. **판정 뒤집힘 감지(표시만)** — 같은 사안의 판정이 ○→×로 바뀌면 이력 줄에 ⚠ 표시.
   규정 개정을 담당자가 알아차리는 신호이지, 제품이 판단하지 않는다.

### 하지 않는 것 (정직 경계)

- 판정 캐싱·자동 재사용 ✗ (낡은 규정으로 답하게 됨)
- 임베딩 유사 매칭 ✗ (1차 — "비슷해 보이는 다른 사안"을 같다고 하면 법무 리스크)
- 화면 신설 ✗ — 조회는 대화창, 원칙대로

### 검증 계획

- 단위: 저장·재질문 병기·qa 배제·뒤집힘 표시 각각 시험
- e2e: 같은 질문 2회 → 두 번째 답에 「지난 판정」 줄 실측 · 게이트 routing 축(새 강제 규칙 겹침 0)
- 백업: 슬라이스 0과 함께 복원 점검에 이력 건수 포함

## 3. 크기·순서 근거

슬라이스 0은 결함이라 즉시. 1은 테이블 1개 + 저장 1곳 + 병기 1곳 + 도구 1개 —
반나절. 2는 개인정보 설계가 먼저라 별도 승인. 3은 오탐을 잘못 일반화하면 **진짜
취약점을 숨기는** 최악의 실패라 "표시만"부터 천천히.
