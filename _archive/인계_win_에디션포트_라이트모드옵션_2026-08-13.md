## 2. ⚠ 프로 7447의 걸림돌 — 스탠다드와 같은 프로세스다

**프로는 별도 빌드가 아니다.** 에디션은 `lite`(dist/lite/index.js)와 스탠다드(dist/index.js)
둘뿐이고, **프로는 스탠다드의 런타임 티어**(app_state `gijoTier`)다. 같은 프로세스라 스탠다드와
**다른 포트를 동시에 못 연다.** 게다가 포트는 **부팅 때** 정해지는데 티어는 **부팅 후 DB에서** 읽는다.

▶ 그래서 「프로 7447」이 성립하려면 **런처가 부팅 전에 의도된 티어를 알아** 포트를 정해야 한다:
- 방법 A: 티어 설정을 userData의 파일에 두고(부팅 전 읽기 가능), 스탠다드 진입점이 그 값으로
  `GIJO_SERVER_PORT`를 7446/7447로 고른다.
- 방법 B(더 단순): **스탠다드=7446 하나로 두고 프로는 같은 포트**를 쓴다. 프로는 「기능 등급」이지
  「다른 서버」가 아니므로, 포트를 굳이 가를 실익이 적다(같은 프로세스라 헷갈릴 일도 없다).
  ▷ max 의견: **B를 권함.** 사장님께 「프로는 스탠다드와 같은 서버라 7446을 공유한다」로
    확인받는 게 깔끔하다. 정 나눠야 하면 A.

## 3. 권하는 구현 — 단일 출처로 네 곳을 한 번에

포트를 **클라(main.ts)가 에디션·티어로 정해** 서버에 넘기고, 렌더러 기본값까지 그 값으로 맞춘다:

```ts
// main.ts — 에디션→포트 한 곳
function 서버포트(): number {
  if (에디션() === "lite") return 7445;
  // 스탠다드: 방법 A면 저장된 티어로 7446/7447, 방법 B면 7446 고정
  return 7446;
}
```

- **① 서버 listen**: 라이트는 이미 `lite/env.ts`가 `GIJO_SERVER_PORT`를 세팅할 수 있다(max가
  한 줄 준비만 하고 안 켰다 — §5). 스탠다드는 main.ts가 spawn env에 `GIJO_SERVER_PORT=서버포트()`를
  넣으면 index.ts:42가 그 값을 쓴다. **index.ts의 기본값 4000은 안 바꿔도 된다**(env가 이기므로).
- **② 헬스 폴링**: `http://127.0.0.1:${서버포트()}/api/health`.
- **③ 렌더러 기본 주소**: core.ts는 렌더러라 에디션을 모른다. **main.ts가 `auth:getState`로
  넘기는 `authState.serverUrl`을 첫 실행에 `http://localhost:${서버포트()}`로 seed**하면
  core.ts:24(`persisted.serverUrl ?? DEFAULT`)가 그걸 집는다 — DEFAULT_SERVER_URL은 손 안 대도 됨.
  (core.ts:22가 `ipcRenderer.sendSync("auth:getState")`로 main에서 읽어 온다 — 이미 통로가 있다.)
- **④ login 안내문**: 표시용이라 마지막. 에디션 문구로 바꾸거나 그냥 둬도 접속엔 무해.

이러면 literal 4000이 **전부 사라지고** 에디션 한 곳에서 흐른다.

## 4. 기존 클라에 라이트 모드를 「선택 사항」으로

지금 `에디션()`은 **package.json의 `gijoEdition`을 빌드 때 박아** 읽는다(main.ts:383-389).
그래서 라이트는 **전용 dmg**로만 존재한다. 사장님이 원하는 건 **스탠다드 클라에서 라이트 모드를
고를 수 있게**다.

▶ 권하는 방법 — `에디션()`을 **런타임 설정 우선**으로:
```
에디션() = userData의 저장된 값(있으면)  ?? package.json.gijoEdition(빌드 고정)  ?? ""
```
- 전용 라이트 dmg: package.json이 `lite`라 **항상 라이트로 잠김**(고객이 못 바꾼다 — 유지).
- 스탠다드 dmg: 저장된 값이 없으면 스탠다드. **설정(또는 첫 실행 선택 화면)에서 「라이트 모드」를
  고르면** userData에 `lite`를 써서 다음 실행부터 라이트로.
- 라이트로 바뀌면 main.ts가 이미 하는 대로 `dist/lite/index.js` 진입점 + `lite-app.html` 셸 +
  7445. 즉 **§3의 서버포트()·서버몸통() 선택이 그대로 재사용된다.**

⚠ **주의 — 한 userData를 두 에디션이 공유하면 안 된다.** 스탠다드로 쌓은 회사 데이터(자산·결재)가
라이트 화면엔 안 보이고, 라이트로 만든 것이 스탠다드에 섞이면 혼란이다. 모드를 바꾸면 **다른
데이터 폴더**를 쓰거나(예: userData/lite/), 최소한 「모드를 바꾸면 보이는 화면이 달라진다」를
경고해야 한다. 서버 도구 13 vs 78도 **부팅 때** 갈리므로 **모드 변경은 재시작을 요구**한다
(max가 이미 모델 교체용으로 만든 「재시작하세요」 안내와 같은 계열).

max가 만든 것 중 재사용 가능한 것: `lite-app.html`·`lite-*.html` 9장·`lite-tools.json`·
`lite/env.ts`·`lite/index.js`·`에디션()` seam. **옵션 스위치만 얹으면 된다.**

## 5. max가 준비만 하고 **안 켠** 한 줄 (win이 §3과 함께 켜라)

`server/src/lite/env.ts`에 이걸 넣으면 라이트 서버가 7445로 뜬다 — 지금은 **안 넣었다**
(클라 ②③이 아직 4000이라 넣으면 현재 dmg가 깨지므로):
```ts
if (!process.env.GIJO_SERVER_PORT) process.env.GIJO_SERVER_PORT = "7445";
```
§3의 클라 변경과 **같은 커밋**에 넣어야 상태가 안 깨진다.
