# GIJO AS — 정보구조(IA) 통합 설계

> 목적: 20개로 늘어난 메뉴를 **1인 보안담당자가 쉽게 쓰는** 구조로 통합한다.
> 기능은 **삭제하지 않고 탭·고급접기로 보존**한다. 구현 전 이 문서로 구조를 확정한다.
> 기준 문서: `GIJO_AS_다음단계_가이드.md` §0 — "이 제품은 간단한 툴이다. 엔터프라이즈 스위트가 아니다."
> 작성: 2026-07-17.

---

## 1. 문제 진단 (현행 20개 메뉴)

각 페이지의 실제 설명(page-sub)에서 확인한 3가지 구조적 문제:

**P1. "AI 팀·학습" 6개 메뉴 과부하** — 매일 쓰는 건 `에이전트 AI` 하나. 나머지 5개(`기억·학습`,
`온톨로지`, `학습루프`, `LLM 합성`, `LLM 가이드`)는 "AI에게 지식·모델을 세팅"하는 저빈도·고급 작업.
`기억·학습` 페이지 스스로 *"AI에게 지식을 주는 3가지 방법"*이라 설명하는데, `온톨로지`(4번째 방법)와
`학습루프`(자동 학습)가 개념상 같은 묶음인데 메뉴만 쪼개져 있다.

**P2. 한 워크플로우가 두 메뉴로 분리** —
- `취약 자산관리`(발견) → `승인 워크플로우`(조치): 취약점 지침 생애주기(발견→우선순위→**조치**→측정)의 한 흐름
- `AI 자산`(목록) ↔ `AI-BOM`(구성 상세): 같은 자산의 두 뷰
- `대시보드` ↔ `보안 KPI`: 둘 다 요약/지표

**P3. 저빈도 관리 메뉴가 상위 노출** — `사용량·요금`, `로그`는 1인 담당자에겐 가끔 보는 화면.

---

## 2. 설계 원칙

1. **사용 빈도로 계층화**: 매일(daily) → 주기적(periodic) → 세팅 1회(setup) → 고급(advanced).
   고급·세팅은 상위 메뉴에서 내리고 탭·"고급 펼치기" 뒤로 보낸다.
2. **워크플로우 단위로 묶기**: "발견→조치"처럼 이어지는 일은 한 페이지 탭으로.
3. **삭제가 아니라 이동**: 모든 기존 기능·라우트는 유지. 진입 경로만 통합.
4. **점진 적용**: 사이드바가 페이지마다 복제돼 있으므로(현행), 통합과 함께 **네비를 단일 소스로** 뺀다.

## 3. 통합 후 구조 (20 → 9)

### 네비게이션 트리

```
보안 업무
  ├─ 대시보드            (홈: 오늘 할 일 + KPI 요약)
  ├─ AI 자산             [탭: 자산 목록 · AI-BOM 구성]
  ├─ 취약점 관리          [탭: 취약점(발견·우선순위) · 조치/승인]
  ├─ 위협 인텔리전스
  ├─ 보안 운영            [탭: 보안제품 등록부 · 유지보수 점검]
  └─ 리포트·컴플라이언스   [탭: 내부 리포트 · 컴플라이언스(KISA)]
AI
  ├─ AI 어시스턴트        (매일 쓰는 에이전트 채팅·팀)
  └─ AI 지식·모델         [탭: 지식(문서RAG+온톨로지) · 학습(데이터셋+파인튜닝+루프) · 모델(가이드+합성+엔진)]
시스템
  └─ 설정                [탭: 연결·계정·엔진 · 사용량·요금 · 로그]
```

## 4. "AI 지식·모델" 상세 (통합 핵심)

6개 → 2개의 절반. 이 페이지 하나가 "AI 두뇌를 세팅하는 모든 것"을 담는다. 3개 탭:

**탭 A — 지식** (AI에게 회사 지식 주기)
- 문서(RAG / 장기 기억): `memory.html`의 문서 올리기 → LanceDB 벡터 검색
- 규칙(온톨로지 / 지식 그래프): `ontology.html`의 트리플·그래프·규칙 주입 미리보기
- (설명 카드로 "문서=비슷한 내용 검색 / 규칙=명시적 관계·근거" 차이 안내)

**탭 B — 학습** (AI에 각인)  *기본 접힘 — 고급*
- 데이터셋 만들기 + 파인튜닝: `memory.html`의 학습 파트
- 헤르메스 학습 루프(자동 수집→학습→배포): `learnloop.html`

**탭 C — 모델** (AI 두뇌 준비)  *기본 접힘 — 고급*
- 추천 LLM 가이드(용도별 다운로드): `llmguide.html`
- 보안 LLM 합성(SLERP 병합): `merge.html`
- 로컬 엔진 시작/스왑 상태(현재 `settings`에 있는 엔진 관리와 연계)

기본값: **지식 탭만 펼침**, 학습·모델 탭은 "고급" 배지. 담당자는 평소 문서·규칙만 만지고,
학습·합성은 필요할 때만 연다.

## 6. 리스크 / 지키기

- **기능 손실 0**: 어떤 페이지도 삭제하지 않는다. URL 진입(navigateTo)도 당분간 유지(북마크·딥링크 보호).
- **점진 검증**: 단계마다 각 페이지가 여전히 열리고 동작하는지 스모크. (온톨로지처럼 실기 확인 가능.)
- **되돌리기**: 네비 단일화·탭은 프론트만 바꾸므로 커밋 되돌리면 원복.
- **모바일 지시 상황**: GUI 육안 확인이 어려우니, 각 단계에서 페이지 로드·주요 버튼 동작을 스크립트/스모크로 대체 검증.

## 7. 확정 필요 사항 (구현 착수 전 결정)

1. **9개 최상위가 맞나?** 더 줄일 여지: `위협 인텔리전스`를 `취약점 관리`나 대시보드로 흡수할지.
2. **AI 지식·모델의 "학습/모델" 탭을 고급으로 접는 기본값** 동의 여부.
3. **`사용량·요금` 유지 여부** — 1인 온프레미스 툴에 요금 화면이 필요한지(다음단계 가이드 4단계 "만들지 않기" 후보와 연결).
4. **네비 단일화 방식** — 공용 JS 주입 vs 빌드 시 include. (현 스택은 정적 HTML이라 JS 주입이 간단.)
5. **롤아웃 순서** — §5 순서대로 vs "AI 지식·모델 허브"(3단계)부터 먼저.

> 위 5개에 답이 정해지면 1단계(네비 단일화)부터 구현 착수.
