# GIJO AS — AI 에이전트 지휘 대시보드 계획서

> 목표: 대시보드를 **"보는 화면"에서 "AI 보안팀을 지휘하는 화면"으로**. 보안담당자가 **팀장처럼**
> 활성 에이전트를 한눈에 보고, 각자에게 직접 지시·대화하며 결과를 취합한다. 작성 2026-07-17.

---

## 1. 지금 상태 (현행)

- **에이전트 5명** (`agents.ts`): 오케스트레이터·스캔·분석·리포트·GIJO Security(id=normaltic). 각자 역할·상태·전용 LLM 보유.
- **상태 모델**: `idle`(대기) / `working`(작업 중) / `watching`(감시 중) — 라이브 신호(휘발성), `setAgentStatus`로 실시간 갱신, 서버 재시작 시 기본값 복귀.
- **2모델 구성**: 오케스트레이터·리포트·GIJO Security → gijo / 스캔·분석 → 보안 LLM. `assignedModelId`로 노출.
- **대화 API**: `POST /api/llm/chat {agentId, message}` — **이미 에이전트별 개별 대화 가능**. 그러나 대시보드는 **오케스트레이터에게만** 말함(중앙 입력창 1개).
- **실시간**: `asset:updated`·`collaboration:event`·`llm:event` WebSocket. 협업 피드에 에이전트 간 위임/완료가 흐름.
- **현재 UI**: 중앙 SVG 허브-스포크 말풍선(장식성 다이어그램) + 오케스트레이터 지시창 + 협업 피드 + 오늘의 조치.

## 2. 무엇을 바꾸나 (핵심 아이디어)

> **"팀장(나) + 팀원(5 AI 에이전트)"** 은유. 활성 상태를 시각적으로 살리고, 팀원 각자와 직접 대화한다.

1. **팀 로스터 상시 표시**: 5명을 카드/아바타로. 상태(대기·작업·감시)와 담당 LLM·역할을 배지로.
2. **활성 하이라이트**: `working`인 에이전트는 발광·펄스·타이핑 인디케이터로 "지금 일하는 중"을 강조. `watching`은 은은한 표시.
3. **에이전트별 직접 대화**: 팀원 클릭 → 그 에이전트와 1:1 대화 패널(`/api/llm/chat`의 agentId만 바꾸면 됨 — 백엔드 무변경).
4. **팀장식 지휘**: 오케스트레이터에게 "전체에게 시켜" (dispatch)도 유지. 개별 지시 ↔ 전체 위임 둘 다.
5. **실시간 협업 가시화**: 오케스트레이터가 스캔→분석→리포트로 위임하는 흐름을 팀원 간 연결선/말풍선으로 라이브 표시(협업 피드 이벤트 활용).

## 3. 데이터·API 매핑 (구현 난이도 낮음 — 대부분 프론트)

| 필요 | 이미 있는 것 |
|---|---|
| 팀원 목록·역할·상태·LLM | `GET /api/agents` (id·name·role·status·assignedModelId) |
| 상태 라이브 갱신 | `setAgentStatus` + `llm:event`/`collaboration:event` WebSocket |
| 에이전트별 대화 | `POST /api/llm/chat {agentId, message}` (그대로) |
| 전체 지휘(위임) | `/api/dispatch` (orchestrator → scan/analysis/report) |
| 협업 흐름 | `collaboration:event` (from·to·message) |

→ **백엔드 신규 개발 거의 없음.** `chat` 중 에이전트가 `working`으로 표시되게 상태 emit만 보강하면 이상적(작은 서버 변경).

## 4. 3가지 디자인 방향 (아래 목업 HTML 참조)

| # | 이름 | 컨셉 | 팀장 느낌 |
|---|---|---|---|
| **A** | **팀 로스터 + 대화 패널** | 좌측 팀원 카드 목록(상태 배지·활성 발광) → 클릭 시 우측 대화 패널. 익숙한 좌/우 구조. | 팀원 명단을 보고 콕 집어 지시 |
| **B** | **지휘본부(상황실)** | 중앙에 나(팀장), 주위에 팀원들이 궤도로 배치. 활성 팀원은 펄스+연결선, 클릭 시 말풍선 대화. 몰입형. | 상황실에서 팀 전체를 내려다보며 지휘 |
| **C** | **메신저 워크스페이스** | Slack/메신저형: 좌측 팀원 채널 목록(활성·안읽음 배지), 우측 대화 스레드 + 협업 로그 탭. 실무형. | 팀 메신저로 각 팀원과 대화·전체 공지 |

- 공통: GIJO 다크 테마, 상태 3색(작업=파랑 발광 / 감시=초록 / 대기=회색), 담당 LLM 배지(gijo·보안LLM), "전체에게 지시(오케스트레이터)" 상단 고정.

## 5. 단계별 구현 (선택 확정 후)

1. **정적 목업 확정** (지금) — 3종 중 택1 또는 혼합.
2. **팀 로스터 컴포넌트** — `GET /api/agents`로 카드 렌더 + 상태 배지. 대시보드 중앙 영역 교체.
3. **활성 라이브** — `llm:event`(추론 시작/종료)·`collaboration:event` 구독 → 해당 에이전트 카드 `working` 발광/타이핑.
4. **에이전트별 대화 패널** — 선택 에이전트로 `chat` 호출, 스레드 유지(에이전트별 이력).
5. **협업 흐름 시각화**(선택 B) — dispatch 이벤트를 연결선/말풍선으로.
6. **서버 소폭 보강**(선택) — `chat()` 진입/종료 시 `setAgentStatus(working/idle)` + emit해 카드가 실제로 반응하게.

## 6. 스코프·원칙

- **온프레미스·기존 API 재사용** — 백엔드 신규 최소화(프론트 중심).
- **"간단한 툴" 유지** — 화려한 애니메이션보다 "누가 지금 뭘 하는지 + 콕 집어 지시"가 핵심.
- 기존 대시보드 요소(오늘의 조치·자산 탐색기·협업 피드)와 **공존**하도록 중앙 영역만 교체.

## 7. 확정 필요

- 디자인 3종(A/B/C) 중 채택안(또는 혼합).
- 개별 대화 시 이력 유지 범위(에이전트당 최근 N턴 — 현재 llm.ts가 에이전트당 이력 보유).
- 활성 표시를 위해 서버 `chat` 상태 emit 보강할지(권장).
