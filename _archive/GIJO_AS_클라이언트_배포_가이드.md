# GIJO AS 클라이언트(데스크톱) 배포 가이드 — v2.5.0

> **대상:** 담당자 PC에 GIJO AS 데스크톱 앱을 나눠주고 설치·연결하는 사람(헬프데스크·IT 담당·보안담당자 본인).
> **범위:** 데스크톱 앱 설치·서버 연결·업그레이드·문제 해결. **서버(GPU 머신) 구축은** 별도 문서 `GIJO_AS_배포_가이드.md`를 참고하세요.
> **원칙(온프레미스):** 데이터·AI는 조직 경계 밖으로 나가지 않습니다. 데스크톱 앱은 사내 서버(:4000)에 붙거나, 자체 번들 서버로 단독 동작합니다.

---

## 1. 배포 방식 두 가지 (먼저 선택)

| 방식 | 설명 | 준비물 |
|---|---|---|
| **분산 모드 (권장·표준)** | 사내 GPU 서버 1대에 여러 담당자 PC가 접속 | 서버 주소 `http://<서버IP>:4000`, 발급 계정 |
| **단독 모드 (standalone)** | PC 1대에 서버까지 번들(설치본에 포함) | (분산 서버 불필요) 별도 모델 배치 필요 |

> **쉽게:** 회사에 GPU 서버가 있으면 **분산 모드**(각 PC는 그 서버에 접속만). 서버 없이 데모·소규모로 쓰면 **단독 모드**.

---

## 2. 준비물 (설치 전 체크)

- [ ] **설치본 파일**: `GIJO AS Setup 2.5.0.exe` (약 160MB) — 관리자에게 전달받기
- [ ] (분산 모드) **서버 주소**: `http://<사내 서버 IP>:4000`
- [ ] (분산 모드) **로그인 계정**: 관리자에게 발급받은 **아이디 / 초기 비밀번호**
- [ ] 대상 PC가 **시스템 요구사항**(아래 §3)을 만족하는지

> 설치본은 사내 파일서버·USB 등 **폐쇄망 안**에서 전달하세요(외부 다운로드 불필요).

## 3. 시스템 요구사항

| 항목 | 최소 | 권장 |
|---|---|---|
| OS | Windows 10 (64bit) | Windows 11 (64bit) |
| CPU / RAM | 2코어 / 8GB | 4코어+ / 16GB |
| 디스크 | 1GB 여유 | 2GB+ 여유 |
| 네트워크(분산 모드) | 사내 서버 `:4000` 도달 가능 | — |
| 권한 | **관리자 권한 불필요** (사용자 단위 설치) | — |

> 단독 모드로 AI 추론까지 하려면 GPU/모델이 필요합니다(데모·경량 용도가 아니면 분산 모드 권장).

---

## 4. 설치 (단계별)

1. `GIJO AS Setup 2.5.0.exe`를 **더블클릭**해 실행합니다.
2. 설치가 진행됩니다(사용자 단위 설치라 **관리자 권한/UAC 없이** 진행). 완료되면 바탕화면·시작 메뉴에 **GIJO AS** 아이콘이 생깁니다.
3. **GIJO AS**를 실행합니다.

> 설치 위치·설정은 사용자 프로필(`%LOCALAPPDATA%` / `%APPDATA%\GIJO AS`)에 저장됩니다.

---

## 5. 최초 실행 · 로그인

### 5.1 분산 모드 (사내 서버에 접속)
1. 첫 화면(로그인)의 **서버 주소** 칸에 `http://<서버IP>:4000` 입력.
2. 관리자에게 받은 **아이디 / 비밀번호**로 로그인.
3. 우상단 **`● 운영중 LIVE`**(초록)면 서버 연결 정상입니다(빨간 점이면 연결 실패 — §7 참고).

> **한 계정은 한 곳에서만** 로그인됩니다. 다른 PC에서 같은 계정으로 로그인하면 확인 후 기존 세션이 종료됩니다(중복 로그인 방지).

**환경변수로 서버 고정(선택):** 배포를 자동화하려면 실행 환경변수 `GIJO_SERVER_URL=http://<서버IP>:4000` 를 지정하면 매번 주소를 입력하지 않고 그 서버에 붙습니다.

### 5.2 단독 모드 (번들 서버)
- `GIJO_SERVER_URL`을 지정하지 않고 실행하면, 설치본에 포함된 **번들 서버가 자동 기동**되어 `http://localhost:4000`에 붙습니다.
- AI 추론(채팅·분석)까지 쓰려면 **모델 파일을 별도 배치**해야 합니다(관리자 문의).

## 6. 업그레이드 · 재설치

1. 새 버전 설치본(`GIJO AS Setup x.y.z.exe`)을 실행하면 **덮어쓰기 설치**됩니다.
2. **로그인 서버 주소·탐색기 폴더 등 로컬 설정은 유지**됩니다(`%APPDATA%\GIJO AS`).
3. 서버(분산 모드)는 관리자가 별도로 업그레이드합니다 — 클라이언트만 새로 깔면 됩니다.

### 6.1 설치 전에 앱을 닫아야 하나요? — **아니요(닫아두면 더 매끄럽습니다)**

앱이 켜져 있어도 설치할 수 있습니다. 설치 프로그램이 실행 중인 앱을 스스로 감지합니다.

| 상황 | 설치 프로그램 동작 |
|---|---|
| 앱이 **꺼져 있음** | 곧바로 설치 진행(팝업 없음) |
| 앱이 **켜져 있음** | **"GIJO AS이(가) 실행 중입니다. OK을 클릭하면 종료됩니다."** 팝업 → **확인** 누르면 자동 종료 후 설치 |
| 위 팝업에서 **취소** | 설치가 **중단**됩니다(아무것도 바뀌지 않음) |
| 자동 종료가 안 될 때 | `수동으로 닫고 재시도` 안내가 반복 표시 — 앱을 직접 닫고 재시도 |

- 종료 대상은 **본인 계정이 띄운 GIJO AS만**입니다(사용자 단위 설치라 다른 사용자 세션은 건드리지 않음).
- **작업 중 데이터**: 서버에 저장되므로 강제 종료로 유실되지 않습니다. 다만 **입력 중이던 채팅·미저장 입력은 사라지므로**, 담당자에게 미리 닫아달라고 안내하는 편이 좋습니다.
- **무인(사일런트) 설치** `GIJO AS Setup x.y.z.exe /S` 로 실행하면 위 팝업이 자동으로 확인 처리되어 앱을 종료하고 설치합니다 — 원격 일괄 배포용.

### 6.2 인앱 자동 업데이트 (v2.5.0부터 — 신규)

새 버전이 이 방식으로 배포되면, 설치본을 따로 받지 않아도 앱 안에서 바로 업데이트할 수 있습니다(클로드 데스크톱과 같은 방식). **배포처는 외부 서비스가 아니라 이미 접속돼 있는 GIJO AS 서버 자신**입니다.

1. 사이드바 **⚙ 설정 → 업데이트** 메뉴로 들어갑니다. 새 버전이 있으면 이 메뉴와 ⚙ 아이콘에 빨간 배지가 자동으로 뜹니다(앱 시작 시 자동 확인).
2. **버전·릴리스 노트**를 확인하고 **"지금 업데이트"**를 누릅니다.
3. 다운로드 진행률이 표시되고, 완료되면 **자동으로 설치가 진행되며 앱이 재기동**됩니다 — 클릭 한 번으로 끝입니다.

> 관리자가 새 버전을 게시하지 않았다면 이 메뉴엔 "최신 버전입니다"만 표시됩니다. (관리자용 게시 절차는 `GIJO_AS_배포_가이드.md` 참고.)

### 6.3 PowerShell로 수동 업데이트 (관리자·IT 담당용, v2.5.0부터)

여러 대를 원격으로 일괄 업데이트하거나, GUI 없이 스크립트로 확인·설치하려면 클라이언트 소스에 포함된 `client/scripts/manual-update.ps1`을 씁니다(로그인 → 최신 버전 확인 → 다운로드 → **sha256 무결성 검증** → 설치 실행까지 한 번에).

```powershell
cd <client 소스 경로>
.\scripts\manual-update.ps1 -User <아이디> -Password <비밀번호> -ServerUrl http://<서버IP>:4000
```

| 옵션 | 설명 |
|---|---|
| `-CheckOnly` | 최신 버전만 확인하고 다운로드·설치는 하지 않음 |
| `-ForceLogin` | 그 계정이 이미 앱 등 다른 곳에 로그인돼 있어 409(중복 로그인)가 날 때 강제 전환(그 세션은 끊김) |

> 다운로드한 설치파일은 서버가 게시 시 계산해 둔 sha256과 대조해 무결성을 확인한 뒤에만 실행합니다 — 값이 다르면 스크립트가 실행하지 않고 중단합니다.

### 6.4 설치 위치 (참고)

| 항목 | 경로 |
|---|---|
| 프로그램 | `%LOCALAPPDATA%\Programs\gijo-as-client` |
| 설정·로컬 데이터 | `%APPDATA%\GIJO AS` |

> 설정을 완전히 초기화하려면 앱 종료 후 `%APPDATA%\GIJO AS` 폴더를 삭제하고 다시 실행하세요.

## 7. 문제 해결

| 증상 | 확인·조치 |
|---|---|
| **서버에 못 붙음**(빨간 점) | 서버 주소·포트(`:4000`) 오타 확인 → 사내망에서 서버 IP `ping`/접속 확인 → 서버 상주 여부(관리자) → 방화벽 `4000/tcp` |
| **로그인 실패** | 아이디/비밀번호 확인(초기 비번은 관리자 발급) → "이미 로그인 중" 뜨면 **강제 로그인**으로 기존 세션 종료 |
| **첫 AI 응답이 느림** | 모델 첫 로딩(콜드스타트)입니다 — 잠시 기다리면 이후는 빨라집니다(고장 아님) |
| **화면은 뜨는데 데이터가 비어 있음** | 분산 모드인데 서버에 데이터가 없거나, 단독 모드에서 모델·데이터 미배치 — 관리자 문의 |
| **설치가 막힘/차단됨** | 백신·EDR이 미서명 실행을 막을 수 있음 — 보안팀에 예외 등록 요청 |

## 9. v2.5.0 주요 화면 (담당자 첫 안내용)

- **대시보드**: 왼쪽 **📁 내 PC 파일 탐색기**(문서 클릭 → 장기기억에 올리기), 가운데 **내 업무 바로가기 + 🤖 AI 팀**, 오른쪽 **🗂 작업 화면**(작업 세션·지휘 콘솔 — 헤더의 "진행중 N" 배지로 진행 상황을 바로 확인). 오른쪽 위 **`☰ 전체메뉴`** → 보안 KPI(전체 메뉴 화면).
- **어디서든 지시**: 다른 화면에선 오른쪽 가장자리 **`◧ 작업 화면`** 탭으로 지휘 콘솔을 열어 AI에게 자연어 지시(현재 화면 맥락 자동 전달).
- **⚙ 설정 → 업데이트**(신규): 인앱 자동 업데이트 — 새 버전이 있으면 배지로 알려주고 클릭 한 번으로 다운로드·설치·재시작(§6.2).
- **📅 리포트 → 예약 설정**(신규): 주간/분기 리포트 자동 생성 스케줄 등록 — 챗봇에게 물어도 같은 데이터로 답한다.
- **🔌 MCP 연동**(관제·모니터링): AI를 외부 도구·데이터에 연결(원격은 egress 승인·감사).
- **보안 KPI**: 섹션 제목 클릭으로 접이식(기본 접힘, 추세 번다운만 펼침).
