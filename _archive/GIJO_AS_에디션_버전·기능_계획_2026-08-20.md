# 에디션 버전·기능 업데이트 계획 (2026-08-20)

> 사장님 지시: 「라이트 및 표준 모델 버전관리 잘하고, 배경뿐만 아니라 기능 업데이트 할 만한 것까지 해서 계획 잡아줘」.
> 이 문서가 그 계획이다 — **실행은 사장님 확인 후**(순서·범위 바꾸실 수 있게 계획만 먼저).

## 1. 버전관리 — 현행 확인 + 보강 2가지 (보강은 반영 완료)

| 에디션 | 번호 체계 | 현재 |
|---|---|---|
| 표준·프로 | `client/package.json` X.Y.Z (같은 바이너리 — 로그인에서 셸 선택) | **5.46.0** (2026-08-20) |
| 라이트 | `electron-builder.lite.json` 독자 semver (2026-08-14 결정) | **Lite 1.1.11** (연초록 이전) |
| 서버 | 번호 없음 — 커밋+마이그레이션으로 추적 | 29d8c212 배포됨 |

- ✅ **보강 ①** 에디션 게시 대장 신설 — `GIJO_AS_버전관리_기준.md`에 표 추가(게시마다 갱신).
- ✅ **보강 ②** 라이트 게시 규칙 추가 — 게시 시 「반영 기준 hub 커밋」을 대장에 기록(결함 회신이 오면 어느 코드 기준인지 즉시 판별).
- 원칙 유지: 표준·프로 번호를 나누지 않는다(같은 바이너리 — 나누면 번호에서 「같은 것 여러 곳」 재발).

## 2. 당장의 게시 일감 — Lite 1.2.0

- **내용**: 연초록 배색(에디션 이름표) + 마라톤 공용 개선 중 라이트에 닿는 것(dialog·selectnotify 등 공용 부품·Smart MD 유지).
- **조건**: max 실기 검증(mac dmg — 인계 발행됨) 통과. win exe(dist:lite)는 win에서 병행 빌드.
- **규모**: 검증 회신 후 반나절(빌드·Drive 교체·대장 갱신·안내서 파일명).

## 3. 기능 업데이트 후보 — 우선순위 제안

### 라이트 (무료판 — 「빼기」 원칙 유지, 셋 다 서버 기능 재사용이라 화면만 얹는 작은 일)
| # | 후보 | 왜 | 규모 |
|---|---|---|---|
| L1 | **위험수용 판정** 라이트 노출 — lite-scan 판정에 「위험수용(기한·사유)」 추가 | 서버는 5.43.0에 이미 있음. 1인 담당자야말로 「일단 수용하고 분기 재검토」가 일상 | 화면만, 반나절 |
| L2 | **내 문서 미니** — lite-memory(나만의 기억)와 개인 문서(personal_docs) 통로 정리 | 라이트는 1인용이라 격리 개념이 단순 — 지금은 두 저장소가 헷갈릴 여지 | 조사 반나절 후 판단 |
| L3 | 대시보드에 **AI 팀 미니 카드**(오늘 호출·오류 한 줄) | 5.43.0 감독 집계 재사용 — 무료판에서도 「AI가 일하고 있다」 체감 | 화면만, 2~3시간 |

### 표준·프로 (마라톤 신기능은 이미 공용으로 반영됨 — 위험수용·감독·내 문서 전부 표준에서도 동작)
| # | 후보 | 왜 | 규모 |
|---|---|---|---|
| S1 | ★**신고 시한 시나리오** — 침해 확인 시 KISA 24시간·개인정보 유출 72시간 카운트다운 + 신고서 초안 + 이력 | 사장님 예약 백로그(「우리의 장점일 듯」). 한국형 차별점 — 법령 조회와 결합. 계획서 관계: 전-7(보여 주기) 연장 + 외부검증 4순위 | 시안→구현 2~3일 |
| S2 | **감독 7일/30일 실증** — 집계가 1주 쌓인 뒤(8/27~) 추이 화면 실측·보정 | 도입일부터 쌓이는 지표의 첫 실데이터 검증 | 반나절 |
| S3 | **회귀 표본 QA 자산** — 휴면 처리된 웹리포트 케이스를 QA 전용 표본으로 부활 | 파서 회귀 감시 복원(운영 데이터 오염 없이 — qa 태그 자산) | 반나절 |
| S4 | **프로 흰 바탕 피드백 라운드** — 사장님 실사용 후 걸리는 색·대비 일괄 수리 | 배색은 실사용 눈이 최종 관문 | 피드백 후 반나절 |
| S5 | 에이전트 감독 → **주간 감독 리포트**(리포트 스케줄에 편입) | 감독 데이터의 보고서화 — 기존 리포트 엔진 재사용 | 1일 |

### 하지 않기로 제안(사유)
- 대화 검색 개인/회사 토글 UI — 격리는 구조가 이미 보장, 수요 확인 전 새 조작 개념 금지.
- 라이트에 프로 카드 계약 이식 — 라이트는 화면 한 자리 셸이라 계약이 성립 안 함(빼기 원칙).

## 4. 제안 순서 (승인 시)

1. **이번 주**: max 검증 회신 → **Lite 1.2.0 게시**(대장 갱신) → S3(회귀 표본).
2. **다음**: **S1 신고 시한 시나리오**(시안 먼저 — 이게 이 계획의 주력 신기능).
3. **그다음**: L1·L3(라이트 소품 두 건 묶음 → Lite 1.3.0) → S2(감독 실증, 8/27 이후) → S5.
4. 상시: S4(흰 바탕 피드백)는 들어오는 대로 끼워 수리.
