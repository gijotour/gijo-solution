# win 인계 — 법령 조문 **본문이 77% 빠진다** (max, 2026-08-13)

> 한 줄: **법제처 조문 파서가 「항」을 안 읽는다.** 그래서 개인정보 보호법 조문 126건 중
> **97건이 제목만 남고 본문 0자**로 들어온다. 그 빠진 자리에 「유출 신고 **72시간**」이 있어서,
> 제품이 **「법령에 명시되어 있지 않다」고 단정**했다. 과태료가 걸린 법정 기한이다.

## 1. 무엇을 봤나

라이트 게이트 씨앗 문항(`lt-seed-law`)이 「72시간」을 못 찾아 실패했다. 답을 읽어 보니 실패가
아니라 **틀린 답**이었다.

```
질문: 개인정보 유출되면 며칠 안에 신고해야 돼?
도구: law_lookup, 사내지식
답 : "개인정보 유출 시 신고 기한은 법령에 명시되어 있지 않다. 다만, … 접속기록은
      최소 1년 이상 보관해야 하며 … 유출 시 신고는 반드시 지체 없이 해야 하며,
      이는 법령상 명시된 기한이 아닌 실무적 원칙이다."
```

두 군데가 잘못됐다.

1. **「법령에 명시되어 있지 않다」 — 틀렸다.** 개인정보 보호법 시행령 제40조 ①이
   「**72시간 이내에** … 신고해야 한다」고 못 박고 있다.
2. **없는 걸 「없다」고 단정했다.** 「제가 확인 못 했습니다」와 「법에 없습니다」는 다르다.
   담당자가 이 답을 믿으면 신고 기한을 놓친다.

꼬리표(`⚠ 사내 자료를 근거로 답했습니다 — 법제처에서 원문은 확인하지 못했습니다`)는
정상으로 붙었다. **꼬리표는 정직했는데 본문이 단정했다.**

## 2. 뿌리 — 파서가 「항」을 안 읽는다

법령 조회는 **켜져 있고 인증키도 정상**이다(`/api/law/config` → `enabled:true, hasKey:true`).
검색도 된다(제목·시행일·링크까지 정상). 깨진 것은 **조문 본문** 단계다.

법제처 `lawService.do`는 조문 한 칸을 이렇게 준다:

```
조문번호  34
조문내용  "제34조(개인정보 유출 등의 통지ㆍ신고)"      ← 제목 줄뿐이다
항       [4건]  { 항번호:"①", 항내용:"① 개인정보처리자는 …",
                 호:[{호번호:"1.", 호내용:"1. 유출등이 된 개인정보의 항목"}, …] }
```

**본문은 `조문내용`이 아니라 `항[].항내용`에 있다.** 그런데 파서는 `조문내용`만 읽는다:

`server/src/engine/lawinfo.ts:273`
```ts
text: arr(u["조문내용"] as string | string[]).map(str).join("\n").trim(),
```

그 다음 줄(275)이 `text`가 빈 칸을 걸러 내므로, 항이 있는 조문은 **아예 사라지거나 제목만 남는다.**
그리고 `registry.ts:329`가 `.catch(() => [])`로 오류를 삼켜, 위에서는 「없다」로만 보인다.

### 실측 — 얼마나 빠지나

| 법령 | 조문 | 지금 본문 0자 | 고친 뒤 |
|---|---|---|---|
| 개인정보 보호법 | 126건 | **97건 (77%)** | **0건** |
| 개인정보 보호법 시행령 | 140건 | **96건 (69%)** | **0건** |

제1조(목적)처럼 **항이 없는 단항 조문만 살아남는다.** 실무에서 찾는 조문은 대부분 항이 여럿이다.

## 3. 패치 (그대로 붙이면 된다)

`server/src/engine/lawinfo.ts` — `getLawArticles()` 안, 270~274줄의 `mapped` 를 교체:

```ts
  // ⚠ 2026-08-13 실사고: 조문내용만 읽으면 **항이 여럿인 조문은 제목 줄만 남는다.**
  //   법제처는 본문을 `항[].항내용`, 그 아래를 `호[].호내용` · `목[].목내용`에 따로 담는다.
  //   실측: 개인정보 보호법 조문 126건 중 **97건(77%)이 본문 0자** · 시행령 140건 중 96건.
  //   그 빠진 자리에 「유출 신고 72시간」(시행령 제40조①)이 있어, 제품이
  //   "법령에 명시되어 있지 않다"고 **단정**했다 — 과태료가 걸린 기한이다.
  const 조문본문 = (u: Record<string, unknown>): string => {
    const 머리 = arr(u["조문내용"] as string | string[]).map(str).join("\n").trim();
    const 몸 = arr(u["항"] as Record<string, unknown>[]).map((h) => {
      const 호들 = arr(h["호"] as Record<string, unknown>[]).map((o) => {
        const 목들 = arr(o["목"] as Record<string, unknown>[])
          .map((m) => arr(m["목내용"] as string | string[]).map(str).join("\n"))
          .filter(Boolean);
        return [str(o["호내용"]).trim(), ...목들].filter(Boolean).join("\n");
      }).filter(Boolean);
      return [str(h["항내용"]).trim(), ...호들].filter(Boolean).join("\n");
    }).filter(Boolean);
    return [머리, ...몸].filter(Boolean).join("\n").trim();
  };
  const mapped = 조문칸.map((u) => ({
    no: str(u["조문번호"]),
    title: str(u["조문제목"]),
    text: 조문본문(u),
  }));
```

`arr`은 제네릭(199줄), `str`은 `unknown`을 받으므로(200줄) 그대로 쓰면 된다.

**검증(실데이터로 이미 재현해 확인함)**
- 개인정보 보호법 제34조: 22자 → **823자**
- 시행령 제40조: 19자 → **743자**, 「**72시간**」 들어옴
- 본문 0자 조문: 97건 → **0건** / 96건 → **0건**

### 같이 봐 줄 것 두 가지
- **`registry.ts:329`의 `.catch(() => [])`** — 조문 조회 실패를 통째로 삼킨다. 삼키더라도
  「조문 원문은 못 가져왔다」를 답에 남겨야 한다. 안 그러면 이번처럼 **모델이 「법에 없다」로
  메운다.**
- **`law_config.domain` 값이 `www,gijo.ai`** — 쉼표다(점이 아니다). 지금은 검색이 되니
  법제처가 안 막는 모양이지만, `normalizeLawDomain()`(84줄)이 스킴·경로·포트만 떼고
  **모양 검사를 안 한다.** 2026-08-09에 Referer 때문에 하루 태운 자리다 —
  점이 없거나 공백·쉼표가 든 값은 저장할 때 되물어 주는 게 낫다.

## 4. 덤으로 찾은 것 — **온톨로지 2,166건이 한국어로는 안 닿는다**

같은 회차에 `lt-onto-2`를 파다 나왔다. `/api/ontology/expand`는 **subject 전체 문자열이
질문 안에 들어 있어야** 매칭된다:

| 질의 | 결과 |
|---|---|
| `T1566 Phishing` | 12건 |
| `T1566 Phishing 완화통제 뭐야?` | 12건 |
| `T1566` | **0건** |
| `Phishing` | **0건** |
| `피싱` | **0건** |

게다가 subject 2,166건 중 **한글이 든 것은 264건(12%)** 뿐이고 나머지는 영문 ATT&CK 코드명이다.
담당자는 「T1566 Phishing」을 외우고 있지 않다. **한국어로 물으면 절대 안 닿는다.**

⚠ 이건 네가 찾은 말투 문제보다 **한 단계 더 나쁘다.** RAG는 거리가 밀릴 뿐이라 재작성으로
0.19를 되찾았지만, 온톨로지는 **정확 일치라 0이다.** 재작성으로도 안 된다 —
「피싱」 → 「T1566 Phishing」은 질의 재작성이 아니라 **용어 사전 매핑**이다.
**▶ 별칭 표를 만들어 뒀다 — `server/src/lite/onto-aliases-ko.json`** (2026-08-13, max)
- 170항목 · 한국어 낱말 451개. ATT&CK 기법 93 · 완화통제 39 · OWASP LLM 11 · CWE 27을 덮는다.
- **주어 이름은 온톨로지와 대조해 오타 0건**을 확인했다(틀리면 조용히 안 맞는 자리라 꼭 봐야 한다).
- 실측: 낱말을 주어로 바꿔 `expand`를 부르면 「피싱 막으려면」 **0 → 12건**, 「랜섬웨어 대응」 0 → 12,
  「망 분리」 0 → 12, 「무차별 대입」 0 → 12, 「공급망 공격」 0 → 12, 「다중 인증」 0 → 12.
- 쓰는 쪽에서 역인덱스를 만들고 **긴 낱말부터** 맞춰야 한다(「무차별 대입」이 「대입」보다 먼저).
- ⚠ 아직 안 덮은 것: **ATLAS(AML.T####) 205개**와 전술 이름 39개. 2단계로 남긴다.
- 파일을 `server/src/lite/`에 둔 건 경계 때문이다 — 제품 어디로 옮길지는 win이 정한다.

## 5. 라이트 쪽 상태 (참고)

라이트 문항 **32/33**. 남은 하나가 이 `lt-seed-law`다 — **고칠 때까지 실패로 둔다.**
게이트가 실제 결함을 붙잡고 있는 상태라 맞다.

앞 회차에 실패로 남았던 셋(`lt-search-2`·`lt-explain-2`·`lt-onto-2`)은 다시 재 보니
**전부 내가 문항을 과하게 박은 것**이었다. 특히 `lt-search-2`는 `search` 도구로 못 박아 뒀는데,
실제로 `search`를 태우면 「찾지 못했습니다」가 나오고 지금 경로가 **맞는 답**을 낸다 —
**더 나쁜 길을 정답으로 박아 두고 있었다.** 셋 다 답 내용으로 보게 바꿨다.

## 6. 재측정 회신 (max, 2026-08-13 03:00 — 네 수리 768e33e 반영 후)

파서 수리는 **맞게 들어갔는데 이 문항은 여전히 실패한다.** 원인이 한 겹 더 있다:

**`lawAnswer`(lawinfo.ts:309)는 검색 제목·링크만 주고 조문 본문을 아예 안 준다.**
본문은 질문에 조문 번호가 있을 때(`조문번호()` → `lawArticleAnswer`)만 탄다.
담당자의 실무 질문(「며칠 안에 신고해야 돼?」)에는 번호가 없다 — **네가 고친 파서에
닿기 전에 흐름이 끝난다.**

그리고 실측에서 더 나쁜 걸 봤다. 본문이 없으니 모델이 빈자리를 이렇게 메웠다:

> "실무에서는 유출 발생 후 즉시 또는 **최대 5일 이내**에 신고하는 것이 일반적이다.
>  이는 개인정보 보호법 **시행령 제16조**에 근거를 두고 있으며…"

**5일도 제16조도 지어낸 것이다** — 조문 번호까지 조작했다. 꼬리표(「원문 확인 못 함」)는
정직하게 붙었지만, 담당자는 본문의 단정을 믿는다.

▶ 제안: `lawAnswer`에서 상위 검색 결과의 조문 제목 목록을 받아(이미 `getLawArticles(mst)`가
전체 목록을 준다), **질문 낱말과 겹치는 제목의 조문 2~3건만 본문을 붙인다.**
「유출·신고」 → 제34조(유출 등의 통지·신고)·시행령 제40조(유출 등의 신고)가 정확히 걸린다.
이러면 72시간이 본문으로 들어오고, 지어낼 자리가 없어진다.

### 곁가지 — lt-neg-noassign이 한 번 흔들렸다
「이 취약점 담당자한테 배정해줘」(라이트에 배정 도구 없음)에 **「배정 완료」라고 답한 회차가
1번** 있었다(직후 4연속 재측정은 전부 정상 — 「아직 아무것도 바꾸지 않았습니다」).
비결정 흔들림인데 **하필 조작 방향**이라 기록한다. 문항의 forbid는 맞게 물고 있으니 그대로 둔다.

### 곁가지 2 — PDF 인입 (라이트 화면에서 막아 둔 이유를 확정)
추출은 `python3+pypdf`(extract_doc.py)를 타는데 **라이트 동봉본에는 파이썬이 없다**
(개발 venv 것이었다). 고객 기계에서 넣으면 못 읽는 글이 지식으로 들어간다 — 화면 문구를
사실대로 바꿔 막아 뒀다. 열려면 JS 추출기(pdf-parse류)를 서버에 들이는 게 제일 싸 보인다 — 네 판단.

## 7. 정밀 재측정 (max, 2026-08-13 — 네 f7d4fcc 반영 후)

「72시간 이내에 … 신고해야 한다」를 그대로 준다(공개 test 키로도 확인). 파서·본문 수리는 유효하다.

  (개인정보 보호법 **제30조**·**고시 제2023-6호**·「구체적 기간 규정 없음」).

- 네 f7d4fcc는 번호 없는 질문에 조문 본문을 붙이는데, **본법만 당기고 시행령은 안 당기는 것으로 보인다.**

▶ 제안: 「유출·신고」류 질문에서 **본법과 시행령을 함께** 조회해 본문을 붙인다(시행령은 별도 mst다 —

  질문 낱말과 겹치면 그 본문을 다 붙인다. 그러면 72시간이 컨텍스트에 들어가고 지어낼 자리가 없어진다.
