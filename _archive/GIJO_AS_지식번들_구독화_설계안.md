# 후-3 기본 지식 번들 구독화 — 설계안

> 작성 2026-07-31 · 상태 **설계안(구현 미착수)**
> 계획서 후-3: "표준·위협·법령 번들 연 단위 갱신 상품(오프라인 번들 배송) — 일회성 라이선스에
> 반복 매출 축 추가. 폐쇄망 고객일수록 '갱신 데이터'가 돈이 됨"

---

## 1. 지금 어디까지 되어 있나 (전-4에서 만든 기반)

**새로 만들 것이 생각보다 적습니다.** 번들의 뼈대는 이미 있습니다.

| 이미 있는 것 | 무엇 |
|---|---|
| **버전 체계** | `2026.07-1` CalVer — "언제 기준의 세상인가"가 지식의 본질이라 날짜가 정직합니다 |
| **번들 내용물** | 온톨로지 표준 시드 9종(KISA·ATLAS·OWASP·NIST·CWE·ATT&CK 등 ~2,000 트리플) + 제품 문서 + 보안 지식 6종 |
| **멱등 적용** | 이미 들어간 것은 건너뜁니다 — 두 번 적용해도 중복이 안 쌓입니다 |
| **무결성 지문** | 문서별 sha256을 들고 있습니다 |
| **재배포 고지** | MITRE·OWASP·NIST·KISA 라이선스 문구를 번들 상태에 함께 내보냅니다 |
| **상태 API·화면** | 지금 어느 버전이 적용됐는지 확인 가능 |

**즉 후-3는 "번들을 만드는 일"이 아니라 "번들을 계속 보내주고 받는 길"을 만드는 일입니다.**

---

## 2. 무엇을 만들어야 하나 — 4가지

### ① 번들 파일 포맷 (`.gijobundle`)

폐쇄망이라 인터넷으로 받을 수 없습니다. **파일 하나로 배송**합니다(USB·승인된 반입 경로).

```
gijo-knowledge-2026.10-1.gijobundle   (실체는 zip)
├── manifest.json      버전·발행일·유효기간·수록 항목·각 파일 sha256
├── signature.bin      ⚠ GIJO 개인키 서명 (아래 ② — 가장 중요)
├── ontology/          표준 시드 트리플
├── docs/              지식 문서
└── ATTRIBUTIONS.txt   재배포 고지(MITRE·OWASP·NIST·KISA)
```

### ② 서명 검증 — **이게 없으면 만들면 안 됩니다**

⚠ **번들 반입은 그대로 두면 공급망 공격 경로입니다.** 가짜 번들 하나로 온톨로지를 오염시키면 AI 답변이 통째로 조작됩니다 — 오늘 막은 간접 프롬프트 주입과 같은 계열이고, 파급은 훨씬 큽니다.

| 항목 | 설계 |
|---|---|
| 서명 | GIJO 개인키로 manifest 해시에 서명(Ed25519). **개인키는 우리 빌드 환경에만** |
| 검증 | 공개키는 제품에 내장. 서명이 안 맞으면 **반입 거부**(경고가 아니라 거부) |
| 되돌리기 | 적용 전 스냅샷 → 문제 시 이전 번들로 복귀 |
| 기록 | 누가·언제·어느 버전을 반입했는지 감사 기록 |

### ③ 구독 기간 — ⚠ **만료돼도 기존 지식을 뺏지 않습니다**

이 결정이 제품의 성격을 정합니다.

| 상태 | 동작 |
|---|---|
| 구독 중 | 새 번들 반입 가능 |
| **만료 후** | **이미 들어간 지식은 그대로 씁니다.** 새 번들만 못 받습니다 |
| 화면 표기 | "지식 기준일 2026.07 · 구독 만료 — 최신 위협 정보가 반영되지 않습니다" |

**왜**: 돈을 안 냈다고 이미 준 지식을 빼앗는 것은 **인질극**이고, 보안 제품이 할 짓이 아닙니다. 고객사 입장에서도 "구독 끊기면 AI가 바보가 된다"면 애초에 도입을 못 합니다. 대신 **낡았다는 사실을 계속 눈에 보이게** 해서 갱신의 필요를 스스로 느끼게 합니다.

### ④ 무엇이 바뀌었나 — 갱신 가치의 증명

담당자가 상급자에게 "이거 왜 매년 돈 내요?"에 답할 수 있어야 합니다.

```
2026.07-1 → 2026.10-1 갱신 내역
· 새 CVE 매핑 1,240건 (KEV 신규 38건 포함)
· ATT&CK v17 반영 — 기법 24개 추가·6개 폐기
· KISA AI 보안 위협 매뉴얼 2026.9 개정 반영
· 개인정보보호법 시행령 개정(2026.9) 반영
```

**이 요약이 곧 상품의 값어치**입니다. 번들에 담아 보내고 화면에 그대로 보여줍니다.

## 3. ⚠ 먼저 정해야 할 것 (개발 전)

### 법무 — 재배포 권리

이미 `BUNDLE_ATTRIBUTIONS`에 적어 뒀지만 **"고지"와 "상품에 담아 파는 것"은 다릅니다.**

| 출처 | 확인 필요 |
|---|---|
| MITRE(ATT&CK·ATLAS·CWE) | 저작권 고지+라이선스 재현 조건. **상업 재배포 범위 확인** |
| OWASP | CC 라이선스 — 조건 확인 |
| NIST | 퍼블릭 도메인(출처 표시) — 문제 적음 |
| KISA | 문서별 **공공누리 유형** 확인(유형에 따라 상업 이용 제한) |
| **법령 원문** | 국가법령정보센터 이용 조건 — 조문 전재 가능 여부 |

> 코드로 못 푸는 항목입니다. **법무 확인 전에는 "표준 코드 매핑"까지만 담고 원문 전재는 피하는 편**이 안전합니다.

### 사업 — 가격·주기

계획서 §"가격 구조"에 달린 항목입니다. 개발이 정할 수 없습니다:
- 연 단위인지 반기인지 · 라이선스 대비 비율 · 미갱신 시 지원 범위

## 4. 단계와 예상

| 단계 | 내용 | 예상 |
|---|---|---|
| **0** | 법무·사업 결정 대기 (§3) | — |
| **1** | 번들 빌더 — 지금 자산을 `.gijobundle`로 묶는 도구 + manifest·지문 | 2시간 |
| **2** | **서명·검증** — Ed25519 서명, 공개키 내장, 실패 시 반입 거부 | 2시간 |
| **3** | 반입 화면 — 파일 고르기·검증 결과·갱신 내역 표시·적용 | 2시간 |
| **4** | 구독 상태 — 기준일·만료 표기, 만료 후에도 기존 지식 유지 | 1.5시간 |
| **5** | 되돌리기 + 감사 기록 + 자가 진단 항목("지식 기준일이 N개월 지났습니다") | 1.5시간 |
| **6** | 챗봇 안내·용어사전·시험·실측 | 1.5시간 |
| | **합계** | **약 10.5시간** |

**1·2단계만 먼저(4시간)** 해도 값이 있습니다 — 번들을 만들어 안전하게 배송할 수 있게 되고, 그때부터 수동 반입이 가능합니다.

## 5. 정직하게 남기는 것

- **서명 검증 없이는 이 기능을 열면 안 됩니다.** 반입 경로가 곧 공급망 공격 경로입니다
- **개인키 관리가 새 부담입니다** — 우리 빌드 환경에서 새면 가짜 번들을 누구나 만듭니다. HSM까지는 아니어도 최소한 빌드 머신 밖으로 나가지 않게 해야 합니다
- **법무 확인 전에는 원문 전재를 피합니다** — 표준 코드·관계 매핑은 우리가 만든 것이라 안전하지만, 원문 문단은 다릅니다
- 갱신 내역을 **자동으로 만들 수 없습니다** — 무엇이 왜 바뀌었는지는 사람이 씁니다(그게 상품의 값어치이기도 합니다)

---

## 6. 결정이 필요한 것

1. **법무 확인을 먼저 받을지**, 아니면 1·2단계(빌더·서명)만 선행할지
2. **만료 정책** — "기존 지식 유지"에 동의하시는지(제 강한 추천)
3. **서명 키 관리** — 빌드 머신 로컬 / 별도 보관소
4. 갱신 주기 — 연 1회 / 반기 / 분기(위협 정보는 빨리 낡습니다)
