# 점검 보고 — 개발이 목적에 맞는가 · 설계는 건전한가 · 사업성은 있는가

> 2026-08-19. 기준 문서(전중후 계획서)와 코드를 직접 대조한 결과다. 좋은 말과 나쁜 말을 같은 무게로 적는다.

---

## 1. 목적 정렬 — **맞다. 단 한 곳에서 무게가 쏠렸다**

### 1차 목표·차별점이 코드로 실존하는가 (직접 확인)
| 계획서가 정한 것 | 코드 실존 | 상태 |
|---|---|---|
| 1차 목표: 3소스 통합 분석·관제 | `analysishub.ts` + 통합 관제 판 | ✅ 동작(QA 실측) |
| 차별점: AI-BOM | `sbom`·aibom 5영역 | ✅ |
| 차별점: 온톨로지 | `ontology.ts` + 표준 데이터 2종 + 번들(전-4 완료) | ✅ |
| 차별점: 레드팀/가드레일 | `redteam.ts`·`guardrail.ts` | ✅ |
| 공백 ②: 인수인계 | `handover.ts` | ✅ 있음 · ⚠ **실사용 0** |
| 공백 ③: 행동 대조 | `actioncheck.ts` | ✅ 있음 · ⚠ **실사용 2건**(123건 중 121이 QA) |

### 전 단계(~1개월) 진도
- 전-1 시연 · 전-2 행동대조 · 전-3 후보함 · 전-4 번들 · 전-6 정직 경계 · 전-7 보여 주기 — **개발 몫 전부 완료/유지**.
- **전-5 파일럿 1곳 — 유일한 미완이고, 사업(사장님) 몫이다.** 중·후 전 단계가 여기 걸려 있다.

### ⚠ 정직한 지적 — 무게 쏠림
최근 2주(3에디션·프로 셸·팝업·세로 대응·QA)는 전부 **전-7 「보여 주기」의 연장**으로 계획서와 정렬된다(사장님 승인 편입 기록 있음). 문제는 방향이 아니라 **비율**이다:
- 계획서의 판매 서사 1·2번(**인수인계·행동 대조를 전면에**)은 코드가 완성된 채 **쓰인 적이 없다.**
- 화면 층(에디션·셸·팝업)은 두꺼워지는데, **차별점의 증거(실사용 데이터)는 0에서 안 움직였다.**
- 계획서 원칙 그대로 말하면: 지금은 "보여줄 것"은 충분하고 **"보여줄 곳"이 없다.**

## 2. 설계 건전성 — **뼈대는 좋다. 위험 3곳을 이름 붙여 둔다**

### 잘 서 있는 것 (코드로 확인)
1. **세 축이 서로 독립** — 에디션(어떤 상품, 데이터·도구) × 셸 모드(화면을 어떻게, standard/pro) × 티어(엔진 값). 어제 프로 판정 때 일부러 가른 구조를 max도 「통합 제품의 축」으로 그대로 승인 — 3에디션 사업 구조의 코드 기반이 이미 서 있다.
2. **단일 출처 + 감시 시험이 설계를 강제한다** — 시험 332파일/3,670개 중 43파일이 「같은 것을 여러 곳에 적으면 어긋난다」를 지키는 감시다(STAGE_SCREENS·GROUPS·판 목록·ALL_MARKS·티어표…). 설계 문서가 아니라 **시험이 설계다** — 이 저장소의 가장 강한 자산.
3. **정직성이 코드에 박혀 있다** — tierhonesty(없는 기능 팔기 금지)·falseclaim(가짜 완료)·「못 거르는 화면은 못 거른다고 말한다」·못 구한 값은 「—」. 보안 구매자가 과장을 가장 빨리 알아챈다는 전-6과 정확히 정렬.
4. **지시 입구가 하나**(대화창) — dispatchentrances 시험이 강제. 원칙이 흔들린 곳(라이트 할일 입력칸)은 QA 보고서에 예외로 기록돼 있다.

### ⚠ 위험 3곳 (이번 주 실측이 근거)
| 위험 | 근거 | 처방 |
|---|---|---|
| **① 내부 갈래 누적** — 핵심 8파일이 1,000~1,900줄(dispatcher 1,849 · agentloop 1,926 · registry 1,758). 빠른 길·강제 규칙·결정적 답이 겹겹 | 「갈래 하나를 빠뜨리면 오류도 없이 아무 일도 안 일어난다」를 **이번 주에만 4번** 겪음(범위 3갈래+프로 신호) | 새 값·새 신호를 만들면 **갈래 전수 목록**을 시험으로 강제(ALL_MARKS 방식의 확장). 파일 쪼개기는 급하지 않다 — 감시가 있는 한 |
| **② 배관 이중화** — postMessage(탭)와 IPC(팝업) 두 겹. 재주입으로 처리 복제는 피했지만, 릴레이할 gijo:* 타입이 nav.js에 **손목록**(select·scope·openTab) | 새 gijo:* 타입을 만들고 릴레이에 안 넣으면 팝업에서만 조용히 죽는다 — `#범위` 표식 누락과 같은 부류 | picklistmarks처럼 **릴레이 목록 감시 시험** 신설(소) |
| **③ 화면이 가로 전제** — 세로 대응이 사후 @media 패치 8건 | 주모니터가 세로인데 한 번도 안 쟀었다 | 새 화면 규칙에 「@media 포함」을 uireadability급 시험으로(소) |

**총평: 설계는 목적(폐쇄망·정직·대화 중심)에 충실하고, 약점은 구조가 아니라 "갈래가 늘 때 새는 것" — 그리고 그걸 잡는 장치(감시 시험)를 이미 만드는 법을 안다.**

## 3. 사업성 — **있다. 단 유통기한이 있고, 병목은 코드 밖이다**

### 계획서 결론의 현재 유효성 (재검)
- **경쟁력의 실체 = 시간의 창**: 국내 동종(이글루·SK쉴더스·샌즈랩)은 전부 과제·파일럿 단계, 우리는 완결형. 이 판정은 중-8(2026-08-01 재조사)까지 유지 — **다음 재조사 2026-10**.
- 창은 닫히는 중: SentinelOne·Google 에어갭 진출 공식화, 12~24개월 추정.
- 공백 2개(인수인계·행동대조)는 **여전히 시장 공백** — 우리 최대 차별화 유지.

### 지금의 사업 상태 (숫자로)
| 항목 | 값 |
|---|---|
| 제품 판정 | **파일럿 투입 가능 · GA 미판정** (코드 P0 9/9, 외부 관문 0/4) |
| 파일럿 | **0곳** — 중·후 전 단계의 전제 |
| 차별점 실사용 | 인수인계 0 · 행동대조 2건 — **증거 경쟁인데 증거가 아직 자기 실측뿐** |
| 축적 해자(후-6) | 실질 0건 |
| 매출 축 | 라이선스 + 번들 구독(후-3 뼈대 완성 · **가격 미정**) + 에디션 3종 사다리(라이트 무료→표준→프로) — 이번 3에디션 작업이 여기 기여 |
| 코드 밖 미결 4건 | 파일럿 대상 · 인증 예산 · 가격 · 법무 면책 — **전부 사장님 결정 대기** |

### 판정
1. **사업성은 성립한다** — 실존 공백 2개 + 완결형 제품 + 정부 방향(RAG·N2SF) 정합 + 3에디션 가격 사다리. 이건 흔치 않은 조합이다.
2. **그러나 가치가 감가한다** — 경쟁력이 기능이 아니라 시간이므로, 파일럿 없이 보내는 한 달이 곧 비용이다.
3. **개발은 더 이상 병목이 아니다.** 지금 제품을 한 달 더 다듬는 것보다 **지금 상태로 한 곳에 설치되는 것**이 사업 가치가 크다. 남은 개발(잔여 결함·문구)은 파일럿과 병행 가능한 크기다.
4. 개발이 사업을 도울 수 있는 남은 두 가지: **전-1 시연 패키지 최신화**(3에디션·프로·⓪자산이 대본에 없다 — 낡았다) · **중-5 N2SF 문서**(공공 조달 언어).

### 한 줄 결론
> **제품은 팔 준비가 됐고, 설계는 그 제품을 지킬 준비가 됐다. 다음 90일의 변수는 코드가 아니라 전-5(파일럿 1곳)와 코드 밖 결정 4건이다.**
