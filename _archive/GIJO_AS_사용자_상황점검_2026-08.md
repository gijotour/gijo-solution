## 1. 상황을 어떻게 만들었나 — 지어내지 않았다

상상해서 만든 시나리오는 "다 통과했다"는 착각만 남긴다. 그래서 **화면에 실제로 있는 것**에서 뽑았다.

| 종류 | 개수 | 뽑은 방법 |
|---|---|---|
| 버튼 | 506 | 버튼 253개 × {자료 있을 때 / 하나도 없을 때} |
| 입력 | 292 | 입력칸 146개 × {제대로 넣기 / 빈 채로 넘어가기} |
| 상태 | 198 | 화면 33개 × {처음 열 때·자료 많을 때·서버 느릴 때·권한 없을 때·창 좁을 때·항목 눌러 들어왔을 때} |
| 챗봇 | 99 | 화면 33개 × 대표 질문 3개 |
| 선택 | 38 | 고르는 목록 전부 |
| **합계** | **1,133** | |

**같은 버튼이라도 상황이 다르면 다른 일이다.** 자료가 없을 때 [저장]을 누르는 것과 있을 때 누르는 것은 담당자에게 전혀 다른 경험이다.

## 2. 어떻게 쟀나

| 방법 | 범위 | 도구 | 왜 이렇게 |

| **실화면 전수** | 사이드바 화면 **29개 전부** 열어 봄 | `tools/ux-clickthrough.mjs` | 소스가 멀쩡해도 안 뜰 수 있다 |

> "되는가"는 기계로 전수, "답이 좋은가"는 표본. 이 구분을 숨기지 않는다.

## 3. 무엇을 봤나 — "직관적이고 쉬운가"를 기계가 볼 수 있게

| 규칙 | 담당자가 겪는 일 |
|---|---|
| U1 이름 없는 조작 | 아이콘만 있고 설명이 없다 → 뭐 하는 버튼인지 모른다 |
| U2 죽은 조작 | 눌리게 생겼는데 아무 일도 안 한다 |
| U3 막막한 빈 화면 | "없습니다"만 있고 **다음에 뭘 하라는 말이 없다** |
| U4 확인 없는 위험 동작 | 되돌릴 수 없는데 그냥 지워진다 |
| U5·U9 영어 노출 | 읽어야 하는 자리에 영어가 있다 |
| U6 약속-동작 불일치 | "이 자산의 ○○"라 적어 놓고 전체를 연다 |
| U8 날것 오류 | HTTP 상태·스택을 그대로 보여준다 |
| C1~C4 실화면 | 화면이 뜨는가 · 비어 있지 않은가 · 조작할 게 있는가 · 첫인상이 오류가 아닌가 |

## 4. 고친 것 (4건)

### ① 지식 관계를 **묻지도 않고** 지웠다 — 온톨로지

```js
// 고치기 전
async function removeTriple(id) {
  try { await window.gijo.removeOntologyTriple(id); ... }
  catch (e) {}          // ← 실패해도 아무 말이 없다
}
```

🗑을 누르는 **즉시** 지식 관계가 사라졌다. 되돌리기도 없는데 확인도 없으면 **손이 미끄러진 것과 결심한 것을 구별할 방법이 없다.** 게다가 `catch`가 비어 있어 **못 지웠는데도 조용했다** — 담당자는 지워진 줄 알고 넘어가는데 목록엔 그대로 남아 있다.

**고침**: 무엇을 지우는지 보여주며 묻고, 실패하면 말한다.

> 이 관계를 지울까요?
> `방화벽 — 완화통제→ CVE-2021-44228`
> 지운 관계는 되돌릴 수 없습니다. AI가 이 관계를 근거로 하던 답이 달라질 수 있습니다.

### ② 화면에 **`[undefined]`** 가 그대로 보였다 — 기억·학습(RAG)

문서 건강검진 결과에 `[undefined]`가 떴다. 서버는 **`demo_overlap`**(데모 문서가 실제 문서와 겹침)이라는 종류를 내는데 **화면 표에 그 이름이 없었다.**

**고침**: 이름을 추가하고, **모르는 종류가 와도 `[undefined]` 대신 종류 이름이라도 보이게** 했다 — 그래야 담당자가 우리에게 알려줄 수 있다.

### ③ 머신러닝 용어가 날것으로 — 기억·학습(RAG)

> 고치기 전: `학습 중 — step 40/100, loss 0.83`
> 고친 뒤: `학습 중 — 40/100단계 · 오차 0.83`
> 고치기 전: `✓ 학습 완료 — 최종 loss 0.41`
> 고친 뒤: `✓ 학습 완료 — 마지막 오차 0.41 (낮을수록 잘 배운 것)`

담당자는 머신러닝 용어를 모른다. **뜻을 화면에 그대로 적었다.**

### ④ 막막한 빈 화면 4곳 — 학습 루프·레드팀

| 고치기 전 | 고친 뒤 |
|---|---|
| 아직 실행 이력이 없습니다. | 아직 실행 이력이 없습니다 — **아래 [학습 시작]을 누르면 첫 학습이 돕니다.** |
| 신호 강한 후보가 없습니다 | 신호 강한 후보가 없습니다 — **담당자가 👍를 누른 답이 쌓이면 여기에 뜹니다.** |
| 아직 실효 점검 기록이 없습니다. | 아직 실효 점검 기록이 없습니다 — **[실효 점검 실행]을 누르면 지금 방어 상태를 잽니다.** |

## 5. 살펴봤지만 **고치지 않은 것** (판단 근거를 남긴다)

| 지적 | 판단 | 왜 |

## 7. 앞으로 볼 것 (고치지 않고 남김)

1. **「보안 KPI」에서 바로 할 수 있는 일** — 지금은 숫자만 본다. "이 지표가 나쁜데 뭘 하지?"에서 화면을 떠나야 한다. 지표에서 해당 목록으로 가는 길을 붙이는 것을 제안한다(오늘 고친 「누른 것으로 간다」와 같은 결).
2. **1,133개 중 챗봇 99개는 표본만 확인** — 서랍 17문항으로 대신했다. 전수는 실 LLM이라 4시간이 든다.
3. **표에 없는 값이 오면 `[undefined]`** — 오늘 1건 고쳤고, 같은 꼴이 24곳 더 있다. 서버 값과 대조해 **실제로 빠진 곳은 없음을 확인**했지만, 서버에 종류를 더할 때 화면도 같이 고쳐야 한다는 약한 고리는 남아 있다.

## 📖 용어 풀이

- **상황(시나리오)** — 담당자가 실제로 겪는 한 장면. "자료가 없을 때 [저장]을 누른다" 같은 것.
- **오탐(거짓 지적)** — 문제라고 잡았지만 실제로는 멀쩡한 것. 오탐을 그대로 보고하면 멀쩡한 코드를 고치러 가게 된다.
- **정적 검사** — 프로그램을 돌리지 않고 소스만 읽어 보는 것. 빠르지만 화면이 실제로 어떻게 보이는지는 모른다.
- **실화면 검사** — 앱을 실제로 띄워 화면을 열어 보는 것. 느리지만 "안 뜬다"를 잡는 유일한 방법.
- **막막한 빈 화면** — 자료가 없을 때 "없습니다"만 있고 다음에 뭘 하면 되는지 안 알려주는 화면.
