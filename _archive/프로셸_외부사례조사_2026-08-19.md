# 프로 셸 외부 사례 조사 (gijo-scout, 2026-08-19)

## 결론 먼저

프로 셸의 「대화 홈 + 화면은 팝업」 구조는 업계 사례와 **부분적으로만** 일치한다. 승인 흐름(결재판)·근거 배지·작업표시줄 깜빡임은 이미 업계 표준 방향(HITL 4요소, OS 알림)과 같은 방향이지만, **"화면을 별도 OS 창으로 띄운다"는 결정 자체는 업계 최신 흐름(지속형 사이드바·사이드카 패널)과 반대 방향**이다. 중요 코드 사실: `app.html:299-305`에 표준 셸이 "화면을 팝업으로 띄우던" 옛 구조를 **버리고** 탭으로 바꾼 이유가 적혀 있다 — *"팝업이 존재하던 유일한 이유가 '이동하지 않아 대화가 유지된다'였는데, 그걸 구조로 해결한다."* 프로 셸은 다른 이유(대화창 하나 유지)로 팝업을 재채택했다 — 이 「왜」를 분명히 해 둘 가치가 있다.

## ⓑ 없는 것 상위 5
1. **「접고 펴는 패널」 옵션 부재** — 팝업(별도 창)뿐. 사이드카/지속형 사이드바(대화가 안 가려지는 배치)가 업계 최신 흐름과 가장 벌어진 지점.
2. **알림함 부재** — 깜빡임 1회가 전부. 동시 다건 진행 시 「무엇이 대기/완료인지」 한눈 장치 없음.
3. **다단계 절차(Promptbook) 부재** — ⭐는 단문만.
4. **핀보드형 요약 부재** — 긴 대화에서 중요한 것만 압축 저장하는 장치 없음.
5. **빈 상태가 4원칙 중 절반** — 워크드 예시·한계 노출 없음.

## ⓒ 이미 잘하는 것 5 (과잉 개발 방지)
1. 결재판이 HITL 골격(필드 수정·실행되면·되돌리기) 충족 — 라벨 다듬기 수준이면 됨.
2. flashFrame 절제 사용 — MS 가이드 부합.
3. 근거 원문/배지 = Security Copilot의 프로세스 로그와 같은 방향, 이미 구현.
4. 팝업에서 화면 내 챗봇 위젯 숨김 — 「대화는 한 곳」 파편화 회피.
5. 서랍의 here/ok/go 3분류 = Cmd+K 3분류 철학과 동일.
