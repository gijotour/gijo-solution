# WAF SQL 인젝션 차단 — 실제 공격 판단
- 로그 분석: 차단된 요청의 출발지 IP·평판(위협 인텔), URL·파라미터, 페이로드를 확인. ' OR 1=1, UNION SELECT, sleep()/benchmark(시간지연), 주석(--,#) 등 전형적 SQLi 패턴인지 본다.
- 정상 여부 구분: 애플리케이션이 정상적으로 특수문자를 포함할 수 있는 필드(검색어 등)에서 나온 단발성인지, 여러 파라미터·엔드포인트를 훑는 자동화 스캔(반복·다량)인지 구분.
- 상관 분석: 동일 IP의 다른 요청(디렉터리 스캐닝, 다른 공격 시도), User-Agent(sqlmap 등 도구 흔적), 빈도·시간대를 함께 본다. WAF만이 아니라 웹서버·DB 로그와 교차.
- 판단·조치: 실제 공격이면 IP 차단·모니터링 강화·해당 파라미터의 서버측 파라미터라이즈드 쿼리 점검. 오탐이면 룰 예외. 애매하면 탐지 상향 후 관찰.
- 담당자 요약: "페이로드 패턴+출발지 평판+반복성+도구 흔적으로 판단. 웹·DB 로그와 교차, sqlmap 흔적이면 실공격 유력."
