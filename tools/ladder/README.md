# tools/ladder — 3일 증류 사다리 (계획서 `GIJO_AS_AI팀_증류학습_계획서.md` §12)

사장님 2026-09-03 「허락」으로 시작한 3일짜리 실험 사다리다.

```
1일차  재료 확장(증류)        day1-distill.sh   → results-ladder/day1/<주제>-<회차>.json
2일차  RAFT형 학습 → A/B      day2-train.sh     → results-ladder/day2/<회전>/
       ↳ 표본 5조건 + KEV     team-bench/{ask-samples,kev-probe}.mjs → samples-*.json · kev.json
       ↳ 게이트               team-bench/gates.mjs → gate.json · gate.md
3일차  판정(채택 여부)        사람이 한다 — 게이트는 「못 넘은 것을 막는」 자일 뿐이다
```

한 번만 미리: `bash tools/ladder/day2-train.sh --baseline-probe` — 어댑터 **없는** 베이스로 같은
표본 5조건(grounded·distractor-only·bare·persona·knowledge) + KEV를 돌려 `results-ladder/baseline/`에
둔다. 관문 ①·⑤·⑧·⑭이 견줄 상대가 그 파일들이다. 베이스 폴더는 `LADDER_BASELINE_DIR`로 바꿀 수
있다 — 문항 파일이 바뀌면 **옛 베이스를 덮지 말고 새 폴더에** 쌓는다(모집단이 다르면 자리별로
견주는 ⑤·⑬·⑭이 거짓 빨강을 낸다. 2026-09-11 40문항 전환에서 `baseline-q40/`을 그렇게 만들었다).

⚠ 표본·KEV는 **$PORT(기본 8093)의 두뇌에 직접** 던진다. A/B를 돌리는 `run.mjs`는 회차가 끝날 때마다
자기가 띄운 서버를 내리므로(run.mjs:106 finally), 사슬은 표본 단계에서 **같은 어댑터를 얹어 다시 띄운다.**
2026-09-04 수리 전에는 그 자리에 두뇌가 없어 ECONNREFUSED로 `exit 8` — 게이트에 닿지도 못했고
관문 ⑧·⑩은 회전 갈래에서 영영 「미측정=불합격」이었다(껍데기 두뇌로 사슬을 완주시켜 실측).

### ⚠ gb10 결과를 저장소에 남기는 순서 (안 지키면 push가 거부된다)

**gb10 결과는 scp로 win에 가져와 커밋한 뒤 gb10 쪽 사본을 지우고 push한다** — 같은 파일이 gb10에
untracked로 남아 있으면 `git push gb10 main`이 작업트리를 못 바꿔 **거부된다**(2026-09-04에 두 번 겪었다.
gb10은 `receive.denyCurrentBranch=updateInstead`라 push가 작업트리까지 갱신하기 때문이다).

그 순서를 그대로 하는 자가 있다 — **win에서** 돌린다:

```bash
bash tools/ladder/gb10-sync-results.sh r2-v2                  # ① gb10 → win (로그·pid는 안 가져온다)
git add tools/team-bench/results-ladder/day2/r2-v2 && git commit   # ② 커밋은 **사람이** 한다(무엇을 남길지 눈으로 본다)
bash tools/ladder/gb10-sync-results.sh r2-v2 --after-commit   # ③ gb10 쪽 커밋된 파일만 삭제 → push → rev-list 0 0
```

### ① 재료 빌드 — **win**에서, 운영 4000 창구로

```bash
# 먼저 눈으로 본다(저장하지 않는다). 판 짜기 인자가 맞는지, 회수율이 떨어지지 않았는지.

# 같은 명령에서 --dry-run 만 빼면 서버 위생 창구로 저장한다(운영 data/datasets/ 에 남는다).
```

- 실측: 보낸 행 1,124 → 저장 1,115(**위생이 뺀 행 9**). 「보낸 수 ≠ 저장 수」의 차이가 곧 위생 적발이다.
- ⚠ **admin은 계정당 1세션**이다. 이 빌더·증류기·표본 하네스가 같은 계정을 쓰므로 **하나씩** 돌린다.
  세션이 물려 있으면 밀어내지 말고 기다린다(밀어내면 남의 회차가 죽는다).
  2026-09-04에 이 빌더가 로그아웃을 안 해 **유령 세션 30분**이 남았고 다음 도구가 26분을 기다렸다 —
  지금은 성공·실패 어디로 끝나든 세션을 닫는다(`server/test/raftdataset.test.ts` 가 그것을 감시한다).

### ② 캘리브레이션 슬라이스 — **win**에서

```bash
node tools/ladder/make-cal-slice.mjs <원본.json> --n 160
#  → <원본>-cal160.json · 행수·md5·글자수(평균/p95)를 찍는다
```

- 식은 `rows[⌊i×n/160⌋]`(균등 간격). **앞 160행을 자르면 승인 순서 쏠림이 그대로 실린다.**
- 실측(raft-vuln-v2, 1,115행): md5 `4939415652d08bad37a73dab82995544` ·
  슬라이스 글자수 평균 3189 / p95 4102 (전체 3176 / 4074 — 닮았다).

### ③ gb10으로 보내기 — **두 자리에 똑같이**

```bash
scp raft-vuln-v2.json raft-vuln-v2-cal160.json gb10:~/gijo-as/server/data/datasets/
scp raft-vuln-v2.json raft-vuln-v2-cal160.json gb10:~/bench/lora-vuln/data/datasets/
ssh gb10 'md5sum ~/gijo-as/server/data/datasets/raft-vuln-v2*.json'   # win에서 잰 값과 대조
```

- 왜 두 자리인가: 사슬(`day2-train.sh`)은 `$SERVER_DIR/data/datasets/` 를 읽고,
  캘리브레이션(`cal-run-v2.sh`)은 `cd ~/bench/lora-vuln` 뒤 `data/datasets/` 를 읽는다.
  ⚠ 학습기는 **cwd 기준** `data/datasets/<id>.json` 을 연다(`finetune_qlora14b.py:75`) — 그래서 자리가 둘이다.
- ⚠ WireGuard 너머라 RTT 70~106ms다. 6MB짜리도 체감이 있고, 모델 크기는 밤을 잡아먹는다.

### ④ 캘리브레이션 10스텝 — **gb10**에서

```bash
ssh gb10 'cd ~/gijo-as && bash tools/ladder/cal-run-v2.sh 4096 raft-vuln-v2-cal160'
# 볼 것 ① 길이 초과 제외가 0인가  ② 스텝 간격(=초/스텝)  ③ 최소 가용 메모리
```

- 실측: **96초/스텝**(maxSeq 4096). 회전 1은 73.2초/스텝이었다(maxSeq 3072) — **maxSeq를 올리면 느려진다.**
- ⚠ **글자 ≠ 토큰.** 재료 보고서가 주는 것은 글자수인데 maxSeq는 토큰이다. 한국어는 글자 1개가
  토큰 1~2개라 글자수로 어림하면 틀린다 — 토큰 분포는 `tools/ladder/tokcount.py` 로 따로 센다.
  그래도 **확정은 학습 로그의 「길이 초과 제외 N」**이다(그 값이 0이 아니면 뒤=답이 잘린 행이 생긴 것이다).
- ⚠ **swap이 차오를 때 `free` 의 available은 거짓말을 한다.** 「아직 여유 있다」로 보이는데 실제로는
  스왑을 긁고 있어 초/스텝이 갑자기 늘어난다 — `available` 만 보지 말고 `swap` 칸을 함께 본다
  (`watch-r2.sh` 가 두 값을 같은 줄에 적는 이유다).

### ⑤ 에폭 정하기 — **≤ 6.5시간이면 3에폭**

- 산수: 초/스텝 × 스텝수 × 에폭. 실측 96초/스텝에서 **1에폭 ≈ 1시간 45분** → 3에폭 ≈ **5시간 15분** → 3으로 간다.
- 6.5시간을 넘길 것 같으면 2에폭으로 내린다. 밤 하나에 안 끝나는 회전은 **다음 날 아침을 통째로 먹는다.**
- `saveEpochs: true` 면 에폭마다 체크포인트를 남겨 **한 회전 안에서** 「3에폭이 과했나」를 잰다
  (회전 1은 5시간 20분을 굽고 마지막 것만 남겨 그 질문을 못 물었다).

### 승격한 gb10 홈 스크립트 3종 (2026-09-04)

회전 1·2 때 이 셋은 **gb10의 `~/bench/ladder/` 에만** 있었다. 기계 홈에만 있는 스크립트는
기계가 바뀌면 사라지고, 시험도 검토도 안 붙는다. 저장소로 올리면서 `$HOME` 에 박혀 있던 자리를
전부 env로 뺐다 — **값은 gb10 기본값 그대로**라 gb10에서는 하던 대로 돈다.

| 파일 | 하는 일 | 쓰는 법 |
|---|---|---|
| `cal-run-v2.sh` | 10스텝 캘리브레이션(초/스텝·길이 초과·메모리) | `bash tools/ladder/cal-run-v2.sh [maxSeq] [데이터셋id]` |
| `watch-r2.sh` | 5분마다 메모리·swap·스텝·eval·체크포인트 한 줄 | `bash tools/ladder/watch-r2.sh <회전>` → `~/bench/ladder/watch-<회전>.log` |
| `tokcount.py` | 재료의 **토큰** 길이 분포(글자수가 아니다) | `~/venv-train/bin/python tools/ladder/tokcount.py <재료.json>` |

자리 바꾸기(전부 env — 안 주면 gb10 기본값):
`LADDER_HOME`(결과·로그) · `LADDER_WORK_DIR`(학습이 도는 곳) · `LADDER_REPO_DIR`(저장소) ·
`LADDER_PYTHON` · `LADDER_HF_BASE_DIR`(=`BASE`) · `LADDER_INTERVAL` · `LADDER_PORTS` · `LADDER_CAL_TAG`.

- `cal-run-v2.sh` 는 시작 전에 파이썬·학습기·베이스 모델·데이터셋이 **있는지 먼저 본다**(원본에는 없던 것).
  캘리브레이션은 「빨리 알려고」 도는 자리라, 몇 분 뒤 로그 속에서 죽으면 그 존재 이유가 깎인다.
- `tokcount.py` 의 숫자는 **미리보기**다 — 학습기 `render()` 를 불러올 수 없어 그 안의 두 줄을
  글자 그대로 옮겨 적었다. **확정은 학습 로그의 「길이 초과 제외 N」**이다.

## 밤/낮 전환은 **산출물 존재**로 가른다

밤새 도는 일은 중간에 끊긴다(ssh 끊김·전원·사람의 Ctrl+C). 그때 「어디까지 했나」를 로그로
뒤지게 만들면 그건 자동화가 아니다. 그래서 **모든 단계가 자기 산출물을 보고 스스로 건너뛴다.**

| 무엇 | 있으면 건너뛰는 것 | 파일 |
|---|---|---|
| 1일차 회차 | `--skip-done` 을 주면 **끝난 회차 수만큼** | `results-ladder/day1/<주제>-<번호>.json` (**보고서만**) |
| 2일차 학습 | 학습(다시 안 태운다) | `server/data/lora/<회전>/adapter_model.safetensors` |
| 2일차 변환 | GGUF 변환 | `results-ladder/day2/<회전>/adapter.gguf` |
| 2일차 A/B | 그 회차 시험 | `results-ladder/day2/<회전>/easy|hard/<모델>.json` |

★ 회전 설정에 `saveEpochs: true` 가 있으면 학습이 `checkpoint-*` 를 남기고, 사슬은 그 **하나하나를
판으로** 잰다 — `adapter-epN.gguf` → `results-ladder/day2/<회전>/epN/{easy,hard,samples-*,kev,gate.md}`.
에폭 번호는 스텝 번호를 오름차순 정렬한 **자리**다(폴더 이름의 숫자는 총 스텝이지 에폭이 아니다).
왜: 1회전은 3에폭을 통째로 굽고 마지막 것만 남겨서 「3에폭이 과했나」를 **다시 굽지 않고는** 물을 수
없었다(5시간 20분). 체크포인트가 없으면 종전 그대로 마지막 어댑터 하나만 재고 파일 자리도 안 바뀐다.

회차 번호는 **디렉터리 상태만으로** 정해진다(`ladderlib.mjs 회차이름표`) — 다시 돌려도 앞
회차를 덮지 않고 `-02`, `-03`으로 쌓인다.
⚠ 증류 보고서의 원래 이름은 **시각 기반**(`.tmp-reports/distill-<주제>-<시각>.json`)이라
「이미 했나」를 파일로 못 가린다. 게다가 `.tmp-reports`는 `.gitignore`(66줄)라 사라진다.
그래서 회차마다 번호를 붙여 `results-ladder/`로 **복사해 남긴다.**

★ **끝난 회차의 증거는 보고서(`.json`) 하나뿐이다.** 로그(`<주제>-<번호>.log`)는 증류가
**시작될 때** 생기고 보고서는 **끝나야** 생긴다. 2026-09-03 1일차 실기동에서 회차 셈이 확장자를
안 가려 `사내규정-01.log`를 회차 1로 세는 바람에, **보고서 없이 죽은 회차를 `--skip-done`이
영영 건너뛰었다**(그날은 사람이 로그 이름을 손으로 바꿔 피했다 — 자동화가 사람 손을 부른 것이
결함의 증거다). 이제 셈은 `.json`만 세고, 실패·중단한 회차의 로그는 스크립트가
`<주제>-<번호>.failed.log`로 옮긴다. 점이 둘인 이름은 어떤 셈에도 안 걸리고, 폴더만 봐도
어느 회차가 죽었는지 보인다. Ctrl+C·SIGTERM으로 끊어도 같은 표식이 남는다(코드 130·143).

## 보고는 이 파일들에서만 나온다

게이트(`tools/team-bench/gates.mjs`)가 읽는 것은 **오직** 아래 파일들이다. 표의 모든 숫자는 여기서 온다.

| 원천 | 만든 자 | 게이트가 여기서 보는 것 |
|---|---|---|
| `easy/<모델>.json` | `run.mjs`(1회차 7과제) | 과제 점수 · 인용(겹침·인용) · 한글 · tok/s · 잘림 · 서술 답 길이 |
| `hard/<모델>.json` | `run-r2.mjs`(2회차 6과제) | 위와 같음(13과제 평균의 나머지 절반) |
| `samples-grounded.json` | `ask-samples.mjs --mode grounded` | 관문 ⑧ — 정답 조각을 20자 그대로 옮겨 적는 비율 · 관문 ⑫ — 그중 **베낀 글자**가 몇 할인가 · 관문 ⑬ — 그중 **거절문으로 시작한 답**이 몇 건인가 |
| `samples-distractor-only.json` | `ask-samples.mjs --mode distractor-only` | 관문 ⑩ — 「자료에 없다」고 말하는 비율 |
| `samples-bare.json` | `ask-samples.mjs --mode bare` | 관문 ⑤(잘림) · (참고) 한글 · **⑨의 참고값**(제품이 안 쓰는 조건이라 모집단에서 뺐다) |
| `samples-persona.json` | `ask-samples.mjs --mode persona` | 관문 ⑨ — 인용 창작(「원문:」·「[n]에 따르면」 둘 다). 팀원 프롬프트만 준 자리 = 제품에서 RAG가 빈 순간 |
| `samples-knowledge.json` | `ask-samples.mjs --mode knowledge` | 관문 ⑭ — **로컬 14B 단독**(원격 없음·근거 블록 없음)에서 아는 것을 잃지 않았는가. 근거는 프롬프트에 **안 싣고** 정답 조각만 파일에 적어 overlap20으로 채점한다 |
| `kev.json` | `kev-probe.mjs` | 관문 ① — 본문에서 CISA를 말하는가(베이스 대비) |
| `harness-args.json` | day2-train.sh | **무슨 조건으로 던졌나** — 포트·서버·에이전트·명령줄 |

베이스 대조(관문 ①·⑤·⑧·⑭이 견줄 상대)는 `results-ladder/baseline/`의 `kev.json`·`samples-*.json`이고(⑤가 자리별로 견준다),
⑤가 보는 세 자리(grounded·distractor-only·bare)는 **베이스에도 있어야** 한다 — 없으면 미측정=불합격이다.
⚠ `samples-persona.json`은 베이스도 함께 만들지만 **관문이 견주지는 않는다** — ⑨의 기준이 「0건」이라 상대가 필요 없다.
그래도 넘기는 이유(`--baseline-samples-persona`)는 표의 참고 줄에 「베이스도 같은 조건으로 쟀다」를 남기기 위해서다.
`bash tools/ladder/day2-train.sh --baseline-probe`가 **어댑터 없이 한 번** 돌려 만든다.

기준선(1·2회차 과제 점수)은 `tools/team-bench/results-ladder/baseline/`에 있고, **어디서 온 파일인지**는 그
폴더의 `README.md`에 적혀 있다. 없는 입력은 「미측정」이고 **전체는 불합격**이다(fail-closed) —
못 잰 것을 통과로 세면 게이트가 게이트가 아니다.

### 표본 문항은 어디서 왔나 — `tools/team-bench/samples-questions.json`

12문항은 gb10의 `~/bench/lora-vuln/samples-questions.json`(회전 1 때 쓴 그 파일)을 **한 글자도 안 바꾸고**
옮겼다. 여기에 `chunk`(정답 조각 본문)·`distractor`(방해 조각 본문)를 채웠는데, 되찾는 방법은
`tools/build-raft-dataset.mjs`가 학습 재료를 만들 때 쓰는 그 함수들(`refParse`·`방해조각고르기`)을
**그대로 불러서** 했다 — 학습이 본 조각과 시험이 보는 조각이 갈리면 재는 것이 딴것이 된다.

- 12문항 중 **8개만** 조각이 찼다. 나머지 4개는 원천이 `chat`이라 근거 ref 자체가 없다.
  빈칸으로 두고, 하네스가 grounded에서 **건너뛰며 그 수를 결과에 적는다**(0으로 세지 않는다).
- ⚠ **방해 조각 후보는 라이선스 허용목록으로 먼저 거른다.** 처음 회수했을 때 방해 8개 중 **4개가
  타사 상용 제품 가이드**에서 왔다 — `방해조각고르기`에는 라이선스 판정이 안 걸려 있기 때문이다
  (정답 조각에만 걸린다). 그 본문을 저장소에 넣으면 그냥 재배포다. `server/test/ladder.test.ts`가
  실린 조각의 출처를 매번 대조한다.

2026-09-11까지 ⑬⑭ 줄과 `gates.mjs`의 안내문이 「8건뿐」이라 말하고 있었고 실제는 36건이었다.
지금 세는 법: `node -e` 로 `samples-questions.json`의 `chunk` 20자 이상을 센다.

⑧~⑪은 r1-base 회전을 뜯어 보고 뒤늦게 붙였다 — 그때까지 **RAFT의 목적(근거를 주면 인용한다)을
재는 관문이 0개**였고, 실제로 난 회귀 두 가지(「원문:」 창작 · 서술 답 34~72% 축소)를 세는 코드도 없었다.

#### ⑤를 「0건」에서 「베이스 대비 증가 0」으로 바꾼 이유 (2026-09-04 실측)

베이스(어댑터 없음)가 **5건**이었고 그 5건은 **전부 samples-bare**였다(grounded 0 · distractor-only 0 ·
kev 0). bare는 시스템 프롬프트가 없어 베이스가 max_tokens 900까지 늘어놓는다 — 즉 절대 0건이 재던
것은 회귀가 아니라 **「프롬프트 없이 900토큰 상한」**이었다. 더 나쁜 것은 방향이다: r1-base가 ⑤를
통과한 이유가 **답이 66% 짧아져서**인데, 그 짧아짐은 ⑪이 잡으려는 바로 그 회귀다. ⑤가 ⑪의 표적에
상을 주고 있었다. 그래서 ①과 같은 꼴(**같은 자리끼리** 견주고 절대값은 참고)로 바꿨다.
⚠ 베이스에 그 자리가 없으면 **미측정=불합격**이다 — 그래서 `--baseline-probe`가 만든 표본 세 벌을
게이트에 다 넘긴다(`--baseline-samples` · `--baseline-samples-distractor-only` · `--baseline-samples-bare`).

#### ⑩의 기준을 0.5 → **0.75**로 올린 이유 (2026-09-04 실측)

**베이스 실측이 88%(7/8)로 나왔다.** 0.5는 「베이스가 이미 하는 것의 절반만 해도 통과」라 회귀를
반쯤 눈감아 주는 바닥이었다(실제로 r1-base는 **0%**였다 — 두 기준 다 빨강이지만, 0.5로는 44%짜리
회귀가 통과한다). 8문항이라 한 문항이 6.25%p씩 움직이므로, 베이스 아래에 두 문항의 흔들림만
봐 주는 자리가 0.75다. 상수는 `gates.mjs 자료없음_최소비율`.
관문 기준을 옮기는 것은 기준선 교체와 같은 자리라 **사장님 결정**이다(이 개정은 상위 결정으로 반영).

#### ⑫(베낀 글자 비율)를 새로 둔 이유 (2026-09-04 실측)

⑧(근거 인용)이 베이스 50% → r1-base **100%**로 올랐는데, 같은 답들의 **베낀 글자 비율**은
20% → **80%**였고 그중 **2건은 100%(통째 복사)**였다. ⑧은 「20자 창이 하나라도 남았는가」만 묻기
때문에 근거를 통째로 게워 내도 만점이다 — 「옮겨 적기」와 「붙여넣기」를 가르는 자가 없었다.
잣대: 공백을 지우고 **조각의 20자 창을 한 칸씩 밀며** 답에서 찾아, 덮인 글자 수 ÷ 답 글자 수
(창 20자·공백 제거는 `overlap20`과 같은 규칙 — 미는 폭만 1칸이다. 넓이를 재는 자라 4칸이면
가장자리가 샌다). 상수는 `gates.mjs 베낀비율_상한`(0.6).

#### ⑬(근거 준 자리의 거절)을 새로 둔 이유 (2026-09-05 · 회전 3 실측)

회전 3(r3-v3)의 ep1·ep2에서 **grounded 8건 중 7건이 거절문으로 시작**했다 —
「등록된 사내 자료에는 관련 내용이 없습니다…」로 시작해 놓고 그 뒤에 근거를 옮겨 적은 답이다.
근거를 **준** 자리에서 자료가 없다고 말하는 것은 RAFT가 가르치려는 것의 정반대인데,
같은 판에서 **⑧은 8/8 초록 · ⑫는 57%로 초록**이었다. ⑧은 「20자 창이 남았나」만, ⑫는
「얼마나 베꼈나」만 물어서 **답의 첫머리가 거절인지는 원리상 못 본다** — 거절 뒤에 복사해 이으면
둘 다 통과한다. 그 사각지대를 메우는 자다.

- 잣대는 **⑩과 같은 자**(제품 `자료없음중복가드` 정규식 · 앞 60자)다. ⑩이 「그렇게 말해야 하는 자리」를
  재는 자라면 ⑬은 「그러면 안 되는 자리」에서 같은 말을 센다 — 한 자를 두 방향으로 쓴다.
- 기준은 **베이스 대비 증가 0**(①·⑤와 같은 꼴). 실측 대조: 베이스 0/8 · r1-base 0/8 ·
  r2-v2 ep1~3 전부 0/8 · **r3-v3 ep1 7/8 · ep2 7/8**. 지금 베이스가 0이라 실질 기준은 0건이지만,
  절대 0건으로 못박으면 베이스가 언젠가 1건이 될 때 관문이 벽이 된다.
- `server/test/ladder.test.ts`가 위 일곱 파일의 숫자를 **실물로** 다시 잰다(관문이 회귀를 잡는지 그 자체를 잰다).

#### ⑨의 모집단을 bare → **persona**로 옮긴 이유 (2026-09-04 · 회전 2 실측)

회전 2(r2-v2)에서 ⑨에 걸린 창작 인용 **11건이 전부 bare**였고, 팀원 프롬프트만 준 조건(KEV `prompt`)은
**0건**이었다. 제품은 팀원 프롬프트 없이 모델을 부르지 않는다 — 즉 ⑨는 **제품에 없는 조건** 때문에
빨강이었고, 고칠 수 없는 빨강은 관문이 아니라 벽이다(①이 절대 3/3을 참고값으로 내린 그 논리 그대로).
그래서 세는 자리를 제품이 실제로 여는 자리(**팀원 프롬프트만 · 참고 자료 블록 없음** = `llm.ts`가
rag=null일 때 만드는 그 system)로 옮겼다. bare는 계속 재고 표에 **참고값**으로 적는다 — 지우면
「프롬프트가 있고 없고의 차이」를 아무도 못 읽는다.

⚠ **persona 표본이 없으면 ⑨는 미측정=불합격**이다. 옛 회전 결과(r2-v2 ep1~3)에는 그 파일이 없으므로

| 과제 | r2-v2 ep2 → r3-v3 ep2 | 무엇이 달라졌나(답 원문) |

  **ⓑ 꼴 — 블록 있음 + 거절로 시작 + 이어진 답**(예: 「Windows 서버에서 공유 폴더 권한 점검 …」 264자)이었다.
  어댑터가 낸 답도 정확히 그 꼴에 `[1]에 따르면 "…"`를 덧댄 것이다 — **ⓑ의 「거절+답」과 ⓐ의 「[n] 인용」이 섞였다.**
  회전 4의 by-kind가 겨누는 자리가 여기다.

##### eval_loss는 **회전 4부터** 회전 간 비교가 된다

`--eval-holdout N`은 **그 회전의 데이터셋 안에서** N행을 뗀다 — 재료가 바뀌면 시험지도 함께 바뀐다.
그래서 회전 2와 회전 3의 `eval_loss`를 나란히 놓은 것은 **다른 시험지의 점수**를 견준 것이었다
(회전 3의 「ep2 뒤 평평」은 그 회전 **안에서** 에폭을 견준 값이라 그대로 뜻이 있다 — 회전끼리가 안 된다).

회전 4부터는 홀드아웃을 저장소 파일 하나(`tools/team-bench/holdout-vuln-100.json`)로 고정하고,
빌더가 그 행들을 **데이터셋에서 뺀다**. 고르는 규칙은 결정적이다: 질문 뭉치를 통째로 떼고
(같은 질문이 양쪽에 있으면 그 손실은 「배웠나」가 아니라 **「외웠나」**를 잰다), **A행을 담은 뭉치가 먼저**,
그 안에서 sha12(질문) 오름차순. 학습기는 `--eval-file`로 그 파일을 읽고 `--eval-holdout`과 **함께 못 쓴다**
(시험지가 둘이면 어느 것으로 쟀는지 알 수 없다).

⚠ **gb10에서 사슬을 돌릴 때는 `--skip-build`를 쓴다.** 재료는 win에서 굽고 scp로 옮기는 것이 절차인데
(위 「회전 절차 한 장」 ①~③), gb10에서 빌드까지 돌면 ⓐ gb10의 승인 코퍼스로 **다른 재료**가 나오고
ⓑ 홀드아웃 파일이 **저장소 추적 파일**이라 gb10 작업트리가 더러워져 **다음 `git push gb10 main`이 거부된다**
(`receive.denyCurrentBranch=updateInstead`). `--skip-build`면 사슬이 시작 전에 홀드아웃 파일의 존재를 확인한다.

⚠ **회전 3 이전과는 비교되지 않는다.** 그 회전들의 eval_loss는 각자 다른 시험지의 값이다 — 섞어 읽지 않는다.
⚠ 홀드아웃 파일은 **저장소에 커밋된다**(데이터셋은 서버 `data/`에만 남는다). 그래서 빌더는 허용목록 밖
문서의 문장이 방해 조각으로 한 행이라도 실렸으면 **그 파일을 안 쓰고 죽는다**(저장소에 넣으면 재배포다).

## 학습 재료의 허용목록

`allowed-sources.json`이 **써도 되는 원천**을 정한다. 제외목록은 두지 않는다 — 제외목록은
새 파일이 생길 때마다 조용히 뚫리지만, 허용목록은 새 파일의 기본값이 「아님」이다.

```
node tools/ladder/ladderlib.mjs allow "knowledge/보안용어.md" "고객사_자산목록.xlsx"
  ✅ knowledge/보안용어.md          — knowledge/ 아래의 .md 문서
  ❌ 고객사_자산목록.xlsx           — 허용목록의 어느 규칙에도 안 걸린다 — 재료가 아니다
```

★ 새로 받아 온 공개 원천(`sources/nvd`·`cisa`·`attack`·`kisa`)은 **RAG에 넣지 않는다.**
파일 재료로만 쓴다(사장님 2026-09-03). 답변 근거로 섞이면 제품이 「사내 문서」와 「외부 원문」을
구분 못 하게 된다.

## 교사 병렬 — 조사 결과 (2026-09-03, 실측으로 갱신)

**결론부터: `--concurrency 2`는 실제로 병렬로 돈다. 2를 유지한다.**

먼저 적어 둔 「실측 4회 **1.00**(=완전 직렬)」은 **틀린 기록이었다.** 남이 같은 두뇌를 쓰는 중에
잰 숫자였다(아래 「재는 방법의 오염」). 슬롯이 빈 때를 잡아 다시 재니 값이 달라졌다.

### 잰 값 — 자가 둘이고 **방향이 반대**다

| 무엇을 쟀나 | 자 | 값 | 뜻 |
|---|---|---|---|
| 프로브 2회(96토큰짜리 짧은 요청) | 벽시계 ÷ 순차합 — **작을수록 병렬**(1.00=직렬 · 0.50=완전 병렬) | 0.655 · 0.915 | 평균 0.785 → **속도 1.27배** |
| **실작업**(증류 회차) | 교사시간합 ÷ 벽시계 — **클수록 병렬**(1.00=직렬 · 2.00=작업자 2로 완전 병렬) | **1.99** | 두 줄이 거의 완전히 겹쳐 돈다 |

⚠ **두 자를 섞어 읽으면 정반대 결론이 난다.** 하나는 작을수록, 하나는 클수록 병렬이다.
말할 때 **어느 자인지 먼저** 말한다.

⚠ **「1.6 이상이면 `--concurrency 2`」 잣대는 실작업 자(교사시간합 ÷ 벽시계) 기준이다.**
프로브 자로 1.6을 찾으면 영원히 안 나온다(그 자는 1.00이 최댓값이다). 실측 1.99 ≥ 1.6 → **2 유지.**

### 왜 두 숫자가 이렇게 다른가

프로브는 **96토큰**짜리 짧은 요청이라 한 번이 몇 초다. 그 몇 초에서 프리필·큐 대기·왕복이 큰 몫을
차지해 겹치는 구간이 짧고, 표본도 둘뿐이라 크게 흔들린다(0.655 ↔ 0.915).
실작업은 요청 하나가 **20~30초**(실측: 조각당 16~31초)라 겹치는 구간이 길다.
**판단의 근거는 실작업 쪽이다** — 우리가 밤새 태우는 일이 그것이기 때문이다.
짧은 프로브로 긴 작업의 병렬성을 대신 재려 한 것이 애초의 오류였다.

**사슬 어디에도 직렬화가 없다.**

| 자리 | 무엇을 봤나 | 결론 |
|---|---|---|
| `tools/distill.mjs` | `Promise.all(Array.from({length: CONC}, worker))` (366줄) | 진짜 동시 작업자 2 |
| 4000 창구 `llmserve.ts` | 큐·뮤텍스 없음. `처리중 >= 동시상한(2)`이면 **429로 거절**하고, 통과하면 그대로 상류로 흘린다(425~500줄) | 2건까지는 직렬화 안 함 |
| `localBaseUrl()` → `ensureAgentModel` | 이미 올라간 모델이면 즉시 반환(`localengine.ts:616-622`) | 락 없음 |
| llama-server 8080 | `--parallel 2`, `--cont-batching` **기본 enabled**(`--help` 실측) | 슬롯 2개 |
| `/slots` 40초 표본 | `1 1 1 1 1 0 1 … 2 2` — **최대 2** | 실제로 2개가 동시에 돈다 |

→ 그러므로 애초의 1.00은 「소프트웨어가 줄 세운 것」이 아니었다. 실제 원인은 둘째다.

1. ~~**대역폭 한계.**~~ 이 설명은 **실측이 기각했다.** 교사는 Qwen3.8-Flash-Next(125B MoE, Q3, 84GB)이고
   gb10 통합메모리 대역은 273GB/s라 「두 줄을 돌려도 합계 처리량이 안 는다」고 봤는데, 실작업
   **1.99**가 나왔다. MoE라 토큰마다 읽는 활성 가중치가 전체가 아니어서 두 줄이 겹칠 여지가 있었다.
   ⚠ 그럴듯한 물리 설명은 **재기 전까지는 가설**이다 — 이 자리에서 실제로 틀렸다.
2. **재는 방법의 오염**(이게 원인이었다). 교사는 **공용**이다. 남이 쓰는 중에 재면 남의 부하를 잰다 —
   2026-09-03 첫 측정이 0.98 tok/s(평시 24.5의 1/25)로 나왔고, `/slots`를 보니 다른 작업이
   슬롯을 물고 있었다. 슬롯이 빈 때를 잡아 다시 재고서야 위 표의 값이 나왔다.

**더 올리려면 — 제안만(제품 코드는 안 고쳤다)**

- ⓐ **동시 수를 3 이상으로 올리는 것이 첫 수는 아니다.** 2에서 이미 1.99(상한 2.00)라 **2는 거의
  다 쓰고 있다** — 다음 이득은 3부터인데 그건 ⓑ의 두 곳을 같이 손대야 한다. 먼저 **요청당 산출을
  키우는** 쪽이 싸다(`--per-chunk` 3 → 5~6). 프리필과 가중치 읽기가 더 많은 출력 토큰에 나뉘어
  **조각당 비용**이 내려간다. 재료 수가 같아도 요청 수가 줄어드는 것이 요점이다.
- ⓑ 그래도 올린다면 **두 곳을 같이** 올려야 한다: llama-server `--parallel N`과 서버
  `GIJO_SERVE_CONCURRENCY`(기본 2). 하나만 올리면 창구가 429로 막거나 슬롯이 남아돈다.
  ⚠ **슬롯당 문맥이 `--ctx-size ÷ N`**이다 — 지금 32768÷2 = **16,384**이고, N=4면 8,192로 준다.
  증류 조각(800자)은 들어가지만 긴 조각은 그 자리에서 400으로 죽는다(KISA 가이드 조각이
  149,612토큰으로 죽은 전례). 올릴 거면 `--ctx-size`도 함께 올린다.
- ⓒ **스왑을 먼저 본다.** 지금 3.2GiB가 스왑에 있다(121GB 중 75GB 사용). 두뇌가 페이지 폴트를
  만나면 동시 수는 아무 의미가 없다.
- ⓓ **다시 잴 때는 슬롯이 빈 것을 확인하고 잰다.** `~/bench/ladder/branch4/par-probe.mjs`가
  그렇게 만들어져 있다(점유>0이면 코드 2로 스스로 멈춘다). 프로브 비율은
  `벽시계 ÷ (단독 t 합)` — **1.00=직렬, 0.50=완전 병렬**(작을수록 좋다).
  ⚠ **채택 판단(「1.6 이상이면 2」)에는 이 자를 쓰지 않는다.** 그 잣대는 실작업 자
  `교사시간합 ÷ 벽시계`(**클수록 좋다**, 작업자 2면 상한 2.00) 기준이고, 값은 회차 보고서의
  `teacherMs`와 그 회차 벽시계로 바로 나온다. 프로브는 **짧은 요청**이라 같은 사슬을 대변하지 못한다.

⚠ **8080은 재기동하지 않았다.** 그 프로세스는 제품 관리 대상이고, 지금 다른 작업이 쓰는 중이다.

## ⚠ 회전 1~4 표본은 「가드 이전」의 답이다 (2026-09-05)

제품에 **인용 검증 가드**(`server/src/engine/citeguard.ts`)가 붙었다 — 근거가 없거나 조각과 20자도
안 겹치는 「[n]에 따르면 "…"」·「원문: "…"」을 답에서 **뗀다**. 그래서 앞으로 표본을 뜨는 조건이
회전 1~4와 갈린다:

- **지문(system)은 그대로다.** ⓐ·ⓑ 지시는 팀원 **공통 가지**에만 넣었고 `normaltic` 가지는 한 글자도
  안 바꿨다 — 회전 1~4 표본의 `agentPromptSha12`(`3452677d58b7`)와 `prompt-spec.json`이 지금도 같다
  (`server/test/raftdataset.test.ts`가 llm.ts 정본과 글자 단위로 대조한다). 규격 재추출은 필요 없다.
- **⚠ 근거 블록 꼴이 갈렸다(2026-09-05 J3) → 2026-09-05 K4에서 닫았다.** 제품의 「참고 자료」 블록은
  **`[n] 《문서 제목》 본문`**으로 나간다(제목이 있을 때). J3 시점에는 빌더(`참고자료블록`)에 제목
  개념이 없어 **학습 표본에는 제목이 없고 추론 지문에는 있는** 상태였다 — 어긋나도 아무 오류가
  안 나는 부류라, 그때는 「다음에 구울 때 먼저 정하라」고만 적어 두었다.
  **결정(2026-09-05): 빌더도 제목 포함 꼴을 쓴다.** 바뀐 것은 셋이다.
  1. 창구 예시 `ragBlockSample`이 `ragBlock(["<조각 본문>"], ["<문서 제목>"])`이다 —
