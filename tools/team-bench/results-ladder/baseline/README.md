# 증류 사다리 기준선 — 어디서 온 파일인가

`gates.mjs`가 「기준선 이상인가」를 물을 때 **비교 대상으로 삼는 두 파일**이다.
기준선이 어디서 왔는지 모르면 게이트는 「무엇보다 나은지」를 모르는 자가 된다 — 그래서 여기 적는다.

## 두 파일

| 파일 | gb10 원본 | 만든 도구 | 만든 때(gb10 시각) | sha256 |
|---|---|---|---|---|
| `r1-qwen3-14b.json` | `~/bench/results/qwen3-14b.json` | `tools/team-bench/run.mjs` (`tasks.mjs` 7과제) | 2026-09-03 00:52 | `9681a397…22bf38` |
| `r2-qwen3-14b.json` | `~/bench/results-r2/qwen3-14b.json` | `tools/team-bench/run-r2.mjs` (`tasks-r2.mjs` 6과제) | 2026-09-03 02:17 | `3f406630…d90de08e` |

가져온 날: **2026-09-03**, `scp gb10:~/bench/results…` (파일 내용 그대로 — 이름만 `r1-`/`r2-`를 붙여 어느 회차인지 파일명으로 알게 했다).
가져온 뒤 양쪽 sha256이 같음을 확인했다.

⚠ **왜 저장소에 넣었나** — 원본은 gb10 홈에만 있었다. git에는 `results-lora`·`results-r3`만 있어서,
게이트가 「기준선 이상」을 물어도 **비교할 파일이 저장소 어디에도 없었다.** 기준선이 한 기계의
홈 디렉터리에만 있으면 그 기계를 지우는 순간 판정 근거가 사라진다.

## 무엇을 잰 기준선인가

- 모델: **qwen3-14b** (Apache-2.0, 무어댑터 베이스). 계획서 §12의 **학생 1순위**다.
  사다리가 학습시키는 것이 이 모델이므로, 「학습 전의 자기 자신」이 기준선이다.
- 조건: temperature 0 · json_schema 강제 · 생각 끔(`--reasoning off`) · `cache_prompt:false` · gb10.
- 1회차 평균 **0.99** / 2회차 평균 **0.58** (각 회차 summary.md의 그 줄).

### ★ needle_64k는 이 모델에서 원리상 0이다 — 게이트가 기본으로 빼는 이유

2회차를 `--ctx 65536`으로 돌렸는데 서버 로그는 이렇게 말한다:

```
llama_context: n_ctx_seq (65536) > n_ctx_train (40960) -- possible training context overflow
srv load_model: initializing, n_slots = 1, n_ctx_slot = 40960
```

즉 **모델의 학습 문맥이 40,960**이라 그 위로는 열리지 않는다. needle_64k 요청은 74,256토큰이라
`400 request … exceeds the available context size`로 떨어졌고, 그래서 기준선 점수가 0이다.

이건 「모델이 못 찾은 것」이 아니라 **「우리가 줄 수 없는 것」**이다. 학습으로 나아질 수 있는 항목이
아니므로 `gates.mjs`는 평균에서 기본으로 뺀다(`--include-needle64k`로 넣을 수 있고, 넣으면 표에
「포함」이라고 적힌다 — 어느 쪽으로 쟀는지가 항상 표에 남는다).

## 2026-09-04 재채점 — 채점 구멍 둘을 고치고 **같은 채점기로 다시 세었다**

`report_draft`(tasks.mjs T4)와 `report_fix`(tasks-r2.mjs R6)의 「절 세기」가 `text.includes(절이름)`
이었다. 그러면 본문에 절 이름을 **나열만 해도** 그 절을 쓴 것으로 세어진다 — 실측(r1-base)에서
아래 답이 **6/6**을 받았다:

```
제목 / 대상 자산 / 위험 요약 / 조치 방법 / 조치 기한 / 담당 부서
hr.example.co.kr(10.20.1.22) /upload.do 의 임의 파일 업로드 취약점(…)
```

서식을 안 지켰는데 만점이라, 서식 회귀를 잡으려고 만든 채점기가 원리상 그것을 못 잡았다.
고친 규칙: **절 제목이 줄 머리에 있고(#·번호·불릿·굵게 허용) 그 아래(또는 `:` 뒤)에 본문이 한 줄 이상**
있어야 한 절로 센다(`tasks.mjs`의 `절세기` — 두 회차가 **같은 함수**를 쓴다).

기준선을 새 채점기로 다시 돌린 결과(답 원문이 결과 JSON에 남아 있어 **재채점만** 했다. 모델을 다시
돌리지 않았다 — 그러면 그날의 기준선이 아니게 된다):

| 회차 | 과제 | 재채점 전 | 재채점 후 | 비고 |
|---|---|---|---|---|
| r1 | scan_extract · needle_16k · priority_rank · ti_match · glossary_cite · tool_select | 그대로 | 그대로 | 채점기 안 바뀜 |
| r1 | **report_draft** | 0.9 (절 5/6) | **0.9 (절 5/6)** | 기준선 답은 실제로 `## 제목` 꼴이라 값이 안 바뀐다 |
| r2 | needle_32k · ti_trap · priority_6 | 그대로 | 그대로 | 채점기 안 바뀜 |
| r2 | **report_fix** | 1.0 (절 6/6) | **1.0 (절 6/6)** | 위와 같음 |
| r2 | needle_64k | 0 | **재채점 불가** | 요청이 400으로 죽어 답이 없다(점수 0은 「실패」의 기록이라 그대로 둔다) |
| r2 | scan_messy | 0.5 | **재채점 불가** | ↓ |

⚠ **`scan_messy`는 재채점할 수 없다.** `run.mjs`가 결과 JSON에 답을 `answer.slice(0, 1500)`으로만
남기는데, 이 답이 정확히 1,500자라 **JSON이 잘려 있다**. 다시 채점하면 「JSON 없음 → 0」이 나오는데
그건 모델이 못한 것이 아니라 **우리가 답을 다 안 적어 둔 것**이다. 그래서 이 과제는 재채점 대상에서
빼고 원래 값(0.5)을 그대로 둔다 — 잘린 답으로 0을 적으면 기준선이 거짓말을 한다.
(고치려면 `run.mjs`의 1,500자 자르기를 늘려야 하는데, 그건 다음 기준선부터 적용될 일이다.)

**결론: 기준선 파일 두 개는 한 글자도 안 바꿨다.** 새 채점기로 재채점해도 같은 값이 나왔기 때문이다.
바뀐 것은 「앞으로 회전이 받을 점수」다 — r1-base 회전의 답을 새 채점기로 재채점하면
`report_fix` **0.7 → 0.2**(절 6/6 → 0/6) · `report_draft` **0.5 → 0.4**(절 1/6 → 0/6)로 떨어진다.
즉 이 수리는 **기준선을 흔들지 않고 회전만 정직하게 만든다** — 게이트가 더 엄해지는 쪽으로만 움직인다.
(r1-base의 `easy/`·`hard/` 결과 파일은 **그날 채점기가 매긴 값 그대로** 둔다. 나중에 고친 자로 옛
결과를 덧칠하면 그 파일이 「언제 무엇으로 쟀는지」를 거짓으로 말하게 된다.)

## 베이스 대조 파일(관문 ①·⑧) — 여기 함께 산다

`bash tools/ladder/day2-train.sh --baseline-probe` 가 어댑터 **없이** 베이스를 띄워 만든다:

| 파일 | 쓰는 관문 | 왜 필요한가 |
|---|---|---|
| `kev.json` | ① KEV 하락 0 | 절대 3/3은 **베이스도 2/3**이라(3번 문항) 관문으로 두면 늘 빨강이다 — 늘 빨강인 관문은 회귀를 못 알린다 |
| `samples-grounded.json` | ⑧ 근거 인용 | 「근거를 주면 옮겨 적는가」의 출발점이 없으면 나아졌는지 나빠졌는지 말할 수 없다 |
| `samples-distractor-only.json` · `samples-bare.json` | (참고) | ⑩·⑨는 절대 기준이라 대조가 필수는 아니지만, 베이스 값이 있어야 기준(0.5)을 올릴 근거가 생긴다 |

## 기준선을 바꿀 때

- 기준선 교체는 **사장님 결정**이다(평가 게이트의 `--accept-baseline`과 같은 자리).
- 바꾸면 이 표의 원본 경로·시각·sha256을 **같이** 고친다. 파일만 갈아끼우고 표를 두면
  게이트가 「무엇과 견줬는지」를 거짓으로 말하게 된다.
