## 1. 준비 (한 번만)

```bash
pip install -U "huggingface_hub[cli]"
huggingface-cli login          # 사장님 HF 토큰(write 권한) 입력
```

## 2. 비공개 레포 만들고 업로드

```bash
# 레포 이름은 조직/이름 형식 — 예: gijotour/gijo-main-orchestrator-GGUF
huggingface-cli repo create gijotour/gijo-main-orchestrator-GGUF --type model --private -y

# 모델 카드 먼저(레포 루트 README.md로)
huggingface-cli upload gijotour/gijo-main-orchestrator-GGUF \
  ~/gijo-as/hf-upload/README.md README.md

# gguf 업로드 (5.1GB — 회선에 따라 시간 걸림, 자동 재시도됨)
huggingface-cli upload gijotour/gijo-main-orchestrator-GGUF \
  ~/gijo-as/server/models/gijo-main-orchestrator/gijo-main-orchestrator.gguf \
  gijo-main-orchestrator-Q4_K_M.gguf
```

⚠ **레포 이름(`gijotour/gijo-main-orchestrator-GGUF`)을 정하시면 알려 주세요** — 제품의 「받기」가
그 이름을 가리키게 max가 박습니다. 파일명은 `<이름>-Q4_K_M.gguf` 꼴을 권합니다(로더가 quant를 봅니다).

## 3. 게이트(접근 통제) 켜기

HF 웹 → 레포 → **Settings → Access requests: Gated → Manual approval** (또는 Automatic).
- 모델 카드의 `extra_gated_fields`(회사명·라이선스 키·용도)가 요청 폼으로 뜹니다.
- 라이선스 고객이 요청하면 승인 → 그 계정 토큰으로만 받아집니다.

## 4. 고객 토큰 흐름 (제품 연결)

라이트에서 「받기」로 이 모델을 내려받으려면 고객이 **HF 접근 토큰**을 제품에 넣어야 합니다:
- 제품에 이미 **HF 토큰 저장소**가 있습니다(`server/src/engine/modelauth.ts` — 암호화 보관).
- ⚠ **지금 라이트 설정에는 토큰 입력칸이 없습니다**(본 제품 settings.html에만 있음). 올리신 뒤
  max가 라이트 설정에 **「GIJO 모델 받기」 + 토큰 입력**을 얹습니다(그때 레포 이름 필요 — 2절).
- 폐쇄망 고객은 토큰·인터넷이 없으므로 **파일(USB) 등록**을 그대로 씁니다 — 이미 동작합니다.

## 5. 올린 뒤 확인

```bash
# 다른 계정/토큰으로 받아지는지(게이트 동작) 확인
huggingface-cli download gijotour/gijo-main-orchestrator-GGUF \
  gijo-main-orchestrator-Q4_K_M.gguf --local-dir /tmp/hf-test
shasum -a 256 /tmp/hf-test/gijo-main-orchestrator-Q4_K_M.gguf
#   → 위 SHA256과 같아야 함
```

## 6. max가 이어서 할 것 (레포 이름 주시면)
- 라이트 설정 「챗 모델 등록 → 받기」에 **GIJO 모델 한 줄** 추가(레포 이름 하드코딩) + **HF 토큰 입력칸**.
- 받기 성공 후 자동으로 목록에 뜨고 「올리기」로 켜지는 것까지 — 실측 검증.
