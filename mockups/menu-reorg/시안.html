3「제품」 3중 충돌 해소안

이름을 정확히 하는 것이 핵심이다. 세 화면 모두 지우지 않는다 — 실제로 세 화면 다 각자 역할이 있다(정찰 결론). 대안 세 갈래를 검토했다.

대안내용판정
A. 재명명 + 등록부 그룹에 통합 (채택) products.html → "우리 보안제품", intro.html → "보안제품 비교·소개"로 이름을 바꾸고 같은 그룹("보안제품")에 둔다. "우리 것" vs "비교용 외부 자료"라는 대비가 이름만으로 드러난다. 채택
B. 세 화면을 한 화면으로 합친다 등록부(우리 제품)와 카탈로그(외부 비교)는 데이터 대장이 다르다(products vs productintro, intro.html:10 주석). 합치면 "우리가 쓰는 것"과 "검토 중인 것"이 뒤섞여 담당자가 오인해 결재판·자산 연동에 잘못된 제품을 건다 — 위험이 이름 헷갈림보다 크다. 기각
C. 세 화면 다 그대로 두고 툴팁만 추가 사이드바 라벨은 tab 이름·검색 결과·즐겨찾기에 그대로 따라다니는 단일 출처다(app.html:412 "이름의 주인은 사이드바"). 툴팁은 마우스를 올려야 보여 처음 쓰는 사람은 여전히 못 찾는다 — 이름 자체를 고치는 것보다 약하다. 기각

4반입 흐름 가시화 — 새 화면 없이

제품 원칙(메뉴는 보기용·새 화면에 입력칸 금지)을 지키며, 기존 자리(내 문서 🩹 반입 탭)를 사이드바에서 미리 알리는 최소안.

채택 — "내 문서"에 배지

내 문서☆3

기존 .gn-upbadge 패턴(nav.js:1439~1468, 진행중 작업·기한초과 배지와 같은 부품) 재사용. 숫자는 "오늘 새로 반입된 문서"(0이면 숨김·99+ 상한 — 이미 있는 규칙 그대로). 누르면 지금과 같이 내 문서 카드가 뜨고, 그 안 🩹 반입 탭이 처음 보이는 탭이 되면 목적지가 한 번에 맞는다.

근거: 숫자가 우선순위 판단(오늘 볼 게 있다/없다)에 쓰이는 경우에만 숫자 배지를 쓰고 0이면 숨기는 것이 뱃지 UI 통례 — PatternFly·Setproduct 가이드와 우리 기존 배지 둘 다 이 규칙.

대안 B (기각) — 대시보드에 「최근 반입」 판

grouppanels.js에 새 판을 추가하는 방식. 더 풍부하게 보여줄 수 있지만:

범위대시보드(현황판)는 이 시안(왼쪽 패널)의 대상이 아니다 — 별도 시안·별도 구현 필요
비용grouppanels.js 새 판 설계(열 규약 4열 등) + 서버 API 확인 필요, 사이드바 배지보다 큰 작업
중복 위험내 문서 🩹반입 탭과 같은 데이터를 또 보여주면 "어디가 맞는 자리인가"가 새로 생긴다(이 저장소가 반복 경계하는 함정)

5왼쪽 패널 활용 아이디어 — 핀 / 최근 / 컨텍스트

아이디어판정이유
핀(즐겨찾기) 이미 있음 — 손대지 않음 ★/☆ 즐겨찾기 가지가 이미 있다(nav.js:564~580, 2026-07-28부터). 다시 만들면 "같은 것을 두 곳에 적는" 반복 함정.
최근 채택 — §4 배지 "최근 반입" 배지 하나로 충분한 자리를 찾음(위 §4). 별도 "최근" 목록 가지는 새 그룹이 되어 Hick's Law 원칙(그룹 수 최소화)에 반한다.
컨텍스트(지금 범위·🗂) 채택 안 함 범위 표시는 이미 대화창(콘솔)의 몫이다(console.js 범위/scope 상태). 사이드바에 또 두면 "지시는 대화창에서만"·"메뉴는 보기용" 경계가 흐려진다 — 제품이 이미 정한 역할 분리를 존중한다.

7왜 이 안인지 · 무엇을 포기했는지 · 제품 원칙 자가점검

왜 이 길을 골랐나

  • 5단계 재편은 하지 않는다. ①~⑤는 이미 업무 순서=세로 순서로 설계돼 있고(사용자 지시로 "건드리지 말 것"), 서버 workflow.test.ts가 id:"s1-find"~"s5-report" 사이 텍스트를 STAGE_SCREENS와 정확 대조한다. 이 구간에 화면을 끼우면(예: 보안로그분석을 ①의 하위 항목으로) 시험이 즉시 깨진다 — 실제로 코드를 읽고 확인했다(§본문 서두 근거).
  • 대규모 삭제는 하지 않는다. 정찰이 찾은 "삭제 후보 2건"을 직접 대조한 결과 (a)는 이미 숨겨져 있어 지울 대상이 없고, (b)는 진짜 흡수(허브 판 병합)가 코드 변경(grouppanels.js+STAGE_SCREENS)을 요구해 "메뉴 재편"의 범위를 넘는다. 껍데기 화면 자체가 0건이므로 삭제가 이번 라운드의 답이 아니다.
  • 새 그룹·새 화면을 만들지 않는다. 반입 가시성은 배지로, 이름 충돌은 재명명+그룹 통합으로 풀어 그룹 수(11)를 유지했다 — Hick's Law(그룹이 늘수록 고르는 시간 증가)와 "같은 것을 여러 곳에 적으면 어긋난다"는 이 저장소의 반복 교훈을 함께 지킨다.

포기한 것

  • 보안로그파일분석을 ①발견·수집 허브 판으로 실제 병합하는 안(더 깔끔하지만 서버·시험 변경 필요 — 별도 구현 과제로 인계).
  • 대시보드 "최근 반입" 판(§4 대안 B) — 사이드바 배지로 충분해 보류.
  • 사이드바에 범위(🗂) 컨텍스트 표시 — 콘솔의 몫을 침범하지 않기 위해 채택 안 함.
  • 화면이름카드(datacard.ts:269~288)에 "우리보안제품"·"보안제품비교" 같은 새 대화 별칭 추가 — 서버 코드라 이 시안 범위 밖(구현 시 함께 검토 권장).
