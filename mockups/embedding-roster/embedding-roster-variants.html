임베딩 엔진을 로스터에 편입 — 시안 3종

현재 로스터는 에이전트 6인(오케스트레이터·스캔·분석·리포트·위협인텔·지식해설)입니다. 여기에 임베딩 엔진(bge-m3)을 7번째로 넣되, 성격이 다릅니다 — 대화 상대가 아니라 RAG 검색·문서 인입을 처리하는 엔진입니다. 그 차이를 어떻게 다룰지가 세 시안의 갈림점입니다.
아래 “임베딩 호출 시뮬레이션” 버튼으로 실제 동작 시 반응을 확인하세요.

시안 A — 동등 카드가장 단순

다른 팀원과 완전히 같은 형태로 7번째 카드를 추가합니다. 호출되면 기존 working 상태와 동일하게 파란 테두리·펄스·타이핑 점이 켜집니다. 코드 변경이 가장 적고 시각적으로 통일됩니다.

장점 · 구현·유지보수가 가장 단순하고 로스터가 한눈에 균일합니다.
단점 · 클릭해서 대화하려는 시도가 생깁니다. 임베딩은 대화 상대가 아니라 눌러도 할 게 없습니다.
시안 B — 인프라 구분역할을 정직하게

7번째 자리에 두되 점선 테두리·청록 계열로 팀원과 구분하고 “엔진” 라벨을 답니다. 대화 대상으로 선택되지 않으며, 클릭하면 엔진 상태(모델·포트·처리량)를 보여줍니다.

장점 · 사람(에이전트)과 인프라(엔진)의 차이가 화면에서 바로 읽혀 오해가 없습니다.
단점 · 카드 스타일이 하나 더 늘어 로스터의 균일함이 약간 깨집니다.
시안 C — 실시간 반응 강화동작이 잘 보임

B의 구분에 더해, 호출될 때마다 파형 애니메이션이 뛰고 처리 건수·응답 지연이 카드에 실시간으로 찍힙니다. RAG가 실제로 도는지 대시보드에서 즉시 확인됩니다.

세 시안 모두 동시에 반응합니다
장점 · “지금 검색이 돌고 있다”가 가장 명확합니다. 장애 시(응답 없음)도 바로 눈에 띕니다.
단점 · 요소가 늘어 카드가 조금 복잡해지고, 잦은 호출 시 시선을 끕니다.
