■ 공용 모듈 설계 — viz.js(map-view.js와 같은 방식)
화면은 데이터와 판정 함수를 넘겨주기만 하고, 그리는 일과 클릭 처리는 모듈이 한다. 지도에서 배운 것 그대로 — 화면마다 따로 그리면 숫자가 표와 어긋난다(그 사고를 이미 겪었다).
· viz.bars(el, 구간[], {onPick}) — 심각도·상태 분포. 클릭 → 그 구간만 목록에 남김
· viz.donut(el, 값, 전체, {label}) — 이행률·덮는 범위
· viz.spark(el, 계열[]) — 추세(주간 신규 등)
· viz.grid(el, 항목[], {색}) — 구획 배치도(제품·자산)
· 히트맵·지도는 이미 있는 map-view.js를 그대로 쓴다(중복 제작 안 함)

■ 밀도 명세(칸 낭비 최소화 기준) — 시각화 띠 세로 총합 116px(제목 20 + 그림 74 + 여백 22). 목록 줄은 26px(기준 화면 21~29px 준수). 띠는 접지 않는다 — 첫인상이 목적이라 접으면 뜻이 없다. 대신 화면당 그림 3~4개까지만 — 더 넣으면 그것도 목록이 된다.

■ 지키는 원칙
· 가짜 숫자 금지 — 위 값은 시안용 예시이고, 구현은 화면이 이미 받아 온 실데이터만 쓴다(새 API 없음)
· 메뉴는 보기용 — 그림은 보여 주고 거르기만 한다. 입력칸·설정 폼은 두지 않고, 지시는 대화창
· 클릭은 되돌릴 수 있다 — 필터 띠에 항상 「✕ 해제 — 전체 N건」이 함께 뜬다(막다른 길 금지)
· 목록은 사라지지 않는다 — 그림 아래에 그대로 있다. 표로 값을 확인하던 담당자를 잃지 않는다
· 그림·목록의 숫자는 같은 판정 함수에서 나온다(진짜 취약점 판정 등)

■ 단계 제안 — 1단계 viz.js + 취약점·컴플라이언스·보안제품(목록만이던 곳 중 값어치 큰 셋) · 2단계 위협·SBOM·조치·유지보수 · 3단계 리포트·기록·대시보드 요약 띠. ⚠ 대시보드는 대화 중심이라 성격이 달라 마지막에 따로 논의.
