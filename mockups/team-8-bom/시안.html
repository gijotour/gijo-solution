추천 시안 1개 · 대상: office.html(책상) · railroster.js(레일) · dashboard.html(팀 카드 줄·AGENT_ICON) · agent.html(AI 팀 카드·AGENT_STYLE) · 디자인은 나중, 배치·숫자·아이콘·칩만 확정하는 단계
먼저 밝히는 핵심 발견 — 8번째는 7번째보다 싸다.
office.html의 넓은 창 배치는 2열 그리드(cols=2, row=Math.floor(i/2))다. 7석일 때 이미 마지막 줄(3번째 줄, 0-index row 3)이 1자리만 채운 반쪽 줄이었다 — 7번째 팀원(사서)을 넣을 때 바로 이 반쪽 줄 때문에 방 높이(ROWS)를 18→20으로 늘려야 했다(office.html:193 주석: "7번째 책상이 4번째 줄에 놓이므로 20으로"). 8번째는 그 반쪽 줄의 남은 한 자리를 채울 뿐이다 — row = Math.floor(7/2) = 3, 7번째와 같은 줄. 줄 수가 늘지 않으므로 ROWS·H·미팅룸 경계 어느 것도 다시 손댈 필요가 없다(좁은 창도 마찬가지, 아래 §1에서 계산으로 확인). 이번 시안이 실제로 정해야 하는 것은 딱 넷: ①PALETTE 8번째 색 ②LOOKS 8번째 생김새 ③레일·대시보드 아이콘 ④"맡은 메뉴" 칩 모양.

표준 조사와 우리 규격의 차이 — 왜 32dp를 그대로 안 쓰나

Material Design Chip 컴포넌트의 기본 최소 높이는 32dp다(근거 §조사 3). 이 규격은 "눌러서 선택/삭제하는 액션 칩"을 전제로 한 손가락 터치 타깃 크기다. 우리 "맡은 메뉴" 칩은 누를 수 없는 정보 배지다(정직한 구현 원칙 — 동작 안 하면 동작 안 하는 대로 둔다). 그래서 이미 이 화면(agent.html specialtyHtml()·agent-spec 클래스, :332-341)에 있는 관행값 높이 20px·글자 12px을 그대로 물려받았다 — 새 규격을 지어내지 않고 "같은 화면 안의 같은 성격의 줄"을 그대로 베꼈다. 최소 글자 크기는 agent.html 자체 주석의 규칙(":129 ⚠ 글자 11px 미만 금지")을 지켜 11.5px로 잡았다.

왜 이 안인가 / 무엇을 포기했나

왜 — 기존 배치 공식(deskAt)이 이미 "몇 명이든 되는" 일반식이라, 8번째 팀원 1명을 더하는 비용이 우연히 0에 가깝다(같은 반쪽 줄을 채울 뿐 — §1). 이 우연을 그대로 살려 ROWS·미팅룸 경계를 전혀 건드리지 않는 안을 추천안으로 냈다. 아이콘·색은 전부 "이미 있는 관례(sbom.html의 📦, 신원색=칩색 재사용)"를 그대로 연장했지, 새 규칙을 만들지 않았다.

무엇을 포기했나 — ① PALETTE 8번째 색으로 hue 거리상 더 안전한 올리브그린(74°)을 포기하고 골드를 추천했다(BOM의 의미적 연결이 순수 구분성보다 낫다고 판단 — 사용자가 반대하면 올리브가 차선). ② 죽은 AGENT_STYLE 키(sbom·cti·pentest·model-evolution) 정리는 이 시안 범위가 아니라 포기하고 기록만 남겼다. ③ dashboard 팀 카드 줄에 칩을 별도 UI 요소(뱃지)로 새로 만드는 안은 포기했다 — 기존 "역할 텍스트 이어붙이기" 패턴을 재사용하는 편이 새 CSS 없이 되고 밀도 증가도 0이라 더 쌌다. ④ agent.html 카드의 메뉴칩 줄바꿈 여유를 확보하려고 카드 폭을 넓히는 안(그리드 4열→3열)은 이번 요청 범위(칩 하나 붙이기)를 넘어서는 재배치라 포기했다.
