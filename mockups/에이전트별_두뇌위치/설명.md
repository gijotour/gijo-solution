# 시안 — 에이전트별 두뇌·위치

파일: `mockups/에이전트별_두뇌위치/시안.html` (자체완결, 더블클릭으로 열림 — CDN·웹폰트·원격 이미지 0개)

사장님 지시: "에이전트별 원격 선택 시안 잡아줘" — 목적은 "여러 개의 두뇌가 공동작업을 하는 것"을
실제로 화면에서 고를 수 있게 하는 것. 팀원(에이전트)마다 **어떤 두뇌를, 어디서** 쓸지 함께 정한다.

추천 1개 원칙(2026-08-09 결정) 준수 — 대안은 시안 안 "다른 길을 왜 안 골랐나"에 글로만 남기고
화면은 하나다.

## 지금 뭐가 없나 (코드로 확인)

- `server/src/engine/llm.ts:697` `remoteLlmTarget()` — **agentId를 안 받는다.** 원격 GPU는 전역
  on/off뿐이라, 켜면 팀 전원이 원격, 끄면 전원 로컬이다. "총괄은 로컬, 분석은 원격"이 지금 불가능.
- 반면 **로컬은 이미 팀원별로 동작한다** — `server/src/engine/localengine.ts:1078 ensureAgentModel(agentId)`.
  실제로 다른 모델 포트로 간다(껍데기 아님).
- **클라우드는 원격보다 훨씬 더 미구현이다** — `server/src/engine/cloudllm.ts`의 `askCloud`/
  `cloudComplete` 둘 다 agentId를 안 받는다. 실사용처를 찾아보니 `docenrich.ts`의 문서 번역
  하나뿐이었다(대화 아님). 즉 "에이전트별 클라우드 선택"은 지금 **설계 자체가 없다.**

## ① 왜 이 안인가 · 다른 길을 왜 안 골랐나

**채택안** — 로스터 카드마다 위치 pill 3개(💻 이 PC / 🖧 원격 GPU / ☁ 클라우드) + 그 아래 정보
한 줄. pill을 누르면 그 자리에서 결과 문장이 바뀐다("설정 안 됨 — 이 PC로 답합니다" 등).

기각한 길:
- **설정 화면에 별도 표를 만든다** — 로스터와 분리된 새 조작 자리가 생겨 "한눈에 팀 전체가
  보이나"를 못 만족하고, 이 저장소가 줄여 온 조작 표면(18→10)이 다시 늘어난다.
- **위치도 select 하나로** — select는 "이걸 고르면 무슨 일이 생기는지"를 같은 자리에서
  못 보여준다. 결국 지연시간·경고를 위한 별도 줄이 필요해지는데, pill이 "지금 상태(active)"를
  더 잘 보여준다.
- **클라우드를 숨긴다** — 조사 결과 이 6개 역할 에이전트는 전부 사내 데이터를 다루도록 설계돼
  있어 클라우드에 사실상 안 맞는다(아래 ②). 그래도 사장님이 "고를 수 있어야 하는 위치 셋"이라
  명시했고 코드도 실재하므로, **선택은 열어 두되 역할별로 정확히 무엇이 빠지는지 경고로 보여주는
  쪽**을 택했다 — 숨기지 않는다.
- **총괄도 pill로 열어 둔다** — 어댑터 잠금(`agents.ts:138`, "총괄엔 배정 불가 — 라우팅 결정성
  보호")과 같은 선례가 이미 있어, 위치도 같은 자리·같은 모양(잠금 배지)으로 통일했다. 근거:
  총괄은 지시마다 반복적으로 도구 선택 JSON을 호출하는데, 오늘 실측 원격 72B는 답 하나에 90초다
  — 결정 하나하나가 짧고 빈번한 역할엔 크고 느린 두뇌가 안 맞는다(arXiv 2601.04861과 일치).
  ⚠ 이건 이 시안의 **제안**이다 — 하드 락으로 코드에 넣을지 여부는 승인 시 함께 정해야 한다.

## ② 무엇을 포기했나

- 원격 서버가 팀원마다 **다른 크기 모델을 동시에** 제공하는 것 — 안 그렸다. 지금 구조는 원격
  엔드포인트가 하나뿐이라(`remotellm.ts` 설정도 URL 1개) 크기는 팀 전체가 공유한다. "누구를
  원격으로 보낼지"만 팀원별로 다르게 고를 수 있다.
- 클라우드가 실제로 개별 대화에 연결된 것처럼 "동작하는 척" — 안 그렸다. 배너로 미구현임을 명시.
- Pro 등급의 "A/B 비교·검증 병행" — 안 그렸다. `abTest`·`compareModels`·`crossVerify` 0건 확인.
  Pro의 "동시 2개"는 **용량**(스왑 없이 두 로컬 모델 유지)이지 비교 기능이 아니다.
- LoRA 어댑터가 원격/클라우드에도 적용되는 것처럼 — 안 그렸다. 로컬 전용(`agentRequestExtras`).
- 실시간 latency 측정 API 연동 — 안 했다(정적 데모 값). 로컬·클라우드는 실측이 없어 "측정 안
  됨"으로 정직하게 비웠다(잰 것은 오늘 gb10 원격 14B/32B/72B 세 개뿐).
- ⓘ screenguide 실연동 — 서버가 없는 정적 목업이라 화면 안 설명 블록으로 대신했다. 실제
  구현에서는 이 설명 대부분을 screenguide+ⓘ로 옮기고 화면엔 정체성 한 줄만 남겨야 한다.

## 설계 전 조사 (근거)

- CrewAI 공식 문서 "Agents" (https://docs.crewai.com/en/concepts/agents) — 에이전트 객체가 자기
  `llm=`을 직접 갖는 것이 멀티에이전트 프레임워크의 표준. 적용: "역할+두뇌가 한 단위"의 근거.
- LM Studio Bionic 공식 문서 "Choose a Cloud, Local, or Remote Model"
  (https://lmstudio.ai/docs/bionic/models, 2026) — 실제 출시 제품이 로컬/원격/클라우드 3분류를
  그대로 씀. 적용: 이름·분류 그대로 채택. 차이: Bionic의 "원격"은 개인 기기 간(LM Link)이고
  우리는 VPN 안 사내 GPU라 신뢰 경계가 더 강함 — 그래서 "원격도 RAG를 그대로 실어도 된다"는
  판단이 우리 쪽에서만 가능했다.
- arXiv 2601.04861 "Confidence-Aware Routing for Efficient Multi-Agent Collaboration across
  Multi-Scale Models" (https://arxiv.org/pdf/2601.04861) — 역할별 모델 크기·지연 트레이드오프
  근거. 차이: 이 연구는 자동 라우팅을 다루지만, 우리는 폐쇄망·GPU 1~2장 환경이라 사람(관리자)이
  정하는 편이 더 정직하다고 판단했다.
- Nielsen Norman Group "10 Usability Heuristics" #1·#6 (https://www.nngroup.com/articles/ten-usability-heuristics/)
  — 선택과 결과를 같은 자리·같은 순간에. 적용: pill+정보줄 설계.

## ⑤ 구현 시 손댈 자리 (파일:줄)

1. **`server/src/engine/agents.ts`** — `AgentDefinition`에 `assignedLocation` 추가. 99-100행
   `modelKey`/123행 `adapterKey`와 같은 자리에 `locationKey` 추가, `getAgentLocation()`/
   `setAgentLocation()`을 145-154행 `setAgentModel()` 패턴 그대로 복제. 총괄 잠금은 138행
   `setAgentAdapter()`의 `throw` 스타일 그대로.
2. **`server/src/engine/llm.ts:692-699`** — 가장 신경 쓸 자리. `remoteLlmTarget()`은
   `searchrewrite.ts` 등 다른 소비자도 agentId 없이 부른다(주석에 명시). **시그니처를 바꾸지
   말고 호출부에서 먼저 가른다**: `getAgentLocation(agentId)==='remote'`일 때만
   `remoteLlmTarget()`을 부르도록. 이러면 `remotellm.ts`(전역 on/off·에어갭·admin 판정)는 그대로
   재사용되고 다른 소비자엔 영향이 없다.
3. **`server/src/engine/llm.ts`에 클라우드 분기 신설** — 지금 `chat()`은 로컬/원격만 안다.
   `location==='cloud'`일 때는 RAG(`rag` 변수)를 절대 실으면 안 되므로 기존 messages 조립을 타면
   안 된다 — `cloudllm.ts`의 저수준 provider 호출을 새로 export해 별도 경로로 불러야 하고
   `cloudegress.ts` 게이트를 반드시 통과시켜야 한다. **원격보다 변경 범위가 훨씬 크다.**
4. **`server/src/engine/localengine.ts`** — 로컬은 손댈 것 없음(이미 agentId 지원). 다만
   "배정 모델 파일 없음"을 화면이 알 수 있도록 `isModelAvailable()` 결과를 에이전트 목록 응답에
   `modelFileMissing: boolean`으로 얹는 것을 권한다(지금은 1083-1084행 콘솔 경고뿐, 화면 표시 없음
   — 실제로 확인해 보니 select가 아무 옵션도 selected 안 돼 "미배정"처럼 보이는 오해의 소지가 있다).
5. **`client/src/renderer/pages/agent.html`** — `modelSelectHtml()`(316-327행) 옆에 위치 pill
   렌더 함수 추가, `specialtyHtml()`(290-303행)처럼 총괄 잠금 문구 추가, `brainList` 요약
   (456-465행)에 위치·예상응답 컬럼 추가.
6. **`client/src/preload.ts:198`** — `setAgentModel` 옆에 `setAgentLocation` IPC 추가(같은
   패턴 복제) + 서버 라우트 1개 신설.
7. 속도 예상 배지를 실측으로 채우려면 — 서버에 "최근 N회 평균 응답시간(에이전트별)" API가 새로
   필요하다(지금 "성능" 패널은 전역 1개 값만 집계, `agent.html:216-225`).

## 참고 — 시연 컨트롤로 확인 가능한 4가지 오류 상황

시안 상단 "🧪 시연 컨트롤"에서 아래 조합을 직접 만들어 카드 반응을 볼 수 있다:
1. 원격 GPU 미설정/꺼짐 → 위치=원격 눌러도 "설정 안 됨 — 이 PC로 답합니다"
2. 에어갭 켜짐 → 원격·클라우드 전부 "🔒 에어갭 — 이 PC로 답합니다"
3. 로그인 유형=담당자(비-admin) → 로스터 카드 전체가 숨고 "팀 한눈에" 표만 읽기 전용으로 남음
   (실제 코드 `agent.html:697-705 applyAdminGating`과 동일한 동작)
4. "고장 상황 미리보기" 체크 → GIJO Agent의 배정 모델이 파일 없음 상태가 되어 빨간 "파일 없음"
   배지가 뜬다(지금 실제 화면은 이 경우를 조용히 숨긴다 — 이 시안이 고치는 지점)
