담당자가 "오탐 자주 나는 패턴 알려줘"라고 물었을 때 대화창에 뜨는 답 하나입니다. 새 화면이 아니라 기존 콘솔(console.js)의 답변 행에 그대로 얹힙니다. 서버는 finding_approvals에 쌓인 반려(오탐) 기록을 판정 사유별로 묶어 표시만 합니다 — 자동으로 아무것도 제외하지 않습니다.

① 이 시안을 만든 이유(요약) — 자세한 출처는 파일 맨 위 HTML 주석

  1. 화면을 새로 만들지 않았습니다 — 실제 콘솔 답변 마크업과 진짜 마크다운 렌더러로 그렸습니다. 여기 보이는 표·인용구는 "모델이 보낸 텍스트가 그 렌더러를 통과한 결과"입니다.
  2. 절대 제약(자동 제외 금지)을 표보다 먼저, 항상 펼쳐진 문구로 얹었습니다 — 스크롤해도 표를 보기 전에 반드시 지나칩니다.
  3. "N건 확인하러 가기"는 승인 화면을 그 패턴으로 걸러 열 뿐입니다 — 콘솔에 이미 있는 일괄조치 컴포넌트(체크박스+일괄처리)를 일부러 붙이지 않았습니다. 그걸 붙이면 그게 곧 자동 제외이기 때문입니다.
  4. ⚠ 위험 열은 지어낸 걱정이 아닙니다 — 같은 finding이 자산마다 진짜/오탐이 갈리는 문제는 업계 문헌(Maze, 아래 출처)이 정면으로 다루는 실제 사례입니다.
  5. 2회 이상 반복된 것만 "패턴"으로 묶어 보여줍니다(1회성 오탐은 일반화할 근거가 없음) — PortSwigger의 반복 이력 기반 관리 관행을 따랐습니다.

#요구사항이 시안의 처리
1패턴당: 무엇/오탐횟수/자산수/최근판정일/판정자 표 5열(패턴·오탐횟수·자산수·최근판정·판정자) — 6개 패턴, 실사용 규모에 맞춘 예시값(오탐 누적 39건).
2지금 열린 동일 패턴을 골라 확인 (단, 일괄 오탐 처리 버튼 금지) '열린 동일건' 열에 개수 + "N건 확인하러 가기"(내비게이션만). 체크박스·전체선택·일괄처리 없음 — 0건 행은 버튼 자체가 없음.
3위험 신호 — 같은 패턴이 다른 자산에서 실취약점 판정된 적 있으면 ⚠ '위험' 열에 ⚠(호버 시 설명) + 표 아래 근거 목록에 자산명·날짜·담당자까지 명시(숨기지 않음).
4절대 제약 — 자동 제외 금지, 1차는 표시만 카드 최상단, 표보다 먼저 오는 인용구로 항상 노출. 접히지 않음. "표시만" 원칙이 문장으로 그대로 화면에 있음.
5화면 신설 금지 — 조회는 대화창 기존 .cs-row/.cm 마크업과 진짜 gijomd.js 렌더러 재사용. 새 탭·새 메뉴 없음.
6정체성 한 줄 + ⚠경고만(사용법 설명 없음) 제목 줄 1개 + 경고 인용구 1개 외엔 전부 데이터(표·근거 목록)뿐 — "이렇게 쓰세요" 식 안내 문장 없음.
