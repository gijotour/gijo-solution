# 0.자산 시안 — 요약

전체 근거(조사 출처·표·자가점검 표)는 `시안.html` 안(상단 HTML 주석 + 페이지 하단 ①~⑥ 섹션)에 있습니다.
이 파일은 빠르게 훑을 때 쓰는 요약입니다 — 내용을 다시 쓰지 않고 결론만 옮깁니다.

## 무엇을 만들었나
`mockups/자산_0단계/시안.html` — 사이드바 최상단에 새 그룹 **⓪ 자산**, 예시 자산 15건을 고르는 목록,
고른 뒤 나오는 **5단계 진행 현황**(①발견~⑤보고) 카드, 카드를 눌렀을 때 그 자산으로 걸러진 것처럼
보이는 **단계 미리보기**, 그리고 실제 콘솔(console.js)을 흉내 낸 미니 대화창 — 전부 실제로 눌립니다.

## 핵심 결정 3줄
1. **자산은 "단계"가 아니라 "범위 축"이다** — STAGE_SCREENS(1~5)에 6번째로 끼워 넣지 않는다. 절차 띠(workflowrail)도 6칸으로 안 늘린다. 대신 콘솔에 **새 지속 알약**(🗂 지금 범위, 파란색)을 만들어 기존 🎯 지금 다루는 것(주황색, 화면 바뀌면 지워짐)과 확실히 구분한다.
2. **새 파일(가칭 assets.html)로 판다, inventory.html은 안 고친다** — inventory.html은 이미 1,837줄짜리 CRUD 화면이라 "고르기"를 얹으면 더 무거워진다. 데이터는 재사용(listAssets 등)하고 화면만 새로 그린다. inventory.html은 "전체 관리 열기"로만 연결한다.
3. **④검증·⑤보고는 지금 데이터로 자산별 숫자를 못 만든다** — hardening_targets에 assetId가 없고 보고서는 폴더 단위다. 지어내지 않고 진행 현황 카드에 "—"로 비운다(직접 눌러 확인 가능).

## 참고한 표준 근거
- PatternFly *Context Selector* 설계지침(patternfly.org) — "컨텍스트 선택기는 필터와 다르다, 보여줄 데이터셋 자체를 바꾼다" · 애플리케이션 전역 영향이면 마스트헤드에 둔다 → 🗂 알약을 콘솔 상단 고정 자리에 둔 근거.
- Tenable Vulnerability Management *Use the Assets Page*(docs.tenable.com) — 자산을 골라 그 findings로 드릴다운하는 표준 패턴 → 대화창 텍스트 질의가 아니라 표+드릴다운으로 고르게 한 근거.
- Nielsen Norman Group, Progressive Disclosure — 목록 줄엔 최소만, 나머지는 고른 뒤에만 펼친다 → 밀도(34px/행) 근거.
