내 문서함 통합 시안 — 보안제품 자료 + 연락처

사장님 1차 지시: 「보안제품 비교·소개 → 내 문서함에 통합하자」. 작업 도중 2차 지시로 범위가 늘었다: 「라이트 연락처관리도 내 문서에」·「라이트는 내 문서 기능만 일단」·「프로 기능은 하나씩 요청해서 라이트에 맛보기로」. 그 결과 내 문서함이 「내 것들의 집」이 되고 사이드바가 6→8항목이 된다 — 이 시안은 그 8항목을 한 번에 설계하고, 셋 중 하나는 여전히 이름 충돌 문제(§1), 다른 하나는 시각 언어 자체가 다른 문제(§4-4)를 안고 있다.

§1이름 충돌 — 「제품」은 여전히 하나만 바꾸면 풀린다

2026-08-21에 갈라놓은 "제품" 중의성(products.html의 우리 것 ↔ 타사 카탈로그)이 내 문서함 안에서 되살아나는 지점은 여전히 제품 안내 ↔ 보안제품 자료 하나뿐이다. 새로 추가되는 연락처는 nav.js 전체를 grep해도 겹치는 라벨이 0건이라 이름 충돌이 없다(확인함, 상단 주석).

§4결정해야 할 것 — 답

4-1. 비교(2~3개 담기) — 가져간다, 경계 충돌 아니다

productintro 대장에 쓰기 0, 화면 상태(담김 배열)만 바뀐다. 📘 GIJO AS 안내 탭의 [📝 요청 만들기]도 "읽기전용" 탭 안에서 조작이 있는 선례다. [외부2] 최대 3개도 업계 권고 안이라 그대로 승계.

4-2. 사이드바 "보안제품" 그룹(products.html) — 유지, id 무변경

id: "registry"는 그대로 둔다. workflow.test.ts 26-30행이 이 문자열의 존재 만 요구한다(직접 코드 확인) — 항목 수는 무관하다. 1항목 그룹 선례(id:"supplychain") 도 이미 있다.

4-3. 비어 있을 때

intro.html 빈 상태 문구를 1자도 안 바꾸고 승계(§6 After 프레임에서 토글로 확인 가능).

4-4. 연락처 — 매트릭스가 핵심이다, 30px 표로 안 욱여넣는다

lite-contacts.html을 직접 읽은 결론: 이 화면의 존재 이유가 매트릭스다("빈 칸=커버리지 구멍이 한눈에 보인다"). [외부3] Atlassian 히트맵 가이드: 그리드는 표보다 훨씬 빨리 군집·공백 패턴을 읽게 한다 — 74×46px 칸을 30px 행으로 눌러 담으면 이 화면이 있는 이유 자체가 없어진다.

해법 — mydocs.html에 이미 있는 "전폭 목록" 매커니즘(v4content.full, 🎓 학습 탭이 이미 이렇게 목록+문서창 분할 없이 전폭을 쓴다)을 재사용한다. 연락처 탭은 안에 작은 세그먼트([매트릭스]/[담당자 목록]) 하나를 둔다 — 기본값 매트릭스(전폭), 담당자 추가·고치기가 필요할 때만 담당자 목록으로 바꾸면 그때는 다른 탭과 같은 400px 목록+ 문서창 3단(행 30px)으로 돌아온다. 새 CSS 메커니즘을 안 만들고 기존 것 재사용 — §7 구현 참고.

4-5. 연락처의 입력칸·PC 전용 저장 — 그대로 승계, 새 예외 아니다

연락처 편집 폼(이름·전화·이메일·메모)은 자유 입력칸이지만 새로 만드는 예외가 아니다 — lite-contacts.html이 2026-08-16부터 이미 이 형태로 게시돼 있다. "지시는 대화창"은 AI에게 내리는 지시를 막는 원칙이지 개인 주소록 같은 순수 데이터 입력까지 막는 것이 아니다 — 👤 내 것 편집기·📝 요청 만들기와 같은 지위(mydocs.html 기존 예외 목록에 이미 있다).

절대 빠지면 안 되는 문구 — "⚠ 전화·이메일은 개인정보입니다 — 이 PC에만 저장되고 백업·동기화되지 않습니다." 이 문구가 사라지면 사용자가 "이거 서버로 가나?"를 다시 걱정해야 한다. §5·§6에서 1자도 안 바꾸고 그대로 넣었다. 저장 방식도 localStorage 그대로(서버 IPC로 바꾸지 않는다 — 바꾸면 이 문구 자체가 거짓말이 된다).

§5라이트에서는 이렇게 접힌다 — 같은 화면의 두 모습

실제 코드(mydocs.html 1288-1304행)가 이미 하고 있는 일: ?edition=lite면 ["learn","future"]를 숨긴다. 이 시안은 같은 판단 기준으로 신규 항목의 운명을 정한다.

§7무엇을 포기했는지

  • 가로 pill 분류 chips(보안제품 자료) — 접기 그룹머리로 교체, §2와 같은 이유.
  • 연락처의 독립 URL·독립 창 — lite-contacts.html을 직접 열던 진입로가 사라지고 탭 파라미터 경유가 된다(§9 TAB_REDIRECT로 안내는 유지).
  • 매트릭스 축 편집 UI 전체 재현 — §6 시안에서는 테리토리·제품 이름 자체를 바꾸는 입력칸(lite-contacts.html 111-126행 "매트릭스 축" 카드)까지는 재현하지 않았다 — 담당자 CRUD와 매트릭스 보기 두 가지가 이 시안의 핵심 판단(4-4·4-5)이고, 축 이름 편집은 구현 단계에서 그대로 옮기면 되는 부차 기능이라 시안 범위에서 뺐다.

§8제품 원칙 자가점검

  • 추천 시안 1개(2026-08-09 확정 원칙) — 복수 시안 아님
  • 자체완결 HTML — 외부 CDN·폰트·이미지 0, 더블클릭으로 열림
  • 설계 전 조사 — [외부1]·[외부2]·[외부3] 3건, 출처·인용 상단 주석
  • 입력칸 원칙 — 검색칸은 필터 전용. 연락처 편집 폼은 새 예외가 아니라 기존 예외 승계(§4-5)
  • 화면엔 정체성 한 줄+⚠경고만 — 연락처의 "이 PC에만 저장" 경고는 반드시 유지(§4-5)
  • 다크 배경·기존 색 토큰 그대로 — 매트릭스 칸 색은 lite-contacts.html의 rgb 값과 동일(상단 주석에서 대조 확인)
  • 엑셀처럼 촘촘 — 보안제품 자료 행 30px. 매트릭스는 의도적 예외(§4-4, 근거 있음)
