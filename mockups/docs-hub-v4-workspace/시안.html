문서 허브 v4 — 사이드바 워크스페이스 시안

사장님 지시: "문서함을 커서나 노션처럼 만들어주면 안돼?" → 도중 추가 실측 지시: "지금 디자인 방식이 너무 화면을 많이 잡아먹고 있어"(10화면 중 mydocs가 껍데기 26%로 1위). 두 지시를 하나로 묶어 풀었다 — 커서·노션에서 취할 것은 사이드바 트리 구조이지 여백이 아니다. 이 문서 자체가 살아있는 시안이다 — §4의 두 프레임은 실제 치수로 만들었고, 목록까지 닿는 높이를 브라우저가 지금 이 자리에서 직접 잰다.

§1추천 1개 — 무엇을 취하고 무엇을 버렸나

구조는 사이드바 트리(왼쪽) + 목록(가운데, .g-rows 그대로) + 문서창(오른쪽, 보기↔편집 인라인 전환) 3단이다. §4에서 실물로 확인할 수 있다. "커서·노션처럼"의 네 후보를 하나씩 판정했다:

후보판정근거
왼쪽 트리(계층)채택 단, 가짜 폴더가 아니다. §2에서 확인하듯 서버엔 폴더가 없다 — 대신 이미 실재하는 구분(탭 5개·mineseg 개인/공유·회사지식 category·제품안내 group)을 스크롤 안에 끼워 넣던 것에서 사이드바로 재배치했을 뿐이다. 새 데이터 모델 0개. 동시에 이게 §4 밀도 이득의 절반을 낸다(탭줄+mineseg 세로 64px가 사이드바로 넘어가 사라진다). [외부1] Notion 3단 규칙(허브→구획→내용)에 맞춰 2단만 쓴다(내 것→개인/공유, 회사지식→카테고리) — 더 깊이 넣지 않았다.
목록+문서창 동시
(2~3단, 인라인 편집)		채택 지금은 "✏ 고치기"를 누르면 .cols 전체가 숨고 전폭 스테이지가 뜬다 — 목록이 시야에서 완전히 사라져 다른 문서로 옮겨 다닐 때마다 "목록으로" 왕복이 난다. v4는 목록을 항상 켜 둔 채 오른쪽 문서창만 미리보기↔편집으로 바뀐다. [외부3] 216px 레일+320px 목록+가변 상세의 3단 마스터-디테일 관례, [외부2] Cursor의 "사이드바를 접으면 에디터가 폭을 흡수한다" 구조를 함께 반영했다.
백링크·문서 간 연결
·위키링크·그래프뷰		기각 mydocs.html 38행 확정 경계("위키링크·백링크·그래프뷰는 만들지 않는다")를 그대로 지킨다. 이유를 다시 적는다: 개인 문서는 격리가 전부인 화면이다(내 것만 보인다) — "관련 문서" 추천·백링크는 존재 자체를 흘릴 길을 만든다(남의 문서 제목이 내 화면에 링크로 뜨는 순간 격리가 깨진다). 범위 폭증이기도 하다.
슬래시(/) 명령좁혀서 채택 편집기 textarea 안에서 줄 시작에 "/"를 치면 서식 삽입 메뉴(제목·목록·표·구분선)만 뜬다 — §4에서 실제로 눌러 볼 수 있다. 서버·LLM 호출 0개, 텍스트영역 안 로컬 삽입뿐이다. "문서 만들어줘"류 자연어 지시로는 절대 안 커진다 — 메뉴 항목 자체가 고정 서식 삽입만이라 "지시는 대화창에서만" 원칙과 안 부딪힌다(편집기 자유 텍스트는 이미 저작 행위로 예외 — mydocs.html 35행과 같은 지위). "8/20"처럼 줄 중간의 "/"는 트리거하지 않는다(직전 문자가 줄바꿈일 때만).
여러 문서 탭
(커서식 탭 스트립)		기각 app.html이 이미 화면 자체를 탭으로 관리한다(#tabBar/#screens, iframe마다 ?embed=1) — mydocs.html은 그 탭 하나다. 그 안에 또 문서 탭 스트립을 두면 "탭 안의 탭"이 된다. 대신 목록 행 클릭 시 오른쪽 문서창이 즉시 바뀌는 것으로 "여러 문서를 빠르게 오가고 싶다"는 진짜 요구를 충족한다 — 개인 문서는 최대 200건 (MAX_DOCS_PER_USER)이라 동시에 여러 창을 띄워야 할 규모도 아니다.

§2폴더/계층이 서버에 있는가 — 실코드 확인

server/src/engine/personaldocs.ts의 PersonalDoc 인터페이스와 server/src/db.ts의 실제 테이블 정의:

export interface PersonalDoc { id: string; title: string; body: string; ragOptIn: boolean; shared: boolean; createdAt: number; updatedAt: number; } // db.ts:588 CREATE TABLE personal_docs — 위 7개 컬럼뿐. folder·category·parentId·tags 없음. // db.ts:601 shared조차 처음엔 없었고 2026-08-20에 ALTER TABLE로 나중에 추가됐다.

출처: server/src/engine/personaldocs.ts:27-35 · server/src/db.ts:588-601

결론 — 개인 문서에 폴더는 없다. 이번 시안은 그걸 지어내지 않았다. 사이드바의 "내 것" 밑 트리는 실재하는 shared·ragOptIn 두 필드로 만든 2가지 필터(개인만/공유만)일 뿐이다. 회사 지식 밑의 카테고리, 제품 안내 밑의 두 그룹은 서버가 이미 주는 category/group 값이다(mydocs.html:396-399, 413-419에서 이미 클라이언트가 이 값으로 묶고 있었다 — 지금은 목록 스크롤 안 접이식 머리행, v4는 그걸 사이드바로 옮긴 것뿐). 진짜 폴더(담당자가 문서를 자기 마음대로 분류하는 기능)가 필요하면 그건 서버 스키마 변경(새 컬럼+마이그레이션+라우트)이 드는 별도 작업이고, 이번 범위 밖이다. 지금 필요를 물어보면 "폴더"보다 "개인/공유 구분 + 회사 카테고리 열람"으로 대부분 풀린다는 게 이 시안의 판단이다 — 그래도 진짜 폴더가 필요하다면 별도로 요청해 달라.

§7전환 비용 — 오늘 게시한 v3를 또 바꿀 값어치가 있는가

있다고 판단한다 — 단, 범위를 좁혀서. 근거:

  • v3는 오늘(5.51.0) 게시됐다 — 같은 날 두 번 지적이 나왔다(①"커서·노션처럼" ②실측 근거를 동반한 "화면을 너무 많이 잡아먹는다"). 우연이 아니라 실사용 중 느낀 것이다.
  • 10개 화면 실측 비교에서 mydocs가 껍데기 비중 1위(26%)다 — 상대적으로도 나쁘다 (report·threat·audit 23%, approvals·vulnscan·memory 19%, maintenance 17%).
  • 작은 개선(그냥 padding만 줄이기)으로는 이 문제가 안 풀린다 — 탭줄+mineseg 세로 64px는 구조를 바꿔야(사이드바로 이동) 없앨 수 있다. "지금 구조로 충분하다"는 결론은 정직하지 않다.
  • 동시에 재작성이 아니다. personalDocsList/Create/Update/Rag/Share, 업무 템플릿 7종 상수, 비밀정보 스캔 경고, docRequestBuild 요청 만들기, docboxList/Read/Search, learnloop 목록 — 오늘 게시된 "엔진"은 100% 재사용한다. 바뀌는 건 오직 "셸"(탭→사이드바, 전폭 스테이지→인라인 문서창, 제목/부제 제거)이다. 서버·IPC 변경 0개.
결론 — 중간 규모(그리기()·스테이지() 함수 및 CSS 블록 재작성 수준)의 셸 교체다. 로직 재사용 비율이 높아 회귀 위험은 낮지만, "작다"고 말하지는 않는다 — DOM 재배치와 이벤트 재배선이 mydocs.html 전체에 걸친다.

§8제품 원칙 자가점검

  • 추천 시안 1개(2026-08-09 확정 원칙) — 복수 시안 아님, v3 대비 전/후 비교로 대체
  • 자체완결 HTML — 외부 CDN·폰트·이미지 0, 더블클릭으로 열림
  • 설계 전 조사 — [외부1~3] Notion·Cursor·3단 마스터-디테일, 출처·인용 §설계 전 조사 참고
  • 격리 — 내 것 목록은 여전히 personalDocsList(서버가 userId로 가림), 회사 지식·제품 안내는 읽기전용
  • Smart MD 창 격리 — smartmd-preload.ts 무변경, iframe으로 품지 않음, "✍ Smart MD" 버튼은 여전히 별도 창을 여는 자리(시안에서는 열리지 않는다고 라벨에 명시)
  • "지시는 대화창" — 검색칸은 필터 전용(readonly 아닌 v4에서도 그리기만 함), 편집기·요청 폼은 저작 행위로 예외(mydocs.html 35행과 같은 지위)
  • 슬래시 메뉴 — 서버·LLM 호출 0, 텍스트영역 로컬 삽입만(§1 표에서 경계 설명)
  • 11px 미만 금지 — 이 파일 전체 최소 폰트 11px(.g-rows-head, 트리 카운트, 캡션)
  • 한글 표기 — 전부 한글
  • 위키링크·백링크·그래프뷰 확정 경계 — 만들지 않음(§1)
  • 화면엔 정체성 한 줄+⚠경고만 — 제목/부제 걷어내고 경고 문구는 유지(§3)
  • 폴더 지어내지 않기 — 서버 확인 후 "없다"고 정직하게 기술(§2), 새 트리는 실재 필드 재배치
  • 가로 예산 계산 포함(§5) — 사이드바가 가로를 먹는 만큼 목록 열이 잘리지 않는지 확인함

§9이 시안이 안 한 일

  • 실서버 연동 없음 — §4 프레임의 모든 동작은 이 문서 안 상태 전환이다.
  • 저장·다운로드·업로드 실행 없음 — 버튼을 누르면 화면 상태만 바뀌고 실제 파일 입출력은 없다.
  • Smart MD Studio 실행 없음 — 버튼은 있지만 별도 창을 열지 않는다(라벨에 명시).
  • 슬래시 메뉴는 커서 좌표를 정밀 추적하지 않는다 — 편집창 좌상단 고정 위치에 뜬다(실구현에서 정교화할 여지, 이 시안은 "로컬 삽입만 한다"는 경계 증명이 목적).
  • 사이드바 폭 드래그 리사이즈 없음 — 펼침/접힘 두 상태만(다음 라운드 후보).
  • 회사 지식·제품 안내·학습·반입 데이터는 전부 예시다 — 실데이터 아님.
