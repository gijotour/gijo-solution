② 왜 이 안인가 — 다른 길을 왜 안 골랐나

  • 새 화면(cleanup.html 등)을 새로 만들지 않는다 — 이미 admin 게이트로 격리된 이 탭 안에 저장 암호화·제품 구성 같은 같은 위험군 조작이 모여 있다. 새 화면은 nav.js(공용 파일) 등록이 필요해 손댈 범위가 커지고, "관리자만 보는 곳"이라는 이미 있는 격리를 화면 하나로 또 나눈다.
  • 대화창(콘솔) 지시로 실행하게 하지 않는다 — "지시는 대화창에서" 원칙은 조회·분석 같은 업무 지시에 해당한다. 되돌릴 수 없는 파괴적 조작은 자유 문장("리셋해줘")이 아니라 화면에서 보이는 표+타이핑 확인이 사고를 막는 데 낫다(조사 근거 1 — GitLab 패턴도 모달/화면 기반).
  • "부분 정리"만 만들고 "전체 리셋"은 화면에 안 놓지 않는다 — handlers.ts가 이미 "완전히 빼려면 실사용 전환을 해야 한다"고 사람에게 말해 왔다. 부분 정리만 놓으면 그 약속을 화면이 여전히 못 지킨다(재시드 5종은 부분 정리로는 안 막힘).
  • 16개 행마다 개별 "지금 삭제" 버튼을 놓지 않는다 — 실수 기회가 16번으로 늘고, "한 번에 훑어보고 결정" 흐름이 깨진다. 다중 선택 + 단일 실행 버튼으로 묶는다.
  • 1열 표 대신 2열 격자 — 16행을 세로로 쌓으면(≈391px) 이 판 하나가 admin 탭의 절반을 먹는다. 이 파일 자신의 기존 원칙("칸 낭비 줄이기", settings.html:46-49)을 그대로 적용해 8행×2열로 절반 이하로 줄인다.

③ 무엇을 포기했나 (범위 밖으로 뺀 것)

  • 라이브 모드 끄기 버튼 — 서버에 그 API 자체가 없다(라이브모드켬만 있고 대응하는 끔 함수가 없음, grep 0건). 없는 API를 부르는 버튼을 그리면 가짜 UI다. 안 만든다 — 필요한지는 별도 결정 사항.
  • [검토관 [상] 수리] 라이브 모드 "지금 상태" 배지 — 처음 그림엔 접힘 배지·판 제목에 "라이브 모드: 꺼짐"을 찍었으나, 이 값을 HTTP로 내보내는 API가 없다(라이브모드()는 server/src/engine/datacleanup.ts:80-84의 서버 내부 전용 함수 — 호출부 6곳(assets.ts:554,675· cti.ts:233·maintenance.ts:400·securityproducts.ts:532·tasks.ts:255)이 전부 시드 가드고, GET /api/admin/data-cleanup 응답(datacleanup.ts:221-223)은 targets 배열만 준다). 생산자 없는 값이라 뺐다 — 이 배지를 넣으려면 서버 변경이 전제다(예: 그 GET 응답에 liveMode:boolean 칸 추가). 승인 범위에 포함할지는 사장님 결정 사항으로 남긴다 — 이번 시안은 배지 없이 간다.
  • 스냅샷 파일 찾아보기·복구 실행 UI — 상태줄에 파일명만 텍스트로 보여준다(runCleanup이 돌려주는 snapshot 경로). 탐색기 열기·자동 복구는 이 시안 범위 밖(백업 폴더 직접 쓰기 금지 원칙과도 맞닿아 별도 설계가 필요하다).
  • 16종 각각의 상세 설명 3줄씩 — 화면엔 라벨 한 줄 + 건수만. "무엇이 왜 지워지는지"는 ⓘ(screenguide)로 뺀다(제품 원칙 — 화면엔 정체성 한 줄과 경고만).
  • 진행률 바 — 두 POST 모두 동기 응답이라 서버가 진행률을 스트리밍하지 않는다. 화면은 "처리 중…" 한 줄만 두고 가짜 퍼센트를 그리지 않는다.
  • [검토관 [중] 수리] ⓑ안 — 화면 2단 확인(체크 + 단추, 타이핑 없음) — 설계관 정의가 제시한 두 대안 중 하나다(ⓐ 대화창 실행은 "왜 이 안인가" 두 번째 줄에서 이미 기각했다). 이 그림은 사실 둘 다 쓴다는 걸 이번에 다시 확인하고 명시적으로 적는다 — ①골라서 정리는 서버가 confirm 문자열을 요구하지 않아(POST /api/admin/data-cleanup, datacleanup.ts:225-249에 confirm 검사 없음) ⓑ 그대로(체크박스+"선택한 항목 정리" 단추, 타이핑 없음)이고, ②전체 리셋만 서버가 confirm:"RESET"을 요구해(:257-259) ⓑ보다 강한 GitLab 타이핑 패턴을 쓴다. 근거: ①은 재기동+스냅샷으로 되돌릴 길이 남지만(재시드 5종은 사실상 자동 복구) ②는 감사 기록 외엔 되돌릴 길이 없다 — 위험도가 다른 두 조작에 같은 확인 강도를 쓰지 않는다는 뜻을 이 문단에서 처음으로 명시한다 (첫 그림엔 이 대응관계가 그림에만 있고 글로 설명되지 않아 검토관이 "ⓑ 논의가 아예 없다"로 읽었다).

✓ 안내는 ⓘ로(rev.2 — 재검토 [하] 적발 수리): 16종이 각각 무엇인지, 스냅샷이 어디 남는지, 재시드가 무슨 뜻인지는 패널에 안 적었다 — "자세한 것은 ⓘ 를 눌러 확인하세요"(기존 문구 그대로, settings.html:856과 동일 표현) 한 줄로 뺀다. ⚠ 처음 판은 이 약속만 하고 ⓘ가 실제로 무엇을 답할지는 한 글자도 안 적어 뒀었다 — 아래 "⑤-보충 screenguide.ts 초안"에 실제 판 이름·문장을 적었다(구현 시 그대로 옮겨 붙일 초안).
✓ 화면엔 정체성 한 줄 + ⚠경고만: 판 본문 첫 줄이 정체성, 그다음이 경고 박스, 나머지는 표·버튼·감사 고지뿐이다. 설명 산문이 없다.
✓ 자체완결: 외부 CDN·웹폰트·이미지 0, 색 토큰·클래스는 전부 settings.html에서 그대로 복사했다.
✓ 정직한 표기: 동작 안 하는 체크박스·버튼엔 disabled 속성을 실제로 걸었다(정지 화면임을 커서로도 알 수 있게) · 숫자는 전부 "데모값" 표기 · 라이브 모드를 끄는 버튼처럼 없는 API를 부르는 가짜 버튼은 만들지 않았다.
✓ 생산자 없는 값 금지(검토관 [상] 수리): "라이브 모드: 꺼짐" 배지 2곳(접힘 머리·판 제목)을 뺐다 — 그 값을 HTTP로 내보내는 API가 없다(라이브모드()는 서버 내부 전용, datacleanup.ts:80-84). 배지가 필요하면 서버 변경(승인 대상)이 먼저다 — 이 시안은 화면만으로 그 값을 지어내지 않는다.
✓ 라벨 단일 출처(검토관 [하] 수리): 목록 16행의 라벨 3개가 서버 label(cleanupTargets())보다 짧게 적혀 있던 것을 원문 그대로로 되돌렸다 — 화면은 줄여 적지 않는다.
△ 미해결: 이 판의 최종 확정은 사장님 승인 후, 구현 착수 전 gijo-architect가 ①TARGETS/RESET_TARGETS 최신 상태(16개 재확인) ②confirm 문자열 대소문자 정책(현재 서버는 정확히 "RESET" 대문자만 통과) ③감사 로그 화면(audit.html) 쪽에 이 기록이 어떻게 보이는지 ④라이브 모드 상태 배지를 넣을지(넣으려면 GET /api/admin/data-cleanup 응답에 liveMode 칸을 더하는 서버 변경이 전제 — 이 시안은 배지 없이 간다) ⑤①에도 RESET급 타이핑 확인을 요구할지(지금은 ①=체크+단추, ②=RESET 타이핑으로 위험도에 따라 다르게 갔다 — 사장님이 ①도 강하게 원하면 서버 confirm 계약을 ①에도 추가해야 한다) 를 점검·결정해야 한다.
