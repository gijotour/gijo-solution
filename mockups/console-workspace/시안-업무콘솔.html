「내 업무」 화면을 없애고 전부 대화창에서 — 시안

지금은 화면(mywork.html) 하나가 목록·가이드·담기·완료를 전담합니다. 이 시안은 그 화면을 지우고, 같은 일을 대화창(콘솔) 안에서 처음부터 보여주고 고르고 끝내는 구조를 그립니다.
핵심: 화면을 지우지만 그 화면이 쓰던 "결정적 가이드"(workguide.ts)는 그대로 둡니다 — 창구만 옮깁니다.
이 페이지는 결정을 위한 정지 그림입니다. 콘솔 프레임 안의 버튼·입력칸은 자리를 보여주기 위한 그림일 뿐 클릭해도 동작하지 않습니다. "샘플-웹서버"·"김보안"·"이현우" 같은 이름은 예시이며, server/src/engine/tasks.ts의 데모 시드 문구를 최대한 그대로 가져와 썼습니다. 실제 콘솔 구조는 client/src/renderer/pages/console.js를 그대로 옮겼습니다.
① 지금 화면 ★ 사라지면 안 되는 것 ★ 추천 왜 이렇게 콘솔 느낌의 균형 좁은 창(도킹) 넓은 창(패널) 끝내기 3종 ★ 잃는 것 새로 만들 것 영향범위 출처

① 지금 「내 업무」 화면이 하는 일

mywork.html 한 화면이 세 출처(내가 적음·AI가 찾음·자주 하는 업무)를 서버(mywork.ts)에서 합쳐 받아, 지금 이거 1건을 항상 맨 위에 접히지 않게 두고, 나머지는 오늘/이번 주/나중에로 나눠 보여줍니다. 고른 업무에 workguide.ts의 결정적 단계(open·ask·note)가 붙으면 그 순서대로 진행합니다.

★ 추천 (1개)

콘솔 헤더의 "무엇을 할 수 있나" 서랍을 "지금 이거" 줄로 바꾸고, 그 안에서 가이드 카드로 이어간다

대화창을 열면(도킹이든 패널이든) 헤더 바로 아래 줄에 오늘 가장 급한 업무 1건이 타이핑 없이 뜹니다. 눌러 고르면(또는 그대로 두면) 그 업무의 결정적 단계가 같은 대화창 안에 카드로 이어지고, "완료"·"담기"· "재배정"까지 화면을 옮기지 않고 끝냅니다. 지금 서랍이 쓰던 헤더 자리를 그대로 재사용하므로 도킹 190px에서 새 공간을 만들지 않습니다.
  1. 도킹 190px엔 이미 빈자리가 없습니다. 지금도 헤더(맥락칩)+서랍(무엇을 할 수 있나)+입력줄이 이미 114px 안팎을 씁니다(§narrow "자리 다툼" 표). 새 영역을 더하면 대화 표시줄이 1~2줄로 줄어 아예 안 보이는 것과 다름없어집니다 — 그래서 있던 자리의 기본 표시를 바꾸는 절충을 골랐습니다.
  2. LLM을 거치지 않습니다. "오늘 뭐부터?"는 이미 today 도구가 directAnswer:true로 LLM 재작성을 생략하는 선례가 있습니다(agenttools.ts:1988-1998, "결과가 이미 사람이 읽기 좋은 우선순위 목록"). 같은 원리로 pinned 줄은 buildMyWork()을 직접 불러 타이핑 인디케이터도 없이 뜹니다.
  3. 이미 있는 부품을 최대한 재사용합니다. 결재판(attachApproval)·목록체크(attachPicks)·화면열기 (attachOpen)가 이미 있어(console.js:353-560), 새로 만드는 것은 "가이드 진행 카드" 하나와 "오늘 할 일을 자동으로 부르는 훅" 정도로 좁아집니다(§gap에 정직하게 정리).

왜 이렇게 했나 (설명 블록)

  • 화면은 지우되 엔진은 남긴다. "결정적 템플릿, LLM 아님"이라는 원칙(workguide.ts:1-19)은 화면이 아니라 데이터 계층에 있었습니다. 그래서 mywork.html 파일만 지우고 workguide.ts·mywork.ts·tasks.ts는 그대로 두면, 가이드 순서는 여전히 코드가 정하고 AI는 순서를 지어내지 않습니다.
  • 도킹 190px는 이미 꽉 차 있습니다. 그래서 "오늘 할 일"을 위해 새 칸을 만들지 않고, 서랍("무엇을 할 수 있나")의 기본 표시를 pinned 줄로 바꿉니다. 서랍 자체는 없애지 않습니다 — 작은 아이콘(≡)으로 물러날 뿐, 누르면 그대로 열립니다.
  • 노출은 LLM을 거치지 않습니다. 매번 같은 순서로, 대기 없이 뜨는 것이 "곧바로 보인다"는 요구에 맞습니다. GPU 추론 슬롯도 아낍니다.
  • 쓰기는 "누구에게 영향을 주는가"로 나눕니다. 사용자 지시엔 "완료 처리·담기·재배정까지… 쓰기는 결재판을 거친다"고 되어 있지만, 오늘 코드도 이미 이렇게 나뉘어 있습니다 — 개인 체크(완료·담기)는 결재판 없이 즉시 처리되고(mywork.html:522-531, 오늘도 결재판이 없습니다), 실제 조치 실행만 결재판을 거칩니다. 전부 결재판으로 무겁게 만들면 체크박스 하나 누를 때마다 승인 팝업이 뜨는 과잉이 됩니다. 그래서 나에게만 영향(완료·담기)=즉시+되돌리기, 남에게 영향(재배정)=결재판 카드로 나눴습니다(§write에서 상세). 이 경계가 사용자 의도와 다르면 말씀해 주십시오 — 코드를 바로 그렇게 맞추겠습니다.
  • 콘솔 감각은 은유로만 씁니다. 프롬프트 기호·등폭 글꼴은 장식·스캔 보조이지 새로 배울 문법이 아닙니다(§balance). 담당자가 실제로 하는 조작은 지금과 같습니다 — 누르거나 짧게 말하거나.
  • 정직한 한계. 좁은 도킹에서는 "여러 건 훑어보기"가 지금 화면의 표만큼 편하지 않습니다. 넓은 패널에서는 나아지지만 완전히 없어지지는 않습니다 — 대화는 원래 순차적이기 때문입니다(§lose).

콘솔 느낌의 균형 — 터미널 흉내는 내지 않는다

우리 사용자는 보안담당자지 개발자가 아닙니다. "콘솔 느낌"에서 겉모습만 가져오고 조작 방식은 그대로 버튼·목록 중심 대화형 UI로 남깁니다.

가져온 것 (콘솔 감각)

  • 입력줄 앞 옅은 ❯ 프롬프트 기호 — "지금 여기 입력한다"는 신호만
  • 단계 번호·시각·상태값·건수 같은 숫자·코드류에만 등폭(D2Coding 계열)
  • 지시→응답이 줄 단위로 위에서 아래로 쌓이는 로그 감각(이미 console.js 구조)
  • "나 / AI 팀" 같은 짧고 고정폭인 발신자 라벨

안 가져온 것 (어려워지지 않게)

  • 명령어 문법(--flag, 파이프, 이스케이프) 없음 — 전부 자연어 또는 버튼
  • 자동완성·↑ 이력 화살표 없음 — 대신 서랍에서 눌러 채우기
  • 에러가 스택트레이스로 안 뜬다 — "무엇을 못했는지" 한 문장
  • 검은 배경+초록 글자(terminal.html의 실제 장비 CLI 배색)를 안 씀 — 위험한 명령창과 헷갈리지 않게 제품 기본 다크팔레트(파랑 계열) 그대로
근거: Naver D2 Coding 폰트 공식 저장소 — "한글 음절은 라틴 글자의 정확히 2배 폭"이라 등폭이 성립하지만, Consolas는 한글 자모가 아예 없어 한글 문장 전체에 걸어도 자동으로 다음 글꼴로 넘어가 실제 효과가 없습니다. 그래서 등폭은 숫자·라벨에만 쓰고, 사람이 읽는 문장은 계속 Pretendard입니다.

★ 잃는 것 — 화면이 없어지면 못 하는 것 (정직하게)

  • 여러 건 한눈에 훑어보기. 지금 화면은 46건도 스크롤 한 번으로 쭉 훑을 수 있는 표입니다. 대화는 순차적이라 카드가 위에서 아래로 쌓이고, 좁은 도킹(190px)에서는 한 번에 1~2건만 보입니다. 넓은 패널도 나아지지만 표만큼 한눈에 들어오진 않습니다.
  • 표 정렬(담당자순·기한순 클릭 정렬). 서버가 정한 순서(기한초과→우선순위→기한)만 나옵니다. "담당자별로 다시 보고 싶다"는 지금처럼 새로 물어봐야 합니다(예: "이현우 담당 것만 보여줘").
  • 지나간 대화가 그대로 다 보이지 않는다. 콘솔은 최근 40개 turn만 유지하고(CL_MAX, console.js:20) 그 이상은 오래된 것부터 지웁니다. "다 한 일" 목록처럼 계속 남아 있는 이력 화면은 아니라서, 오래된 완료 이력은 서랍 안 접힘 목록으로 다시 불러야 합니다.
  • 답이 길면 자동으로 접힙니다(140자, CLAMP_LEN). 지금 화면은 접지 않고 그대로 보여주는 곳(가이드 설명 등)이 있는데, 콘솔은 순서 안내처럼 full:true로 예외 처리한 것만 안 접힙니다 — 새 카드 유형을 추가할 때마다 이 예외 처리를 잊지 않아야 합니다.
  • "자주 하는 업무" 칩이 한눈에 다 안 보입니다. 지금은 접었다 펴면 5개 칩이 한 화면에 다 있지만, 좁은 도킹에서는 서랍 하위 카테고리 하나로 들어가 클릭이 한 번 더 필요합니다.
