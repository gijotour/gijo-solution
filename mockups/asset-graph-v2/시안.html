6. 왜 이 안인가 — 기각한 3가지

✗ 그래프 라이브러리 신설(D3·Cytoscape 등)

폐쇄망 자체완결 원칙과 정면충돌 — 외부 라이브러리를 동봉하면 라이선스·CVE 추적 대상이 하나 늘고, 지금 지도는 순수 DOM+CSS flex로 이미 잘 돌아간다(map-view.js:16 "폐쇄망 안전 — 외부 라이브러리 없음"). 45개 정도 규모에서 물리 시뮬레이션형 그래프는 과한 기술이고, §5 군집 규칙으로 이미 대응된다.

✗ 전용 화면 신설("자산 그래프.html")

[1]의 핵심과 반대 방향이다 — 그래프는 "고른 자산 하나에서 시작"해야 하는데, 새 화면은 다시 "무엇부터 볼까"를 담당자에게 떠넘긴다. 또 제품 원칙("메뉴는 보기용")과 화면 26개 관리 비용이 하나 더 는다. 지금 있는 지도 탭을 키우는 편이 학습 비용 0이다.

✗ 목록에 "보안장비 보기" 버튼 추가

목록(표)은 이미 자산 45줄로 꽉 차 있다. 버튼을 누르면 결국 또 다른 목록(보안제품 표)으로 튀는데, 그건 지금 products.html이 이미 하고 있다. 이 시안이 값어치를 내는 지점은 "같은 지도 한 장 안에서 자산 옆에 방패가 보이는 것"이지, 화면을 오가며 대조하는 것이 아니다.

✓ 고른 길 — 있는 지도 탭에 방패 타일 + 간선 확신도 표기를 얹는다

새 화면 0개·새 메뉴 0개·새 상호작용 문법 0개(기존 클릭→선택, 기존 .mv-ask→대화창 패턴 재사용). 늘어나는 것은 방패 타일 종류 2개 + 자산 칩 최대 4개 순증(§2, ②는 기존 유지) + 방패 칩 2개(③⑧) + 접기 토글뿐이다.

7. 무엇을 포기했나(정직하게)

  • ③ 시작점 승격(다른 화면·다른 목록 행에서 그래프로 "새로" 진입하는 길)은 다음 단계로 미룬다. — 여기서 미루는 것은 새 진입로를 만드는 일이지, "기존 지도 탭이 어느 화면에서 자동으로 함께 커지는가"가 아니다. 후자는 이번 범위이고 이미 벌어진다 — inventory.html과 vulnscan.html이 map-view.js를 공유해서 한쪽을 고치면 다른 쪽도 같이 바뀐다(§11 영향범위). 그래서 lede·§0[1]도 "둘 다 범위"로 고쳐 적었다 — 미루는 것과 이미 일어나는 것을 한 줄로 뭉뚱그리면 안 된다는 검토관 [하] 지적을 반영한다.
  • 관제 모드(실시간 갱신·경보 배너와 그래프 결합)는 다음 단계. — 이번은 정적 스냅샷(버튼 눌러야 새로 계산)이다.
  • 하드닝 대상 → 특정 자산 선은 안 긋는다(§3에서 이유). 필요하면 사람이 직접 물어 확인하게 한다.
  • 방패 타일의 최종 각도·여백은 육안 조정이 필요하다. clip-path 오각형은 폰트·글자 길이에 따라 텍스트가 아슬아슬할 수 있어 구현 때 실제 이름 길이로 재확인해야 한다.
  • 하드닝 방패의 준수율 색(양호/보통/위험/미점검)은 이번 데모에 안 넣었다. 실제로 하려면 /api/hardening/runs에서 최근 lastRate를 끌어와야 하는데, 이번 시안 범위(지도 레이아웃)를 넘는 API 연동이라 다음 라운드로 미룬다 — 지금은 방패에 standard만 표기한다.
  • 군집 타일의 "고/중/저" 세부 분해는 근사치다. 정확한 경계값(예: 40 vs 50)은 구현 때 담당자 화면 크기 실측으로 다시 정해야 한다.
