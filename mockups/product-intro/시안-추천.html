왜 이렇게 했나

  • 왜 "훑기 → 담기 → 비교" 3단인가 — 이 화면의 일은 "무엇이 있나 훑기"와 "고른 몇 개를 나란히 보기"로 성격이 다르다. 칩(거르기)·카드(훑기)·비교 판(대조)을 한 화면에 층으로 쌓아 스크롤 한 번으로 세 동작을 다 마치게 했다 — 새 화면을 열지 않는다.
  • 왜 카드마다 체크박스가 흐리게 꺼져 있나(자료 없는 제품) — ETC-01처럼 반입된 매뉴얼· 소개서가 0건이면 비교할 내용 자체가 없다. 누를 수 있게 두고 담은 뒤 "자료 없음"으로 표시하는 대신, 애초에 못 담게 막아 헛수고를 줄였다(체크박스에 이유를 tooltip으로 남김).
  • 왜 표에 "—"가 실제로 보이나 — 비교표가 실제로 정직하게 동작할 때 어떤 모습인지 결정자가 미리 보게 하려고, 데모 값 자체를 일부러 비대칭(FW-01은 도입형태·자산연결 있음, EDR-01은 없음)으로 잡았다. "전부 다 채워진 예쁜 표"만 보여주면 실제 반입 자료가 빈약할 때의 화면을 상상하기 어렵다.
  • 왜 3개까지인가 — 아래 출처(NN/g)의 권장 상한(4~5개)보다 더 좁혔다. 이 화면의 카드 폭(3열)과 표 열 너비를 생각하면 4개부터는 가로 스크롤이 생겨 "한눈에 대조"라는 목적을 해친다 — 밀도보다 대조 가독성을 우선했다.
  • 카드·표의 제품명·벤더명·숫자는 전부 데모값이다(코드 안에 주석으로 표시). 실제 구현 시 카드 목록은 products.html이 쓰는 listSecurityProductsGrouped()를, 문서 보유 수는 같은 화면의 docs 배열을, "우리 자산 연결"은 assetName을 그대로 재사용한다 — 새 계산식을 만들지 않는다.
  • 이 파일은 정적 그림이다. 스크립트가 없고, 체크박스·칩·"✕ 빼기"를 눌러도 아무 것도 바뀌지 않는다.
