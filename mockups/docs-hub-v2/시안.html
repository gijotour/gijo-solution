개인 메모부터 회사 지식·학습 수집 내역·스캐너 파일까지 — 올리거나 쌓인 것은 모두 여기서 보입니다. 다른 담당자의 「내 것」은 보이지 않습니다.
어디로 올릴까요?
다른 담당자의 「내 것」 문서는 여기 보이지 않습니다 — 서버가 계정별로 가릅니다. 🏢 회사 지식은 열람 등급(공개 O·민감 S·기밀 C)에 따라 실제로 보이는 문서가 달라집니다 — 이 시안은 설명을 위해 세 등급을 함께 보여줍니다.

1. 왜 이 안인지 (탭 4개가 과한가 — 자가반론 포함)

왜 세 부류에 학습을 더했나 — mydocs.html(내 것)·memory.html(회사 지식)은 이미 docs-single-entry에서 한 화면으로 모았다. 그런데 「지식·학습」을 실제로 만드는 재료 중 하나인 learnloop.html의 수집 대화·학습 후보가 빠져 있었다 — 지시("지식 학습 내문서 다 통합")가 명시적으로 가리키는 세 번째 축이다. 회사 지식(RAG, 검색해서 참고)과 학습 (파인튜닝, 모델에 각인)은 memory.html 자신의 안내 문구가 이미 구분하고 있다("📚 그냥 참고만 하면 됨 → RAG가 더 쉬움" vs "🎓 AI가 체화하게 하려면 → 학습", memory.html:302-314) — 그 구분을 화면에서도 지운다면 담당자가 "학습 후보에 올린 질문이 지금 당장 검색에도 쓰이나?"를 오해한다. 그래서 합치지 않고 탭을 하나 더 두었다.

자가반론 — 탭 4개(+전체)는 과하지 않은가? 세 가지 대안을 먼저 검토하고 기각했다:

  • △ 대안 A: 학습을 회사 지식 탭에 섞는다 — 기각. 학습 후보는 아직 파일이 아니다(대화에서 뽑은 Q&A 쌍, learnloop.html:393-426). 회사 지식 목록에 섞으면 "이것도 지금 검색에 근거로 쓰이나"로 읽힌다. RAG vs 파인튜닝 차이는 이미 한 번 헷갈린 적이 있어 memory.html이 별도 안내 패널까지 뒀다(memory.html:302-314) — 같은 혼동을 화면에서 되살리지 않는다.
  • △ 대안 B: 반입 원본을 회사 지식에 흡수한다 — 기각(docs-single-entry §2에서 이미 검토·기각한 이유를 승계) — 스캐너 원본은 파싱해서 finding/이벤트로 바뀌는 원료지 사람이 읽는 지식 문서가 아니다.
  • △ 대안 C: 학습은 탭 대신 상단 KPI 숫자로만 보여준다 — 기각. 지시가 "학습 …도 내문서에서" 라고 통합을 명시했고, 이번 과제의 경계 조건도 "수집 내역 열람+학습 재료 훑기까지"를 요구한다 — 숫자만으로는 훑을 수 없다. 훑으려면 목록(행)이 있어야 한다.

결론 — 4부류(+전체 개요)를 유지하되, 대가를 지불하지 않게 만들었다: 4번째 탭을 더해도 새로 배울 상호작용은 없다. 어느 탭이든 같은 부품(.g-rows) · 같은 흐름(왼쪽 클릭→오른쪽 상세)이다. 탭을 하나 더 누르는 비용은 알약 18px짜리 버튼 하나뿐이다 — 화면 구조·조작법을 다시 배우는 비용이 아니다.

부수 효과(설계 도중 발견) — 행이 30px가 되며 조작이 상세 패널로 이동했다. 원래 mydocs.html의 행(약 40px)은 AI포함·공유·⬇·✕ 네 버튼을 행 안에 나란히 뒀다(mydocs.html:99-110). 30px 행엔 그 네 버튼이 못 들어간다 — 그래서 모든 탭에서 조작 버튼을 상세 패널로 옮겼다. 밀도를 올린 만큼 클릭이 한 번 늘 수 있다(행 클릭→상세→버튼)는 뜻이라, 정직하게 적는다. 다만 memory.html이 2026-08-20에 이미 같은 선택을 했다(등급 배지→등급 글자색, 조작은 상세 패널)는 선례가 있어 새로 발명한 방식은 아니다.

2. 무엇을 포기했는지

  • △ docs-single-entry의 📘 제품 도움말 탭을 뺐다 — 이번 지시가 명시한 부류는 내 것·회사 지식·학습·반입 원본 넷이다. docbox.html의 제품 내장 매뉴얼 (guide/policy, docbox.ts:1-58)은 성격이 또 달라(고객이 올린 게 아니라 제품이 담아 온 읽기전용 문서) 이번 라운드에 억지로 끼우지 않았다 — 문서함(창)에 그대로 남는다. 다섯 번째 탭을 다시 붙일지는 별도 결정이 필요하다(§1의 "탭이 과한가" 논쟁을 스스로 더 무겁게 만들 것이므로 이번엔 보류).
  • △ 학습 탭에 승인/거절/학습 시작 버튼을 넣지 않았다 — 과제 경계("보기·올리기는 창구, 위험한 관리는 전용 화면")를 그대로 지켰다. GPU 학습·모델 배포로 이어지는 조작은 learnloop.html에만 남기고, 이 화면은 "🔄 학습 루프 화면 열기" 바로가기 하나만 둔다. HITL(사람 개입 루프) 조사(외부4)도 "훑어보기"와 "파이프라인에 되먹이는 조작"을 별개로 다루라고 말한다 — 그 방향과 맞춘 것이지 능력을 깎은 것이 아니다.
  • △ 회사 지식·학습 탭은 전건을 그리지 않았다 — 배지 숫자(94· 40/22/6/0)는 지시값 그대로지만, 실제 행은 대표 예시 몇 개뿐이다. 진짜 구현에서는 g-rows-scroll이 전건을 담지만(memory.html이 실제로 그렇게 한다), 시안에서 94건·68건을 손으로 다 채우는 것은 밀도를 보여주는 데 필요하지 않다고 판단했다 — 화면 안에도 이 사실을 밝혀 뒀다(§배너, 각 탭 안내줄).
  • △ 완전한 단일 입구는 여전히 포기 — 콘솔 ＋(2026-07-27)는 그대로 둔다. docs-single-entry의 같은 결정을 승계.
  • △ 검색은 필터 전용 — 자유 명령어 없음(지시는 대화창 원칙), 승계.

4. 제품 원칙 자가점검

  • ✓ 격리 원칙 — 「내 것」은 personalDocs 그대로, 남의 문서는 404("그런 문서가 없습니다", personaldocs.ts:126, docs-single-entry 승계). 화면을 합쳐도 서버 격리 계약은 안 바뀐다.
  • ✓ 열람 등급 준수 — 회사 지식 목록의 등급은 memory.html의 gtxt-C/S/O 글자색 관례 그대로 썼다(색 재사용, 새 색 안 만듦). 실제 서버에서는 "내 열람 등급보다 높은 문서는 검색에도 안 걸린다"(memory.html:777)는 계약이 그대로 적용된다 — 이 시안은 설명을 위해 세 등급을 한 목록에 같이 보여줄 뿐, 실제 화면은 서버가 걸러 준 것만 보여줘야 한다(§배너에 명시).
  • ✓ 보기·올리기는 창구, 위험한 관리는 전용 화면 — 학습 탭에 승인·거절·학습 시작 버튼이 아예 없다(가짜 버튼도 안 둠). "🔄 학습 루프 화면 열기" 하나만 있다.
  • ✓ 지시는 대화창 · 새 입력칸 금지 — 유일한 텍스트 칸은 검색 (필터 전용). 목적지 선택도 칩 3개 중 고르는 것뿐(자유 텍스트 아님).
  • △ 화면 설명은 챗봇/ⓘ로 — 탭별 안내줄("다른 담당자의 회사 지식은…" 등)은 이 시안 설명을 위한 장치다. 실제 구현에서는 이 문장들을 화면에 남기지 않고 screenguide 패널 + ⓘ로 옮겨야 한다(CLAUDE.md 원칙) — 시안 단계에서만 예외로 화면에 그렸다.
  • ✓ 자체완결 HTML — 외부 CDN·웹폰트·원격 이미지 없음. 색은 pro-white.css(실제 프로덕션 파일)의 확정 토큰을 그대로 복사했다.
  • ✓ 정직한 구현 — 상단 배너로 동작 범위를 고지했고, 회사 지식·학습 탭이 예시 데이터임을 명시했다. 학습 탭의 "학습 루프 화면 열기"도 눌러도 안 열린다고 배너에 적었다.
  • △ 파일은 ＋ 한 곳으로(2026-07-27) — docs-single-entry와 같은 부분 준수. 최종 판단은 사장님 승인 몫.
