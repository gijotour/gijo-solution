취약점 목록 — 원문 아래 「한글 한 줄 풀이」

대상 화면: client/src/renderer/pages/vulnscan.html — 자산을 클릭하면 열리는 취약점 목록(#vdList). 엔진은 이미 있다(server/src/engine/findingplain.ts의 한줄풀이글(), 규칙 기반·LLM 아님, 못 찾으면 빈 문자열). 지금은 챗봇 답변에만 연결돼 있고 화면엔 아직 안 붙어 있다. 이 시안은 그 연결을 화면에서 어떻게 보여줄지 추천 1개를 제안한다.

한눈에 — 핵심 결정 3줄
  1. 원문 아래 새 줄로 붙인다(원문 뒤에 이어 붙이는 인라인이 아니다) — 배지가 이미 빽빽해서 인라인은 항목마다 줄바꿈이 들쭉날쭉해진다.
  2. 한글 풀이를 못 찾으면(55%) 아무것도 그리지 않는다 — 빈 줄도, 빈 자리도 안 남긴다. 지금 화면과 1px도 다르지 않다.
  3. 항목 한 줄 높이 약 40px → 약 64px(+24px, +60%), 20건 목록 기준 세로 총합 800px → 1,016px(+216px, +27%) — 실측 커버리지 45% 적용.
⚠ 정직한 구현 고지 — 이 파일은 결정을 위한 정지 그림입니다. 아래 화면 재현 안의 배지·칩·검색창·버튼(＋조치 등록, ✕ 닫기 등)은 실제 vulnscan.html 마크업·CSS를 그대로 복사해 모양만 보여줍니다 — 클릭해도 아무 동작도 하지 않습니다. 항목 앞의 작은 회색 번호(①~⑳)는 이 문서에서만 비교를 쉽게 하려고 붙인 것으로, 실제 제품 화면에는 없는(제안하지도 않는) 표식입니다.

결정왜 "원문 아래 새 줄"인가 — 인라인과 비교

검토한 다른 길: 원문 이름 뒤에 이어 붙이는 인라인. 실제 vulnscan.html의 CSS를 그대로 적용해 보면 왜 버렸는지 바로 보인다 — 이 화면은 이미 .vd-item-top 한 줄에 심각도·이름·상태·KEV·오분류경보·EPSS·VPR·조치버튼까지 최대 7종이 다투고 있다.

숫자밀도 — 기존 대비 얼마나 커지나

아래 값은 vulnscan.html에 선언된 CSS 값을 손으로 대입해 계산한 것이다(이 작업 환경엔 브라우저 스크린샷 도구가 없어 실측 대신 계산으로 냈다 — 실제 렌더링은 폰트 힌팅 등으로 ±1~2px 오차가 있을 수 있다). 계산 기준: .vd-item padding 10px×2 + 테두리 1px + 내용줄(font-size 12.5px × line-height 1.5 ≈ 18.75px) ≈ 40px, .vd-plain margin-top 4px + (font-size 12.5px × line-height 1.6 = 정확히 20px) = +24px.

공백한글 못 찾은 항목 — 어떻게 보이나

권장: 안 그린다. 위 20건 목록에서 ③⑤⑥⑩⑪⑭⑮⑯⑰⑲⑳(11건)이 그 예시다 — .vd-plain div 자체를 만들지 않는다 (빈 문자열 → 조건부로 아예 렌더링 안 함, 예: plain ? `<div class="vd-plain">...</div>` : ""). 빈 div를 만들고 CSS로 display:none 하는 방식은 쓰지 않는다 — margin-top 계산이 남거나, 나중에 누가 실수로 보이게 바꾸면 "빈 설명"이 화면에 뜬다. findingplain.ts의 "모르면 모른다"는 원칙을 화면 구현까지 그대로 끌고 가는 것이 이 결정의 핵심이다.

포기한 안왜
종류별 색 구분(실행=빨강, 인증=파랑…)이미 배지 색이 5중(심각도·KEV·오분류경보·EPSS·VPR)이다. 여섯 번째 색 신호를 얹으면 어디를 먼저 봐야 할지 더 헷갈린다. 굵게(강조)는 findingplain.ts 문장 안에 이미 있어 그것으로 충분하다.
원문 옆 인라인 배치위 "❌ 버린 안" 참조 — 배지 7종+버튼과 한 줄에서 다투면 항목마다 줄바꿈이 들쭉날쭉해진다.

항목내용
데이터 전달서버가 finding을 직렬화하는 시점(자산/취약점 목록 API)에 한줄풀이찾기(f.finding_type)?.말을 plain 필드로 실어 보내는 편을 권한다 — 클라이언트가 정규식표를 복제하면 두 곳이 어긋난다(MEMORY "그 값을 누가 넣는가" 원칙과 동일선상).
함수 선택 주의한줄풀이글()은 채팅용이라 앞에 " — " 접두가 붙는다(문장 뒤에 이어 붙이는 용도). 화면 새 줄에는 한줄풀이찾기(f.finding_type)?.말을 직접 쓰거나, 한줄풀이글() 결과에서 선행 " — "를 잘라 쓴다.
굵게 강조 변환말 필드 안의 **강조**는 마크다운이 아니라 리터럴 별표다 — esc() 적용 이후 /\*\*(.+?)\*\*/g → <b>로 바꿔야 화면에 별표가 그대로 안 보인다. (이 시안의 예시 문장은 전부 손으로 이 변환을 적용해 미리 보여줬다.)
렌더 위치renderVdList()의 .vd-item-top 닫는 태그 직후, .vd-ev 앞에 한 줄: plain ? `<div class="vd-plain">→ ${boldify(esc(plain))}</div>` : "".
고쳐짐(fixed) 항목과의 관계추가 CSS 불필요 — .vd-item.is-fixed{opacity:.5}가 이미 전체 항목(자식 포함)에 적용돼 .vd-plain도 자동으로 함께 흐려진다. 취소선은 .vd-name에만 걸려 있어 설명줄엔 안 걸린다(의도상 맞다 — 설명 자체가 "틀렸던 말"은 아니므로).
소스 감시 테스트findingplain.test.ts가 이미 "만들어만 두고 안 부르면 안 된다"는 감시를 agenttools 쪽에 걸어 두고 있다(부른 횟수 ≥2). 같은 방식으로 화면 쪽(vulnscan.html 소스)도 한줄풀이 호출을 감시하는 테스트를 하나 추가할 것을 권한다 — 이 저장소가 반복해 겪은 함정이다.
