「원문 아래 한글 한 줄」을 다른 화면으로 — 4곳 정찰 결과와 확장 시안

vulnscan.html에 이미 있는 .vd-plain(원문 아래 회색 한 줄, 근거는 server/src/engine/findingplain.ts)을 다른 화면에도 확장할지 검토했다. 요청에 적힌 후보 4곳 — approvals.html · map-view.js · session-explorer.js · grouppanels.js — 을 전부 Read해서 finding_type이 어디서 오는지 코드로 추적했다. 아래는 그 결과와, 결과에 따라 갈라진 단일 권고안이다(4곳에 똑같이 적용하는 안이 아니다 — 근거가 다르면 결론도 다르다).

한눈에 — 4곳 판정
  1. A. 조치·승인(approvals.html) — 적용. 상세 패널(.dt-title 밑)에만 넣는다. 좁은 목록(.rv-row, 실사용폭 약 220px)엔 안 넣는다 — 실측 예문 3종이 전부 3줄로 wrap된다(아래 증명).
  2. B. 보안 지형도 "먼저 볼 것"(map-view.js) — 적용. 최대 3건 고정이라 목록처럼 스크롤 손실이 없다 — 옆 패널이 조금 더 클 뿐이다.
  3. C. 상태카드(session-explorer.js→sessions.html) — 보류. 코드는 있지만 지금 어떤 화면에서도 도달할 방법이 없다(세션 생성·트리 리프·턴 태그 세 스위치가 전부 꺼져 있음 — 근거는 해당 절). 부활 대비용으로만 함께 제시한다.
  4. D. 그룹 패널(grouppanels.js) — 해당 없음. 이 파일은 finding_type을 그리지 않는다(집계 필터에만 쓴다) — 넣을 자리가 코드에 없다.
⚠ 정직한 구현 고지 — 이 파일은 정지 그림입니다. 아래 화면 재현은 실제 approvals.html·inventory.html(map-view.js)·sessions.html·discover.html의 마크업·CSS를 그대로 복사해 모양만 보여줍니다 — 클릭해도 아무 동작도 하지 않습니다. 코드 인용은 전부 이번 조사에서 직접 읽은 파일·줄번호입니다.

정찰화면별 데이터 경로 — 어디서 finding_type을 받는가

approvals.html server/src/engine/approvals.ts listFindingReviews()가 listAssets()를 순회하며 asset.findings를 그대로 씀 — vulnscan과 동일 경로. 있음(현재 항목) 서버 수정 0줄로 즉시 가능. 단, "재스캔에서 사라진 뒤 이력만 남은 건"은 스냅샷 재구성이라 예외(아래 A절 참고).
