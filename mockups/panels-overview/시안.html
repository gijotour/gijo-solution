2단계 §4. 판이 쓰는 AI 에이전트(지시⑥)

원천: server/src/engine/agents.ts의 실제 로스터 6명(id·이름·역할·약자 그대로) + railroster.js의 기반 부품 4(embed·search·guard·lora, 목적지 page까지 실물). 판↔에이전트 대응은 코드에 명시돼 있지 않다 — agents.ts의 역할 설명 문장이 그 판의 업무를 글자 그대로 가리키는 자리만 배지를 달았다(아래 표 "근거"). 나머지 13판은 배지 없이 미상 — "구현 시 등록부의 도구 담당에서 도출"이라고 적었다(지어내지 않음, 제1 금기).

움직임과 배지를 잇는 안: 판이 "움직였다"고 판정될 때 그 판의 배지도 함께 깜박인다(railroster.js의 llm:event 실신호 — kind:"chat"/"embed"/"search"/"guard" 그대로 구독, 서버 신설 없음). 단, 이건 부품(embed·search·guard)에서만 정확하다 — 팀원 6명의 chat 신호는 agent 이름이 지금 "누가 이 판을 다뤘는지"까지는 안 밝혀서, 배지 깜박임은 "그 종류 일이 방금 있었다" 정도로 읽어야 한다(과장 금지).

3단계 §5. 시나리오 — 행동(행위) 기반 묶음(지시⑧)

5단계 띠가 "일반 절차"라면 시나리오는 "구체 상황의 행동 흐름"이다. 아래 3개는 GIJO_AS_대화시나리오_대장_2026-08-19.md에 실재하는 절 번호·제목 그대로 골랐다(지어내지 않음) — 원문 지시 문장까지 인용.

3단계 §6. 판 없는 화면 — 공백 조사표(지시⑨)

nav.js의 메뉴 트리(TOP 6 + GROUPS 10)와 grouppanels.js의 판(17, 그룹 7)을 실코드로 대조했다. 결론: 판 없는 화면 4개 → 신설 카드 4개. 나머지는 datacard.ts의 카드예외(7개, 코드에 이미 이유가 적혀 있음)이거나 별도 창(page 주소가 없어 판 개념이 안 맞음)이라 신설 대상이 아니다 — 추측이 아니라 실측이다.

신설 카드 4개 — 원천은 이미 서버에 있다(datacard.ts 화면카드가 계산한 걸 그대로 판으로)

4곳 모두 서버 계산 함수가 이미 존재 (assetStatusAnswer·mydocsStatusAnswer·sessionsStatusAnswer·productsStatusAnswer, datacard.ts) — 새 API를 만들 필요 없이 판의 load()가 window.gijo.screenCard(page) (preload.ts 244행, 이미 있음)를 불러 dataCard.kpis를 segments로 바꿔 그리면 된다. "코드는 있는데 카드가 없다"의 가장 정직한 뜻 — 계산도, 대화 소환도 이미 있고, 그룹 허브 그리드 타일만 없다.

카드예외 7개 — 이미 코드가 근거를 적어 둔 제외(신설 대상 아님)

2단계 §7. 🎯 고르기 — 통일 + kind 확장(지시⑩)

pick.html은 지금 kind=vuln|asset 2종뿐이다(계약: 행 클릭=gijo:pickdone 좁은 신호 · 검색=필터 전용 · fields 10키 고정 · "새 API 없이 재사용"). 새 고르기 UI를 만들지 않는다 — 같은 계약을 판마다 이어 붙인다. chatparts.js의 고르기kind 맵(366행, dc.screen.page 기준)과 pick.html의 kind 스위치에 항목을 늘리는 일이다.

§11. 제품 원칙 자가점검

✅지시는 대화창에서만 — 이 시안엔 동작하는 입력칸이 없다. 보기 방식 토글·도메인 칩·판 펼치기는 "지시(쓰기)"가 아니라 "보기 필터"라 예외 성격인데, mydocs.html의 shared/personal 필터에도 이미 같은 성격의 필터가 있어 통과로 본다 — 다만 최종 판단은 사장님 확인.
✅메뉴는 보기용, 새 화면에 입력칸 금지 — 판·타일·시나리오 전부 보기+열기(🗔)+고르기(🎯)만. 쓰기는 전부 pick.html→gijo:pickdone→무대→대화창 지시로 넘어간다.
✅자체완결 HTML — 외부 CDN·웹폰트·원격 이미지 0개. 더블클릭으로 열림.
✅다크톤·색 토큰 — 실제 화면(discover.html 등) :root 값을 그대로 복사.
✅11px 하한 — 본문 최소 11px(t-time·t-ag·g-rows-head), 그 아래로 내려간 글자 없음.
⚠정직한 구현 — 판의 값·엑셀 하위 행·움직임 타이머는 전부 가짜(setInterval 데모)다. AI 에이전트 배지 13개는 "미상"으로 정직하게 비웠다. 🎯/🗔 버튼은 실제로는 pick.html·화면 열기로 이어져야 하는데 이 목업에선 안내 오버레이만 뜬다 — 코드 주석과 본문에 명시.
✅같은 것을 한 곳에만 — §8 코드 통합 제안이 grouppanels.js 단일 출처를 유지한다(대화 홈 스트립·전체 지도·향후 dashboard.html 병존까지 전부 같은 배열을 읽는다).
⚠2026-08-18 결정과의 정합성 — "🖥 자산" 판은 그때 discover 그룹 안에서 빠졌다(요약이 kpi/reporting과 중복돼서). 이 시안이 되살리는 "🗺 자산" 판은 discover 그룹이 아니라 별도 assets0 그룹이고, 원천도 다르다(assetHub, 옛 listAssets 단순 카운트가 아님) — 충돌은 아니라고 판단하지만 최종 확인은 사장님 몫으로 남긴다.
