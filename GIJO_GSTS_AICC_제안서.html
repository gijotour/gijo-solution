근거 없이는 답하지 않는 AI 데이터 HUB
— 완전 온프렘 로컬 LLM 기반 근거답변 검증 PoC

「AICC 지식 구조화 기반 AI 데이터 HUB 및 정합성 검증 PoC」 제안요청서에 대한 기술 제안입니다. 상담 데이터가 단 한 바이트도 외부로 나가지 않는 발주사 내부 GPU(100GB급 VRAM) 구동을 기본으로, 모든 답변에 출처·시행일·버전을 붙이고 확신이 없으면 추정 대신 보류하는 아키텍처를 12주 안에 증명합니다.

사업기간 계약일로부터 12주 대상 취소·반품·교환 SR 상담 (1개 브랜드·1개 상담조직) 구동 발주사 내부 GPU · 완전 온프렘 환경 읽기 전용 격리 PoC
내부 검토용 초안 v0.5 (2026-08-09 제품 문서 대조 갱신) — 실적·가격·인력 절은 확정 후 기재

01제안 요지 — 세 문장으로

이 PoC의 본질은 "챗봇 만들기"가 아니라, AI가 믿고 쓸 수 있는 데이터를 만들고 그 답이 옳음을 증명하는 일입니다.

① 근거가 곧 답변이다

모든 처리 안내에 출처 문서·구간·시행일·버전을 필수 필드로 붙입니다. 근거를 못 찾으면 그 답은 화면에 나가지 않습니다.

② 모르면 멈춘다

필수 정보 누락·기준 충돌·권한 밖 질문은 추정하지 않고 "무엇이 부족한지"를 밝히며 보류합니다. 중대오답 0건은 이 원칙의 결과입니다.

③ 데이터는 집 밖에 안 나간다

답변 모델부터 검색·임베딩까지 전부 발주사 GPU에서 돕니다. 외부 API 학습배제를 "계약으로 약속"하는 게 아니라 통신 자체가 없어서 원천 불가능하게 만듭니다.

이 골격은 제안용 그림이 아니라, 저희가 온프렘 AI 보안관제 제품으로 이미 만들어 매일 운영·자동회귀(야간 147개 고정 상황 시험)로 검증 중인 아키텍처입니다. 로컬 LLM 프로세스 풀, VRAM 예산 관리, 모델별 자동 적응(구동 파라미터 교정)까지 로컬 LLM 운용 자체가 저희 제품의 본업입니다. 본 PoC는 그 검증된 골격에 취소·반품·교환 업무 데이터를 얹는 작업입니다.

02아키텍처 — 쉽게 보기

전체 구조는 다섯 층입니다. 데이터가 위에서 아래로 흐르고, 오른쪽 기둥(감사로그·관측·평가 게이트)이 전 구간을 지켜봅니다.

각 층을 쉽게 말하면

① 원천 데이터: 발주사의 주문·결제·배송·클레임 시스템과 정책 문서를 읽기만 하는 통로로 연결합니다. PoC는 어떤 경우에도 운영계에 쓰지 않습니다(SEC-01).
② 정비·연결: AI가 쓰기 전에 데이터를 "장부 정리"합니다. 빠진 값·중복·코드 불일치를 재고, 고객→주문→클레임을 식별자로 잇고, 정책 문서마다 시행일·버전·예외를 붙입니다. 무엇을 어떻게 고쳤는지 정제 이력이 전부 남습니다(DQR-05).
③ 지식층: 정리된 지식을 세 갈래로 저장합니다 — 버전 붙은 문서 저장소, 예외·우선순위를 규칙으로 갖는 온톨로지(지식 관계망), 의미로 찾는 벡터 색인. 질문이 오면 그 시점에 유효한 버전만 검색됩니다. 과거 기준과 현재 기준이 섞이는 사고(추진배경 2항)를 구조적으로 차단하는 층입니다.
④ 근거답변 엔진: 핵심 차별점입니다. 모델이 답을 만든 뒤 끝이 아니라, 답의 문장 하나하나를 검색된 근거와 대조하는 검증 게이트를 거칩니다. 근거가 확인된 답만 출처·버전과 함께 나가고, 근거 부족·기준 충돌·권한 밖이면 보류 카드로 전환됩니다. 이 층의 모델 4종이 전부 발주사 GPU에 상주합니다(→ 03절).
⑤ 상담지원 화면: 질문·상황요약·처리방향·근거·보류사유를 한 화면에 담고(UXR-01), 근거 원문을 클릭 한 번으로 엽니다(UXR-02). 상담사의 채택·수정·보류 기록이 평가·개선 자료로 되돌아갑니다(FNR-06).

03로컬 LLM 구성 — 100GB VRAM을 어떻게 나누는가

모델 하나가 다 하는 구조가 아니라, 역할별 모델 4종이 한 GPU 예산 안에 분업하는 구조입니다. 저희 제품의 모델 풀 엔진(VRAM 예산 관리·상주/스왑·장애 자동 재기동)이 그대로 이 배치를 운용합니다.

왜 로컬 LLM인가 — 세 가지 이유

  • 학습배제(AQR-09)의 완전한 해결: 외부 API는 "재학습에 안 쓰겠다"는 계약과 증빙이 필요하지만, 로컬 구동은 고객·주문·클레임 데이터가 발주사 밖으로 나가는 통신 자체가 없습니다. 증빙이 가장 간단한 방식은 나갈 길이 없는 방식입니다.
  • 비용이 고정됩니다(AQR-10): 토큰당 과금이 없어 질의량이 늘어도 월 비용이 GPU 전기료 수준으로 고정됩니다. 운영 전환 시 예측 가능한 총소유비용을 제시할 수 있습니다.
  • 3초 목표에 유리합니다(PER-01): 외부 API 왕복(네트워크+대기열) 변동이 사라지고, 지연의 전 구간이 발주사 내부에 있어 저희가 직접 계측·통제할 수 있습니다.

쉽게 말하면: VRAM이 곧 "동시에 깨어 있을 수 있는 두뇌의 크기"입니다. 24GB는 두뇌 하나가 답변·검증을 혼자 겸직하는 수준, 48GB부터 분업이 시작되고, 100GB급이면 답변·검증·검색이 전부 병렬로 깨어 있어 3초 안에 근거까지 확인한 답이 나옵니다. 그 이상은 여유이지 필수가 아닙니다 — 그래서 발주사 보유 100GB급을 "적정"으로 판단합니다.

모델을 못박지 않고, 시험으로 뽑습니다

RFP 4.8항은 특정 모델 고정을 금지하고 교체 가능한 구성을 요구합니다. 저희 엔진은 모델을 교체형 부품으로 다루며(GGUF 표준 형식 + 모델별 구동 파라미터 자동 적응), 채택 절차 자체를 제안합니다:

  • G2(4주차)에서 후보 2~3종 공개 비교: 동일 데이터·검색·프롬프트·평가셋로 주력 후보(Qwen3-Next-80B, gpt-oss-120B 등)를 저희 평가 게이트에 걸어 정확도·근거일치·속도·한국어 품질을 표로 제출하고, 발주사와 함께 채택을 확정합니다(AQR-02와 동일 방법론).
  • 한국어 특화 국산 모델 병행 평가: 한국어 최상위로 평가받는 EXAONE(LG)은 비상업 라이선스라 별도 계약 없이는 기본 구성에 넣지 않습니다(4장 라이선스 공개 원칙). 상업 이용이 자유로운 국산 모델(카카오 카나나 등)은 보조 역할 후보로 병행 평가합니다.
  • 운영 전환 시에도 같은 절차: 더 좋은 모델이 나오면 GGUF 파일 교체 + 회귀 게이트 통과, 두 단계로 끝납니다. 수행사를 다시 부를 일이 아니라 발주사 담당자가 인수받는 운영 절차입니다(OPS-03).
쉽게 말하면: 모델은 "갈아끼우는 엔진"이고, 저희가 파는 것은 엔진이 아니라 어떤 엔진을 꽂아도 근거 없이는 말 못 하게 만드는 차체입니다. 그래서 특정 모델 종속(주요 위험 6항)이 구조적으로 생기지 않습니다.

07보안·개인정보 — 폐쇄형 구동의 이점

  • 격리(SEC-01): PoC 전용 계정·망·저장소, 운영계는 읽기 전용 통로만. 저희 제품은 외부 통신 전면 차단(에어갭) 모드를 제품 기능으로 보유 — 승인된 통로 외 외부 발신을 코드 수준에서 전량 차단하고 차단 이력을 남깁니다.
  • 학습배제(AQR-09): 로컬 구동이므로 모델 제공자에게 전송되는 데이터가 존재하지 않습니다. 증빙은 망 구성도와 외부 통신 차단 로그로 제출합니다.
  • 최소권한(SEC-02): 역할 기반 접근 + 폐쇄망에서 동작하는 2차 인증(TOTP) + 계정당 동시 세션 통제.
  • 암호화(SEC-03): 저장 암호화(AES-256, 선택형) — 암호화 키는 발주사 서버에서 생성·보관되며 공급사는 알지 못합니다. 전송 구간 암호화 병행.
  • 개인정보(SEC-04·DQR-06): 주민등록번호·카드번호는 AI에 닿기 전에 자동 마스킹되고 가린 사실이 기록에 남습니다 — 내장 기능.
  • 로그(SEC-05): 질의·참조·답변·모델 버전·관리행위를 위변조 방지 형태로 기록 — 기록은 끌 수 없고, 보관(기본 3년) 정리조차 기록에 남습니다. 동일 입력·동일 버전 재현(FNR-07) 지원.
  • 공격방어(SEC-06) — 3중 방어: ① 입구 가드레일(입력 속 공격 지시 차단) ② 반입 문서 살균(정책 문서·협력사 산출물에 숨겨진 지시문 무력화 — 상담 지식은 외부 문서가 많아 특히 중요) ③ 출구 가림(자격증명이 리포트·외부로 나가는 것 차단). 자동 레드팀은 구축 기간 내내 상시 회귀 항목입니다.
  • 종료(SEC-08, D-12): 데이터·로그·백업·모델 캐시 완전삭제 및 확인서. 삭제 전 "복구되는 백업인지" 검증하는 자체 절차 보유.

09위험을 숨기지 않습니다

RFP 8.2항의 취지대로, 불확실한 것은 불확실하다고 적습니다.

가장 큰 위험: 기준모델 대비 비열위 95%(AQR-03)입니다.

로컬 오픈 모델은 GPT-5.6-Sol·Claude Opus 5 같은 최상위 상용 모델과 맨몸 성능 격차가 있습니다. 저희 전략은 그 격차를 데이터로 메우는 것입니다 — 정비된 업무 데이터·온톨로지·근거 게이트가 붙은 로컬 구성 대(對) 맨몸 기준모델의 비교이므로, 업무 도메인에선 역전이 실측되는 구간입니다(자사 실측: 그라운딩 강화 > 모델 2배 확대). 단, 이는 증명 대상이지 전제가 아니므로 G2(4주차)에 동일 평가셋 조기 비교를 자청하고, 미달 시 승인된 상용 모델을 대체경로(AQR-08)로 두는 이중화 구성을 함께 제안합니다 — 이 경우에도 근거·보류·감사 골격은 동일하게 적용됩니다.

3초 성능은 "설계 목표"이며 1~2주차 실측으로 확정합니다.

발주사 GPU 기종·장수에 따라 토큰 속도가 달라집니다. MoE 주력 + 구조화 짧은 출력 + 병행 검증으로 설계상 여유가 있으나, 착수 직후 실 GPU 실측으로 예산표를 갱신하고 미달 시 양자화 수준·모델 크기를 조정합니다(모두 회귀 게이트 통과 조건).

커머스 도메인 커넥터(주문·결제·배송)는 본 PoC에서 신규 개발입니다.

다만 당사 제품은 이미 3개 이질 소스를 정규화·상관하는 허브 구조로 운영 중이라, 신규 개발은 파서·매핑 계층에 국한되고 검증·근거·보류 골격은 그대로 재사용됩니다.

정확도 90%는 데이터 품질에 의존합니다.

그래서 G1 관문(데이터 준비상태)이 존재합니다. 핵심 결손이 확인되면 추정으로 메우지 않고 대체안 또는 범위 조정을 서면으로 제안합니다 — 이 원칙 자체가 저희 엔진의 보류 철학과 같습니다.
