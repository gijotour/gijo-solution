# 기계 세 대 · 원격 GPU · 하이브리드 절감 · 인계 흐름 — 지금 사실 (2026-09-02)

기준: 저장소 `D:/Connect AI`(hub/main), 클라 5.83.0(client/package.json:4).
문서에 적힌 값 중 코드와 어긋나는 것은 코드를 진실로 삼고, 어긋난 자리를 표시했다.

## 1. 기계는 `win`·`max`·`gb10` 셋이다

- 기계는 이 세 이름으로만 부르고, "윈도우"·"맥"은 **고객 OS**를 가리킬 때만 쓴다 (CLAUDE.md:35-36). 계기는 "윈도우 클라이언트에서 계정을 만드세요"가 어느 기계인지로 안 읽힌 QA 사고다 (CLAUDE.md:44).
- `win` = Windows PC · VPN `10.8.0.1` · 주 개발 · **운영 서버(WSL 4000)** · **git 허브(`D:\gijo-hub.git`)** · WireGuard 서버 · 클라 게시 (CLAUDE.md:40).
- `max` = M1 Max 32GB(arm64) · VPN `10.8.0.11` · 올인원(서버+Metal LLM) 빌드·검증 (CLAUDE.md:41). 주소는 문서에 오래 `10.8.0.4`로 적혀 있다가 기계에서 재서 정정했다 — **접속 주소는 문서에서 베끼지 말고 기계에서 잰다** (2머신 가이드:60-62).
- `gb10` = NVIDIA GB10 / DGX Spark(aarch64) · VPN `10.8.0.12` · ARM CUDA 실측 (CLAUDE.md:42 · 2머신 가이드:21). ⚠ 같은 줄의 「준비 중(4000·22 닫힘)」은 **낡았다** — 그건 `max`에서 잰 값이고, `win`에서는 `ssh gb10`·`git push gb10 main` 모두 정상이다 (2머신 가이드:41-46 · 교차QA:98-103).
- **작업은 전부 `win` 주도, `max`는 검증**(2026-08-20 결정) — 라이트 에디션 작업도 `win`이 한다 (CLAUDE.md:52-54). 라이트 결함이라도 **뿌리가 공용 파일이면 `win`이 고치고**, `max`는 발견·재현·패치안까지 내고 인계한다 (CLAUDE.md:56).
- `gb10` 하드웨어 성격: 통합메모리 121GB(예산 94GB) · 대역폭 **273GB/s**(3090의 936 대비 3.1배 느림) · dense 32B는 10.6 tok/s (하이브리드 설계서:20-22). 그래서 **값어치는 속도가 아니라 용량이다** (CLAUDE.md:147).
- ⚠ `gb10`은 `nvidia-smi`가 GPU 메모리를 `[N/A]`로 준다(통합메모리·드라이버 차원). 판정은 `server/src/util/unifiedmem.ts` **한 곳**에서만 받는다 (CLAUDE.md:154 · unifiedmem.ts:1-13).
- ⚠ **라이트(전용 VRAM 8~10GB) 측정은 `gb10`에서 하지 않는다** — 통합메모리라 RSS·nvidia-smi 둘 다 틀린 자다. 그 측정은 3090(`win`)이 맡는다 (CLAUDE.md:148).

## 2. 세 대를 잇는 길 — VPN · git · 데이터

- 동기화는 계층마다 수단이 다르다: 코드=git 허브 push/pull, 대용량(models/·data/)=scp **시점 복사**(실시간 동기화 금지), 문서·산출물=구글드라이브 (2머신 가이드:48-53). 구글드라이브로 git repo를 동기화하면 `.git`이 깨진다 (2머신 가이드:51).
- **git 방향이 머신마다 다르다**: `max`는 허브에서 당기고(pull), `gb10`은 `win`이 밀어넣는다(push). `gb10`은 `receive.denyCurrentBranch=updateInstead`라 push만으로 작업트리까지 갱신된다 (CLAUDE.md:141,150-151).
- ⚠ `max`에서 `gb10`으로 직접 밀지 않는다 — 두 곳에서 밀면 작업트리가 엉킨다 (2머신 가이드:23 · CLAUDE.md:151).
- WireGuard 서버는 `win`에 둔다(공인 IP가 거기 있다). **`gb10`으로 옮기는 안은 최종 불가** — 공유기 관리자 권한이 없어 51820/UDP 포워딩을 못 바꾼다 (GB10 구성안:43-44,285-289).
- 피어끼리는 서로 라우팅되지 않는다 — `max`→`gb10`이 안 닿는 것은 **고장이 아니라 설계**다 (교차QA:90-96). `gb10` 피어의 `allowed ips`가 `10.8.0.1/32`(win 한 대)로 좁혀져 있다는 것이 그 실측 근거다 (GB10 구성안:176-186).
- `max`는 자기 VPN 주소(`10.8.0.11:4000`)로는 못 붙는다(utun이 경로를 LOCAL로 잡는다) — 자기 기계는 `localhost:4000`으로 본다 (2머신 가이드:109-110).
- `win`은 ICMP를 막는다 — **ping 실패를 「연결 안 됨」으로 읽지 말 것**(TCP는 된다) (교차QA:105-106). 같은 이유로 터널 생사도 ping으로 판정하지 않는다 — 60초 창의 keepalive·핸드셰이크로 본다 (GB10 구성안:250).
- 공인 IP·peer 공개키는 이 저장소에 적지 않는다(외부 협업자와 공유되는 저장소다). 개인키·PSK는 어떤 경우에도 기록 금지 (GB10 구성안:189-192).
- 비밀은 기계마다 자리가 다르다: `win`=사용자 환경변수 `GIJO_ADMIN_PASSWORD`, `max`=macOS 키체인(`-a gijo-qa`), `gb10`=`~/.gijo-secrets`(chmod 600)에서 `source` (2머신 가이드:133-137). ⚠ `security add-generic-password`에 **`-U`를 기본으로 붙이지 않는다** — 같은 이름 항목을 말없이 덮어써 `jyh` 비밀번호를 날릴 뻔했다 (2머신 가이드:150-151,159-161 · 교차QA:79-80). ⚠ `gb10`의 `~/gijo-env.sh`는 권한 664라 비밀을 넣지 않는다 (2머신 가이드:164-166).
- 비대화형 ssh(`ssh gb10 '<명령>'`)는 `.bashrc`를 안 읽으니 원격 명령마다 `. ~/gijo-env.sh &&`를 붙인다 (CLAUDE.md:152 · 2머신 가이드:168-169).
- **교차 QA는 권한이 일부러 비대칭이다**: `max` 클라 → `win` 운영(4000)은 **읽기만**, `win` 클라 → `max` 개발은 읽기·쓰기 자유 (교차QA:21-27). 운영에 붙을 때는 dispatch·설정 변경·문서 인입 금지, 잰 값에 「`max` 세션이 운영에서 쟀음」을 적는다 (교차QA:29-33).
- 계정은 **서버마다 따로** 만든다(사용자 DB가 기계별) — `claude-qa`·담당자 역할·12자 이상, 만든 직후 열람 등급을 올린다(비면 「공개만」이라 「문서가 잘렸다」로 오보한다) (교차QA:35-55). 세션은 **계정당 1개**라 QA 계정과 사장님 계정을 섞지 않는다 (교차QA:59-61).
- 측정 전 세 줄 확인: ① 재기동했나 ② 어느 서버에 붙어 있나 ③ 잰 건수가 기대와 같은가(0건이면 통과가 아니라 중단) (교차QA:119-126).
- `max` 함정 둘: `npm ci` 하면 Electron 서명이 깨진다(qa-mac.mjs가 잡는다) · 의존성이 바뀌면 받는 쪽은 `npm ci`부터(안 해서 275개 시험 파일이 전부 실패한 적 있다) (2머신 가이드:117-122).

## 3. `gb10`의 일 — ARM CUDA 실측과 자산 점검

- 어디서 재는가의 원칙: **ARM CUDA 빌드·실측(llama.cpp `sm_121a`·네이티브 부품·통합메모리 티어)은 `gb10`에서** — x86 CUDA·Metal에서는 원리상 못 잰다 (CLAUDE.md:114-123).
- llama.cpp 빌드는 `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=121`, `win`과 **같은 판본**으로 맞춰야 실측을 비교할 수 있다 (CLAUDE.md:153).
- ⚠ `npm ci`가 몇 초에 끝나는 npm 11.17+ allow-scripts 함정 — **시간도 파일 존재도 증거가 아니고**, 네이티브 부품은 불러서 기능까지 확인한다 (CLAUDE.md:155).
- **도커로 배포하지 않는다**(2026-08-11 판단) — 재현 검증·다른 CUDA 판본 시험 용도로만 (CLAUDE.md:156).
- 자산 주기 점검은 「관리 접속(VPN)」과 **다른 일**이라 섞지 않는다 — 점검 트래픽은 VPN이 아니라 **자산망 LAN 직결(A안)**로 간다(win이 꺼져도 점검이 계속되고, 고객사 배치와 같은 모양이다) (GB10 구성안:15-24,46-64).
- ⚠ 점검을 켜는 순간 `gb10`에 자산 접속 자격증명이 쌓인다 — 그래서 자산 쪽에 점검 전용 계정 `gijo-audit` + `from=`으로 출처 고정 + 읽기 전용이 필수다 (GB10 구성안:26-28,115-139).
- `gb10`의 WireGuard는 **NetworkManager 네이티브**(`client-GB10`)로 이미 붙어 있다 — `apt install wireguard`·`wg-quick`·키 재생성은 **하면 안 된다**(두 번째 터널이 생겨 충돌) (GB10 구성안:67-88).
- 우리 자산을 우리 제품으로 점검한 기록은 계획서 전-1 시연의 **실데이터**가 된다 (GB10 구성안:155-160).

## 4. 원격 GPU — 붙는 쪽 · 내주는 쪽 (제품 기능)

- 담당자 PC에 큰 GPU가 없어도 사무실·집의 큰 기계에 붙어 14B·32B·72B를 쓴다 — 「등급=기계 크기」가 **「등급=기능, 큰 모델은 원격으로」**가 된다 (원격GPU 사용안내:9-16).
- 두 쪽이 짝이다: **원격 GPU**(붙는 쪽, `remotellm.ts`)와 **원격 GPU 내주기**(받는 쪽, `llmserve.ts`) — 둘 다 기본 꺼짐·admin만 켠다 (원격GPU 사용안내:23-32).
- 절차: 빌려주는 쪽에서 설정 → 연동 → 내주기 켜기 → 주소 복사(`http://10.8.0.12:4000/api/llm/serve/v1`) → 빌려 쓰는 쪽에서 붙여넣고 연결 테스트 → 켜기 (원격GPU 사용안내:42-57).
- 코드가 지키는 경계: **사설·VPN 대역에서 온 요청만**(판정은 `airgap.ts`의 `isVpnRangeIp` 한 곳 — 사설 대역 + CGNAT 100.64/10) · 에어갭이면 켜져 있어도 막음 · 프록시 대상은 로컬 llama뿐(열린 중계기 금지) · **동시 2건**(초과는 HTTP 429) (llmserve.ts:16-22,194,434-435 · airgap.ts:93-99 · remotellm.ts:15-23).
- ★ **접속 토큰이 붙었다(2026-08-16)** — 켤 때 서버가 토큰을 만들어 주소에 실어 주고, 붙는 쪽이 헤더 `x-gijo-serve-token`으로 제시해야 통과한다. 토큰 없는 옛 켜짐은 「꺼짐」으로 막는다 (llmserve.ts:24-27 · remotellm.ts:23-27). 토큰은 URL 일부라 app_state에 **평문** 저장된다(VPN 한정·GPU 접속용·재발급 1회성이라는 근거) (remotellm.ts:23-27).
- 실측(2026-08-14): 제품 대 제품 왕복 **538ms**(win → VPN → gb10 GIJO → gb10 llama), `/v1/models` 114ms, 꺼진 상태 404, 인증 없이 상태 조회 401 (원격GPU 사용안내:18,102-110).
- 연결 테스트 타임아웃의 실사고 원인 둘: ① 내 터널 `AllowedIPs`가 서버 하나(`10.8.0.1/32`)뿐이라 상대 주소가 터널을 안 탄다 ② VPN 서버의 기계 간 중계(포워딩)가 꺼져 있다 (원격GPU 사용안내:71).
- 덧: gb10의 14B가 「KISA」를 「한국인터넷정보센터」로 오답했고 7.8B는 맞혔다 — **모델이 크다고 한국 고유명사를 더 잘 아는 것은 아니다**, 원격으로 큰 모델을 써도 사내 자료(RAG) 근거 방식이 그대로 중요하다 (원격GPU 사용안내:112-114).

## 5. `gb10`으로 Claude 토큰 줄이기 (하이브리드)

- 지시: 「온프레미스 하드웨어와 Claude API를 결합해 개발 생산성을 유지하면서 API 토큰 비용을 극소화」(2026-08-27) — 계획서 항목 밖의 **개발 인프라**다 (하이브리드 설계서:3-4).
- 라우팅의 잣대는 난이도가 아니라 **검증 가능성**이다(기계가 잡을 수 있으면 로컬 완결) — L0 결정적 도구 / L1 로컬 완결 / L2 로컬 발췌 후 Claude 마무리 / L3 Claude 직행 (설계서:11,71-78). **검토관·설계·보안 경계는 Claude 고정**이다(모델을 내리면 「그럴듯한데 틀린 지적」이 늘어 검증이 더 비싸다) (설계서:69 · CLAUDE.md:91).
- 층C 원칙 「선별하되 다시 쓰지 않는다」 — 로컬 모델은 **어느 줄을 보낼지 고르기만** 하고 본문은 기계가 원문을 자른다. 실사고 주석 1,711건이 요약에 뭉개지면 함정을 두 번 밟는다 (설계서:116-122 · local-digest.mjs:10-15).
- 창구는 `tools/local-digest.mjs` 하나: `file`(관련 줄 원문 발췌) · `review`(diff 의심 지점 1차 선별) · `log` · `up`. 전송은 win → `ssh gb10` → localhost(llama-server는 루프백만 열려 WireGuard에 포트를 더 안 연다) (local-digest.mjs:18-26).
- 두뇌는 파일 안 `두뇌들`이 단일 출처(`GIJO_DIGEST_BRAIN`으로 고름): **기본은 2026-09-01부터 Qwen3.8-Flash-Next 125B-A6B(포트 8080, 24.5 tok/s, 제품 node가 직접 관리)**, 빠른 훑기는 `coder30`=Qwen3-Coder-30B-A3B(포트 8082, 67 tok/s) (local-digest.mjs:39-66).
- ⚠ 조각 크기는 **두뇌 정의에서 끌어온다** — 상수 70,000자를 박아 뒀더니 두뇌를 바꾸는 순간 조각이 ctx의 4배가 돼 파일 하나가 통째로 실패했다(2026-09-02) (local-digest.mjs:110-113). ⚠ 자르는 단위는 줄이 아니라 **글자**다(1,500줄이 한글 비율에 따라 1.5배 차이 — 한글 많은 파일만 조용히 실패했다, 비율 1.54자/토큰) (local-digest.mjs:103-108).
- ⚠ 제품이 `--parallel 2`로 띄우면 **슬롯당** 문맥이 32768÷2=16384다(전체 ctx를 적으면 400) (local-digest.mjs:51-53). 프로브는 `--parallel 1`로 띄운다 (hybrid-probe.mjs:17-21).
- 1주차 게이트는 통과했다 — **발췌 20/20 · 생성 69.8 tok/s · 압축 약 45×** (local-digest.mjs:3, 게이트 기준은 설계서:188-196 · hybrid-probe.mjs:1-6).
- 작업 규칙으로 굳은 것 셋: ① **800줄 넘는 파일은 Read 전에 발췌부터**(실측 1,416줄→92줄·25초) ② **Claude 검토관 전에 gb10으로 1차 선별**(로컬 결과는 후보일 뿐, 게시 전·보안 경계는 정식 검토관) ③ **모든 작업 보고에 gb10 이용 내역**(안 썼으면 왜) (CLAUDE.md:27-31,95-96).
- 값어치의 실측 정직: 실결함 30건은 전부 Claude 검토관이 찾았고 gb10 1차 선별 후보 1건은 오탐이었다 — **값은 「결함 찾기」가 아니라 「큰 파일을 싸게 읽기」**다 (CLAUDE.md:31). 만들어 놓고 안 써서 병렬 검토관 18개가 지출 한도로 죽은 사고가 규칙을 CLAUDE.md로 옮긴 계기다 (CLAUDE.md:97).
- 미구현으로 남은 것: 설계서 §6의 ⑵ 야간 층A·층B 생성, ⑶ `routing.json`, ⑷ cloudllm 페이로드 캐싱 — `tools/`에 `routing.json`이 없고 `cloudllm.ts`에 `cache_control`이 없다(2026-09-02 확인) (설계서:177-184).

## 6. 인계 흐름 — 지금은 멈춰 있고 「대기 문서」에 쌓는다

- **Mac 인계는 보류다**(2026-08-22 사장님 지시 「MAC 전달은 한동안 하지 말자, 제품 완성 이후 한번에 전달」) — 보고마다 인계 블록을 붙이지 않는다 (CLAUDE.md:21-25 · MAC 인계 대기:3).
- ⚠ **멈춘다 ≠ 잊는다.** 전달할 것은 `GIJO_AS_MAC_인계_대기.md`에 날짜별로 한 줄씩 쌓고, **공용 파일 변경**과 **max가 실기로 검증해야 할 것**은 빠짐없이 적는다 (CLAUDE.md:22-23 · MAC 인계 대기:5-16).
- `max`에서만 되는 일: 라이트 dmg 빌드·실행 · Metal LLM 동작 · 올인원 검증 (MAC 인계 대기:19-25).
- 재개 시점은 사장님이 「제품 완성」이라 판단하실 때이고, 그때 이 대기 문서로 한 번에 인계한다 (MAC 인계 대기:12).
- 보류를 잠시 연 예외가 한 번 있다 — 2026-09-01 클라 5.82.0 게시분을 hub·gb10에 밀고(`356ebc18`) max에 알렸다 (MAC 인계 대기:325,330). 그 뒤 대기 문서의 마지막 항목은 2026-09-01 분할 GGUF 지원이다 (MAC 인계 대기:380-395).
- `/GIJOAS인계`가 강제하는 것: ① `git add -A` 뒤 **파일 수를 세고** 기대보다 많으면 멈춘다(실사고 1,674파일 397MB가 이력에 들어가 hub 이력을 고쳐 썼다) ② server를 건드렸으면 **WSL에서** 시험(`tools/wsl-test.sh`, win은 `no-hardcoded-credentials`·`shotlist` 둘만 따로) ③ 의존성 변경을 자동 확인해 주의사항에 적는다 ④ **win이 `server/`·`tools/`를 건드렸으면 `git push gb10 main`**, `max`는 gb10에 밀지 않는다 (.claude/commands/GIJOAS인계.md:7-13,14-19,20-25,35-37 · CLAUDE.md:67).
- 라이트 게시가 막혀 있다 — 설치본 1,616MB인데 서버 수신 한계가 500MB(`clientrelease.ts` express.raw)라 세 갈래(스트리밍 업로드·짐 덜기·채널 밖 전달) 중 사장님 판단 대기 (MAC 인계 대기:157-166).

## 7. 예전엔 이랬다 (한 줄씩만)

- 예전엔 **`max`가 라이트 전담**이었다(2026-08-13) — 2026-08-20 「작업은 전부 win」으로 대체 (CLAUDE.md:53).
- 예전엔 **`max`가 제품 코드를 아예 안 만졌다**(2026-08-12, 공용 파일 3중 충돌이 계기) — 지금은 검증이 메인이되 사장님이 직접 시키면 작업한다 (2머신 가이드:25-39 · CLAUDE.md:54).
- 예전엔 **원격 GPU가 무인증**이었다(2026-08-14, 「VPN 안은 신뢰 경계」) — 2026-08-16 토큰으로 닫혔다 (llmserve.ts:24-27).
- 예전엔 **git 허브·VPN 서버를 gb10으로 옮기자**는 안이 있었다 — 공유기 포워딩 권한이 없어 최종 불가로 닫혔다 (GB10 구성안:8,285-289).
- 예전엔 **폰에서 `claude remote-control`로 gb10을 조종**하는 절차서를 썼다(2026-08-11, 미검증) — 지금 실제 통로는 `ssh gb10`과 `local-digest`다 (폰으로 원격작업 가이드:5,9-11 · CLAUDE.md:123).
