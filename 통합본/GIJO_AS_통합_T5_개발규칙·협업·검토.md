## 3. 버전과 게시

- **클라 X.Y.Z가 제품의 공식 버전** — 고객이 보는 유일한 번호 (버전관리_기준.md:3 · CLAUDE.md:19). 실측: `client/package.json:4` = **5.83.0**.
- 라이트는 `client/electron-builder.lite.json`의 독자 semver(Lite 1.0.0부터) — 번호 공간이 섞였던 사고 때문 (버전관리_기준.md:5~11). 실측: 같은 파일 11줄 = **1.4.0**.
- 자리 규칙: major=쓰는 방식이 바뀌는 구조 개편(사용자 결정으로만) / minor=새 기능 / patch=수정, 섞이면 가장 높은 자리 **하나만** 올린다 (버전관리_기준.md:17~23).
- 버전은 **게시 순간에 확정**된다 — 게시 없이 번호만 올리지 않는다 (버전관리_기준.md:24).
- 게시 전 필수 4가지: 서버 시험 전부 통과 · 실화면 검증(자동+육안) · 게시 노트 1~3줄 · 커밋 제목 `클라 X.Y.Z 게시 — <핵심 한 줄>` (버전관리_기준.md:26~31).
- 게시·major 올림은 **사용자 허락 근거를 게시 커밋 메시지에** 남긴다. "기준에 따라"는 근거가 아니다 (CLAUDE.md:20). 실측: 2026-09-02 커밋 29919788 본문 첫 줄이 「사장님 지시(2026-09-02 「전체 진행」…)」로 규칙대로다.
- 서버는 번호를 따로 키우지 않는다 — 추적 단위는 git 커밋 + 스키마 마이그레이션 이름. 클라가 서버 신기능에 의존하면 **서버 먼저 배포 → 클라 게시** (버전관리_기준.md:33~37).
- 게시(클라 빌드)는 `win` 전용 — electron-builder·claude-deploy 계정·실화면 검증이 묶여 있다 (CLAUDE.md:69·72).

- 기계는 `win`·`max`·`gb10` **세 이름으로만** 부른다. "윈도우/맥"은 고객 OS를 가리킬 때만 (CLAUDE.md:35~36 · 2머신_개발환경_가이드.md:11~12).
- 역할: `win`=주개발·운영 WSL 4000·git 허브·WireGuard 서버·게시 / `max`=올인원 빌드·검증 / `gb10`=ARM CUDA 실측 (CLAUDE.md:38~42).
- **작업은 전부 `win` 주도, `max`는 검증**(2026-08-20 사용자 결정으로 「라이트는 max 전담」을 대체). max의 수정·구현은 사장님이 직접 시킬 때만 (CLAUDE.md:52~54).
- 뿌리가 공용 파일이면 라이트에서 발견해도 `win`이 고친다 — 라이트 결함의 뿌리가 공용이던 사례가 반복됐다 (CLAUDE.md:56~57). 실제 적용 예: 한글 조합(IME) 결함은 저장소 전체에 흩어진 같은 패턴 25곳이어서 `win`이 라이트 7파일까지 함께 고쳤다(가드 22곳 추가 · 「조합무관: 이유」 6곳) (인계_win_max_조합가드…:12~18·36).
- Mac 인계는 **멈춰 있다**(2026-08-22 사장님 지시) — 대신 전달할 것을 `GIJO_AS_MAC_인계_대기.md`에 그때그때 쌓는다. 멈춘다 ≠ 잊는다 (CLAUDE.md:21~24).
- 두 사람 협업(사장님↔제임스) 규칙: `main` 직접 push 금지·브랜치+PR 필수, 자기 PR을 자기가 병합하지 않는다 (공동작업_가이드.md:29·43 · CLAUDE.md:75~76).
- PR 본문은 무엇을/왜/어떻게 검증했나(숫자로)/주의(의존성·마이그레이션·공용 파일·시안 승인)를 채운다. 「테스트 통과」만 적지 않는다 (공동작업_가이드.md:70~90).
- 충돌이 잦은 공용 파일 6종 — `nav.js`·`screenguide.ts`·`agentloop.ts`·`routes.ts`·`CLAUDE.md`/`README.md`·`gen-screenshots.mjs`. 손대기 전에 알리고 작게 올려 바로 병합 (공동작업_가이드.md:124~133 · CLAUDE.md:81은 앞의 5종만 적는다).
- 제임스는 운영 서버·운영 데이터에 접근하지 않는다 — 계정당 1세션·직렬 자원·단일 운영 DB 때문 (공동작업_가이드.md:139~145).
- 교차 QA: `max` 클라 → `win` 운영은 **읽기만**, `win` 클라 → `max` 개발은 자유. 권한이 일부러 비대칭이다 (교차QA_방안.md:21~33).
- QA 계정은 서버마다 따로 만든다(`claude-qa`, 담당자 역할). 키체인에 비밀번호를 넣는 것은 계정 만들기가 아니다 (교차QA_방안.md:35~50).
- 측정 전 세 줄 확인: ①재기동했나 ②어느 서버·어느 모델을 겨눴나 ③잰 건수가 기대와 같은가(0건이면 통과가 아니라 중단) (교차QA_방안.md:119~126).
- 접속 가능 여부는 **그 일을 맡은 기계에서** 잰다 — `max`에서 잰 값 하나로 `gb10`을 「닫힘」으로 적었다가 정정한 사고 (교차QA_방안.md:98~103 · 2머신_개발환경_가이드.md:41~46).
- 환경별 역할: 서버 시험은 **WSL**(`bash tools/wsl-test.sh`), 클라 빌드·실화면은 Windows/Mac, ARM CUDA 실측은 GB10. 편집하는 곳에서 재면 딴 환경을 검증하게 된다 (CLAUDE.md:114~128).
- 저장소를 환경별로 나누지 않는다(2026-08-10 검토·기각) — 환경 분기 파일은 188개 중 8개(4%)뿐이다 (CLAUDE.md:129~134).

## 5. 코드 규범 — 정직·단일 출처·감시 시험

- **정직한 구현**: 가짜 UI 금지, 실제 end-to-end 검증. 폴백 문구가 나오면 통과가 아니라 FAIL (CLAUDE.md:13 · 공동작업_가이드.md:90·173 · 디자인·코드검토_안내.md:77).
- 주석에는 「왜」와 **실제 사고**를 적는다 — 재발 방지 장치이므로 리팩터링하며 지우지 않는다 (디자인·코드검토_안내.md:40~48).
- 감시 시험은 걸리면 **시험이 아니라 기능을 고친다** — `guidance-routing`·`no-hardcoded-credentials`·`silentbuttons`·`falseclaim`·`shotlist`·`routes` (README.md:196~203). 소스·문서를 읽는 감시 시험은 33개다 (디자인·코드검토_안내.md:50~58 — 여기엔 앞의 4종만 표로 적혀 있다 · 시험지도.md:323).
- **헛통과 방지**: 감시 시험은 대상을 하나도 못 읽으면 「0건 발견」으로 항상 통과하므로, "대상을 실제로 읽었는가"를 함께 확인한다 — 이 확인을 지우지 않는다 (README.md:205~206 · 시험지도.md:325).
- 순서가 뜻을 갖는 자료구조: `agentloop.ts`의 `FORCED_INTENTS`는 배열 순서가 곧 우선순위라 중간 삽입 뒤엔 `node tools/routes-renumber.mjs --write` (CLAUDE.md:169). 어긋나면 `route-explain.mjs`의 설명이 거짓이 된다 (디자인·코드검토_안내.md:67~70).
- 단일 출처: 화면 설명은 `screenguide.ts` 한 곳, 화면 HTML에 설명을 쓰지 않는다 (디자인·코드검토_안내.md:73~74).
- **지시는 대화창에서** — 새 화면에 자유 입력칸을 두지 않고 `window.gijo.askConsole()`로 넘긴다. 화면이 직접 `/api/dispatch`를 부르면 결재판을 못 그린다 (README.md:146~149 · 공동작업_가이드.md:171~172).
- 한글 조합(IME) 규칙: Enter 판정엔 `&& !e.isComposing`, 아니면 줄 끝에 `// 조합무관: <이유>` — 소스 감시 `imecomposition.test.ts`가 이유 없는 예외를 막는다 (인계_win_max_조합가드…:36~42).
- 「이것들 전부」류 지시는 **말만 보고** 좁힘 여부를 판정한다(자료를 보면 날마다 답이 달라진다). 화면이 보는 목록은 조건이 뜻을 잃었을 때만 대상이 되고 상한 50건, 넘으면 아예 안 쓴다 (인계_win_max_조합가드…:56~57·89~91).
- 시험 오염 주의: `resetAssetsForTests`는 `finding_approvals`를 안 지우므로 새 시험은 `beforeEach`에서 지운다 (인계_win_max_조합가드…:127~130).
- 화면을 없앨 때는 `nav.js TAB_REDIRECT` 필수 · 기능 보존 · screenguide 정리 · QA 기대값 연동 (화면구성_가이드.md:26~29).
- 라이트 같은 별도 에디션은 「빼기」로 만들고, 빼는 방식은 **분기 코드가 아니라 설정(목록)** — 공용 파일에 `if (tier === "lite")`를 심으면 그 파일이 충돌 지점이 된다 (Lite_작업경계.md:12~17).
- 실사고 함정(공통): 한글 검증에 curl 금지(Node fetch), 7B에 프롬프트 규칙으로 행동 교정 금지(코드로 해결) (CLAUDE.md:167~168 · README.md:226~228), 임베딩 llama-server는 ctx/batch/ubatch 8192 명시, 운영 재시작은 전 세션 끊김 (CLAUDE.md:171~172).
