**한 줄 요약**: 침해가 의심되면 **끄지 말고 끊는다**. 전원을 내리는 순간 메모리 증거가
사라지므로 네트워크만 분리하고, 증거를 먼저 확보한 뒤에 분석·복구한다. 개인정보가 섞였는지
가장 먼저 확인한다 — 섞였다면 **72시간**짜리 법정 시계가 그 순간부터 돌기 시작한다.

> ⚠ **이 문서는 법률 자문이 아니다.** 신고 의무 해당 여부·기한 산정·과태료 판단은
> 법무팀과 상의하고, 조문 원문은 국가법령정보센터에서 대조할 것.
> 법은 개정된다 — 아래 「보고·신고」 절의 시행일 표기를 반드시 함께 읽는다.

## 0. 지금 화면 앞이라면 — 최초 10분

순서를 지키는 것 자체가 대응이다. 아래 다섯 줄이 이 문서 전체의 뼈대다.

1. **시각을 적는다.** 이상을 처음 느낀 시각·알아차린 경위. 나중에 로그 타임스탬프와 맞춰 볼
   **기준선**이 된다. 이걸 안 적어서 사고 시각을 못 세우는 일이 실제로 흔하다.
2. **전원을 끄지 않는다. 네트워크만 끊는다.** 랜선을 뽑거나, 원격이면 스위치 포트를 차단한다.
3. **아무것도 지우지 않는다.** 악성 파일 삭제, 백신 자동 치료, 로그 정리, 재부팅, 임시파일
   청소 — 전부 나중이다.
4. **혼자 판단하지 않는다.** 정보보호책임자·내부 대응 체계에 즉시 알린다.
5. **개인정보가 관련되는지부터 본다.** 관련되면 법정 기한이 걸린다(§7).

**초동에서 가장 자주 나는 사고**는 「일단 정리하고 보고하자」다. 정리한 그 몇 분에
원인 규명과 신고 근거가 함께 지워진다.

## 1. 인지 — 무엇을 「신호」로 볼 것인가

침해는 대개 경보로 오지 않고 **어긋남**으로 온다. 담당자가 실제로 처음 마주치는 형태다.

- **밖에서 알려 온다** — 외부 기관·거래처·고객·보안업체 연락, 다크웹 유출 제보.
  자체 탐지보다 외부 통보가 먼저인 경우가 적지 않다.
- **계정이 이상하다** — 심야·휴일 로그인, 해외 IP 로그인, 없던 관리자 계정, 퇴사자 계정 활동.
- **트래픽이 이상하다** — 평소 안 나가던 목적지로의 아웃바운드, 대용량 업로드,
  낯선 포트로의 지속 연결(C2 의심).
- **시스템이 이상하다** — 모르는 서비스·예약작업 등록, 알 수 없는 프로세스, 성능 저하,
  보안 소프트웨어가 꺼져 있음, 로그가 특정 시각부터 비어 있음.
- **파일이 이상하다** — 확장자가 통째로 바뀜(랜섬웨어 → `GIJO_지식_랜섬웨어_대응.md`),
  웹 디렉터리에 없던 스크립트 파일(웹셸 의심), 홈페이지 변조.

⚠ **로그가 사라진 것 자체가 신호다.** 공격자가 흔적을 지운 것일 수 있다.
「로그가 없으니 별일 없었다」는 가장 위험한 결론이다.

## 2. 초기 판단 — 진짜 사고인가

모든 경보가 사고는 아니다. 여기서 걸러야 다음 단계에 자원을 쓸 수 있다.

**사고가 아닐 가능성부터** — 예정된 작업이었나(패치·배포·백업·취약점 스캔·협력사 원격 점검) ·
설정 변경의 부작용인가(정책 수정 직후 차단 폭증은 오탐이 많다) · 그냥 장비 장애인가.
⚠ 「안 되는 것」은 장애, 「당한 것」이 침해다. **장애는 복구 우선, 침해는 증거 보전 우선**이라
순서 자체가 다르다.

**그래도 이 중 하나면 사고로 취급하고 진행한다**

- 권한이 올라간 흔적(관리자 그룹 추가, 새 관리자 계정)
- 인증에 **성공**한 비정상 접속 — 실패가 아니라 성공이 문제다
- 지속성(persistence) 흔적 — 새 서비스·예약작업·시작프로그램·크론 등록
- 데이터가 밖으로 나간 정황 / 로그 삭제·감사 정책 변경 흔적

⚠ **애매하면 사고로 놓고 시작한다.** 아니었던 것으로 판명나는 비용보다, 사고인데 늦게
시작하는 비용이 훨씬 크다. 증거 보전은 되돌릴 수 있지만 지워진 증거는 되돌릴 수 없다.

## 3. 왜 증거 보존이 먼저인가 — 끄면 사라지는 것과 남는 것

복구를 서두르다 증거를 지우면 **원인을 못 밝히고, 같은 경로로 또 당한다.**
그리고 신고·법적 대응·보험 청구에서 근거로 낼 것이 없어진다.

| 전원을 내리면 **사라진다**(휘발성) | 꺼도 **남는다**(비휘발성) |
|---|---|
| 메모리 내용 — 실행 중이던 악성코드 본체(디스크에 파일을 안 남기는 유형이 있다), 복호화된 문자열, 공격자가 쓰던 자격증명 | 디스크의 파일과 삭제 흔적, 로그 파일 |
| 네트워크 상태 — 현재 연결 목록, 어느 프로세스가 어디로 붙어 있었는지, ARP 캐시, 라우팅 표 | 윈도우 레지스트리, 예약작업, 서비스 등록 정보 |
| 프로세스 목록·열린 파일 핸들, 로그인 중인 세션 | 셸 히스토리, 크론 설정, 시작 스크립트 |
| 디스크 암호화(BitLocker 등) 키 — 끄면 잠겨 이후 분석 자체가 어려워질 수 있다 | 이미 다른 서버로 보낸 로그(중앙 로그 서버·SIEM) |

**그래서 휘발성이 큰 것부터 확보한다** — 메모리 → 네트워크·프로세스 상태 → 임시 영역 →
디스크 → 다른 서버의 로그. 이 「휘발성 순서」 개념은 증거 수집 분야의 오래된 표준
문서(IETF RFC 3227)에 정리돼 있다 — 이름만 가리켜 둔다.

**현실적인 최소선** — 전문 포렌식 장비가 없어도 이 정도는 한다:

1. 화면을 사진·캡처로 남긴다(랜섬노트·변조 화면·오류 메시지).
2. 프로세스 목록·네트워크 연결 목록·로그인 세션을 **파일로 저장**한다(화면만 보고 넘기지 않는다).
3. 관련 로그를 **다른 매체로 복사**한다. 원본은 그 자리에 그대로 둔다.
4. 사본의 **해시값(SHA-256)을 계산해 기록**한다 — 「고치지 않았다」를 보일 근거다.
5. 누가·언제·무엇을·어디에 확보했는지 적는다. 이 기록 자체가 증거의 신뢰성을 만든다.

⚠ **감염 장비에서 직접 작업하는 것 자체가 흔적을 덮어쓴다.** 최소한의 명령만 쓰고,
가능하면 외부 매체에 담긴 도구로, 결과는 네트워크가 아닌 외장 매체에 저장한다.

## 4. 격리 — 끄지 말고 끊는다

- **네트워크 분리 우선순위**: 스위치 포트 차단(원격으로 즉시 가능) → 랜선 물리 분리 →
  무선 차단 → 해당 구간 VPN 세션 강제 종료.
- **가상머신이면 스냅샷을 먼저** 뜬 뒤 네트워크 어댑터를 분리한다. 단 **메모리 포함 옵션**으로
  떠야 메모리까지 남는다 — 기본값이 아닐 수 있으니 확인하고 뜬다.
- **계정을 끊는다** — 탈취 의심 계정의 비밀번호를 바꾸고 **활성 세션을 강제 종료**한다.
  비밀번호만 바꾸고 세션을 안 끊으면 공격자는 그대로 붙어 있다.
- **범위를 넓혀 본다** — 같은 계정, 같은 대역, 같은 취약점을 쓰는 다른 자산.
  **한 대만 보고 끝내는 것이 가장 흔한 실수다.**
- **백업 시스템 상태를 확인한다** — 백업까지 손상됐으면 복구 전략 자체가 바뀐다.
- **로그 수집을 끊지 않는다** — 격리해도 중앙 로그 서버 경로는 살려 두거나, 최소한 그 시점까지의
  로그를 먼저 확보한 뒤 끊는다.

## 5. 분석 — 어디를 보는가

「무엇을 결론 내야 하나」가 먼저다: **① 언제 들어왔나 ② 어디로 들어왔나 ③ 무엇을 했나
④ 어디까지 번졌나 ⑤ 무엇이 밖으로 나갔나.** 특히 ⑤가 신고 의무를 가른다.

### 윈도우 — 이벤트 로그

이벤트 뷰어의 **보안(Security)** 로그가 중심이고, 시스템·PowerShell 로그를 함께 본다.

| 볼 것 | 이벤트 ID | 왜 보나 |
|---|---|---|
| 로그온 **성공** | 4624 | 시각·출발지·로그온 유형. 실패보다 **성공**이 더 중요하다 |
| 로그온 실패 | 4625 | 무차별 대입 시도의 흔적 |
| 특수 권한 로그온 | 4672 | 관리자 권한으로 들어온 세션 |
| 계정 생성 | 4720 | 공격자가 만든 계정 |
| 보안 그룹에 멤버 추가 | 4732 등 | 권한 상승 |
| **감사 로그 삭제됨** | 1102 | 흔적 지우기. 이것 하나로 사고 확정에 가깝다 |
| 새 서비스 설치 | 7045 (시스템 로그) | 지속성 확보 |
| 프로세스 생성 | 4688 | 무엇이 실행됐나 (감사 정책이 켜져 있어야 남는다) |
| PowerShell 스크립트 블록 | 4104 (PowerShell/Operational) | 실행된 스크립트 내용 |

함께 볼 곳: 예약작업(Task Scheduler), 시작 프로그램, 레지스트리 자동실행 항목,
`C:\Windows\Temp`·사용자 임시 폴더의 최근 생성 실행파일.

⚠ **감사 정책이 꺼져 있으면 애초에 안 남는다.** 사고를 겪고 나면 4688·4104 같은 항목이
켜져 있는지 반드시 점검 목록에 넣는다.

### 리눅스

| 볼 곳 | 무엇이 있나 |
|---|---|
| `/var/log/auth.log` (데비안·우분투) / `/var/log/secure` (RHEL 계열) | SSH 로그인 성공·실패, `sudo` 사용 |
| `/var/log/wtmp` (`last`) · `/var/log/btmp` (`lastb`) | 로그인 이력 / 실패 이력 |
| `journalctl` · `/var/log/messages` · `/var/log/syslog` | 시스템 전반 |
| `~/.bash_history` | 공격자가 친 명령 (지워졌을 수 있다 — 없는 것도 단서다) |
| `/etc/passwd` · `/etc/shadow` · `/etc/sudoers` | 새 계정·권한 변경 |
| `/etc/crontab` · `/etc/cron.*` · `/var/spool/cron` | 지속성(주기 실행) |
| `/etc/systemd/system` · `/etc/rc.local` | 부팅 시 자동 실행 등록 |
| `/tmp` · `/dev/shm` · 웹 업로드 디렉터리 | 임시로 떨군 파일이 자주 놓이는 자리 |

`stat`으로 파일 시각(수정·접근·변경)을 보되, **시각은 조작될 수 있다**는 전제로 읽는다.

### 웹서버 접근 로그

- **아파치**: `/var/log/apache2/access.log`·`error.log` (RHEL 계열은 `/var/log/httpd/`)
- **엔진엑스**: `/var/log/nginx/access.log`·`error.log`
- **IIS**: `%SystemDrive%\inetpub\logs\LogFiles\` 아래 사이트별 폴더

무엇을 찾나 — 없던 경로로의 요청, 특히 **업로드 디렉터리의 `.jsp`·`.php`·`.aspx`**(웹셸 의심) ·
같은 파일에 대한 반복 POST(웹셸을 조종하는 모양새) · 비정상적으로 긴 쿼리스트링과 SQL·명령어
조각이 섞인 파라미터 · 한 출발지에서 쏟아지는 404 뒤에 나타나는 **200**(스캔 후 성공) ·
낯선 User-Agent, 응답 크기가 유난히 큰 요청(자료 반출 정황).

### 방화벽·보안장비

- **아웃바운드를 먼저 본다.** 밖으로 나가는 낯선 목적지·포트·주기적 접속(C2).
- 차단 로그보다 **허용된 세션**을 본다 — 막힌 건 이미 막힌 것이다.
- **정책 변경 이력**과 관리자 접속 이력. 공격자가 길을 열어 둔 흔적이 여기 남는다.
- VPN 인증 로그 — 계정 탈취의 대표적 진입로다.
- 장비별 로그 필드·명령은 `GIJO_지식_보안장비_로그체계.md`를 함께 본다.

⚠ **시각이 맞아야 대조가 된다.** NTP 동기화가 어긋났거나 각 로그의 표준시간대(UTC/KST)
표기를 안 보면, 9시간 어긋난 채 「알리바이가 성립한다」는 잘못된 결론에 이른다.

## 6. 복구 — 원인을 막고 나서

- **원인을 못 찾은 채 복구하지 않는다.** 같은 문을 열어 둔 채 복원하면 며칠 안에 재발한다.
- **격리된 환경에서 복원**하고, 복원 후 다시 점검한 뒤 연결한다.
- **자격증명을 전면 교체한다** — 감염 장비뿐 아니라 도메인 관리자·서비스 계정·API 키·
  백업 계정까지. 공격자가 이미 가져간 것을 전제로 한다.
- **재설치가 원칙**이다. 「악성 파일만 지웠다」로는 지속성 흔적이 남아 있을 수 있다.
- **백업이 오염되지 않았는지 확인한다** — 침투 추정 시점 **이후**의 백업에는 공격자가
  들어 있을 수 있다. 그보다 **이전** 사본을 고른다.

## 7. 보고·신고 — 기한이 걸린 부분

⚠ **이 절의 숫자는 과태료가 걸린 기한이다.** 「알게 된 때」의 시각 기록(§0-1)이 근거가 된다.

### 7-1. 침해사고 신고 — 정보통신망법 제48조의3

개정법이 **2026-03-31 공포, 2026-09-30 시행 예정**이라 지금은 두 가지를 **병기해서** 봐야 한다.

| 구분 | 현행 (오늘 적용) | 2026-09-30 시행 예정 |
|---|---|---|
| 기한 | **즉시** 신고 | **24시간 이내 최초 신고** → 이후 **후속(보완) 신고**의 2단계 |
| 과태료 | 1천만 원 이하 | **3천만 원 이하** |

⚠ **오늘 사고가 나면 현행 「즉시」가 적용된다.** 시행일 전후를 반드시 확인하고,
경계 시점(2026년 9월 말)에는 어느 쪽이 적용되는지 법무 확인을 받는다.
신고 대상 규모 기준·중복 신고 면제 여부는 이 문서에서 **단정하지 않는다**(⚠ 확인 필요).

### 7-2. 개인정보가 유출됐다면 — 72시간

침해에 개인정보가 섞였다면 **별개의 두 조문**이 동시에 걸린다. 하나만 하면 나머지가 미이행이다.

| 무엇 | 누구에게 | 근거 |
|---|---|---|
| **통지** | **정보주체(당사자) 본인**에게 | 개인정보 보호법 **제34조 제1항** / 시행령 **39조** |
| **신고** | **개인정보보호위원회 또는 KISA**에 | 개인정보 보호법 **제34조 제3항** / 시행령 **40조** |

**신고 대상**은 다음 중 하나에 해당할 때다.

- 정보주체 **1천 명 이상**의 개인정보 유출
- **민감정보 또는 고유식별정보** 유출
- **외부 불법 접근(해킹 등)**에 의한 유출 ← 침해사고는 대개 여기에 걸린다

기한은 **유출을 알게 된 때부터 72시간 이내**다. 예외는 시행령 40조 단서를 확인한다.
조문·요건의 상세는 이 저장소의 `보안규제_법적근거_모음.md` 확정본을 따른다(재조사하지 않는다).

⚠ 자주 틀리는 것: 「24시간」·「5일」·「법 제30조」·「시행령 제16조」는 **개인정보 유출 기한이
아니다.** 개인정보는 **72시간**, 24시간은 위 7-1(정보통신망법, 아직 시행 전)이다. 둘을 섞지 않는다.

### 7-3. 그 밖에

- **내부 보고가 먼저다** — 발견 시각·영향 범위·확산 여부·현재 조치를 **사실만**. 추정과 섞지 않는다.
- **KISA 신고·상담 창구**는 보호나라(boho.or.kr)에서 확인. **경찰(사이버수사)** 신고도 가능하다.
  ⚠ 양쪽 다 정확한 접수 경로·전화번호(118 등)는 바뀔 수 있어 **확인 필요** — 사고 시점에 재확인.
- **거래처·고객 통지**: 계약상 통지 의무가 있는지 법무팀과 확인한다.
- **금융권 등 업권별 보고 의무**가 따로 있을 수 있다. 근거 규정의 조번호는 이 문서에서
  단정하지 않는다(⚠ 확인 필요 — 소관 감독기관 규정을 직접 확인).

## 8. 재발 방지 — 여기까지가 대응이다

- **침투 경로를 문장으로 적는다.** 「○월 ○일 ○시, △△ 계정이 □□ 경로로 탈취되어…」로 쓸 수
  있어야 원인을 특정한 것이다. 못 쓰면 아직 분석이 안 끝났다.
- **그 경로를 막는다** — 패치, 노출 포트 차단, MFA 적용, 권한 축소.
- **탐지 공백을 메운다** — 「로그가 없어서 못 봤다」 한 지점이 다음 사고의 사각지대다. 감사
  정책·로그 보존 기간·중앙 수집 여부를 조정한다.
- **재발 감시** — 같은 출발지·같은 수법의 재시도를 최소 2주 이상 감시 목록에 올린다.
- **보고서를 남긴다** — 시간순 경과·원인·조치·남은 위험·재발 방지책. 다음 정기점검에서 그
  항목이 실제로 닫혔는지 확인한다(`GIJO_지식_보안장비_유지보수절차.md`와 같은 원리).
- **훈련으로 만든다.** 이번에 막힌 지점(연락이 안 됨, 백업을 못 찾음, 결정권자를 모름)이
  다음에도 똑같이 막힌다. 절차 문서보다 **연락망과 결정권자**가 먼저다.

## 9. GIJO AS에서 무엇이 되나

- **대화창 초동 절차** — 「침해사고 의심되는데 어떻게 대응해?」처럼 **침해를 말하면서
  「어떻게·절차·대응·뭐부터·초동」을 함께 물으면**, 코드로 고정된 7단계(증거 보전 → 격리 →
  범위 식별 → 계정·인증 차단 → 보고·신고 → 근절·복구 → 재발 감시)가 즉시 나온다.
  **모델이 지어내지 않는 결정적 규칙**이다(`server/src/engine/incidentsteps.ts`).
  - 말한 장비 이름이 우리 **보안제품 등록부·자산**에 있으면 담당자까지 함께 보여 준다.
  - 「신고 의무가 어떻게 되나」처럼 **법을 묻는 말**은 법령 조회로 넘어간다. 단 **지금 당하고
    있는 중**(「당했는데 신고 의무부터…」)이면 초동이 먼저 나온다.
  - 「장비가 죽었어」류는 **장애** 초동 절차(별도 5단계)로 갈린다 — 순서가 다르기 때문이다.
- **이 문서의 몫**: 위 7단계는 급할 때 읽는 뼈대이고, 이 문서는 그 위에 **왜 그 순서인지**와
  **어디를 보는지**를 얹는다. AI가 참고할 근거이기도 하다.
- **함께 쓰는 화면**: 자산현황(노출 자산) · 하드닝 점검(설정) · 보안제품 등록부(담당자·계약) ·
  분석 허브(로그 수집·정규화).
- **정직하게 밝히는 한계**: GIJO AS는 포렌식 도구가 아니다. 메모리 덤프·디스크 이미징·악성코드
  분석은 하지 않는다. 이 제품이 돕는 것은 **범위 파악·근거 조회·절차 안내**다.

## 11. ⚠ 확인 필요로 남긴 것

이 문서가 **모른다고 인정한 것들**이다. 컴플라이언스 판단에 쓸 때는 반드시 원문·법무 확인.

- **정보통신망법 제48조의3의 신고 대상 규모 기준**(사업자 규모·피해 규모 하한 등) — 단정하지 않음.
- **중복 신고 면제 여부** — 망법 신고와 개인정보 유출 신고를 각각 해야 하는지, 하나로 갈음되는지.
- **개인정보 보호법 시행령의 「유출 가능성」 관련 개정 시행일** — 확인 안 됨.
- **금융권 등 업권별 보고 의무의 근거 규정 조번호**(전자금융감독규정 등) — 단정하지 않음.
- **KISA 침해사고 신고·상담의 정확한 접수 경로·전화번호**(118 등) — 사고 시점에 재확인.
- **경찰청 사이버수사 온라인 신고처의 정확한 도메인·전화번호** — 재확인 필요.
- **NIST SP 800-61의 최신 개정판 번호와 발간 연도** — 문서 이름만 가리켰다.
- **윈도우 이벤트 ID의 OS 판본별 차이** — 위 표는 널리 쓰이는 값이나, 판본·감사 정책 설정에
  따라 안 남거나 다르게 남을 수 있다.

## 📖 용어 풀이

- **휘발성(volatility)** — 전원·시간에 따라 사라지는 정도. 사라지기 쉬운 것부터 확보한다.
- **격리(containment)** — 번지는 것을 막는 조치. 침해에서는 **전원 차단이 아니라 네트워크 분리**.
- **지속성(persistence)** — 재부팅해도 다시 실행되게 심어 둔 장치(서비스·예약작업·크론·시작 프로그램).
- **측면 이동(lateral movement)** — 한 대를 잡은 뒤 같은 망의 다른 장비로 옮겨 가는 것.
- **C2(Command and Control)** — 감염 장비를 조종하려고 붙는 외부 서버. 아웃바운드 로그에서 잡힌다.
- **웹셸(web shell)** — 웹서버에 올려 두고 브라우저로 명령을 실행하는 악성 스크립트 파일.
- **무결성 해시** — 파일의 숫자 지문(SHA-256 등). 「고치지 않았다」를 보이는 근거.
- **정보주체** — 개인정보가 가리키는 그 사람 본인. **통지**의 상대다(신고는 기관에 한다).
- **고유식별정보 / 민감정보** — 주민등록번호·여권번호 등 / 건강·사상·노조 가입 등. 둘 다 신고 대상.
