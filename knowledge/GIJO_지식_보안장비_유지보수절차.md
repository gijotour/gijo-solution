# 보안 장비 유지보수 표준 절차 (정기점검·장애 대응·계약 관리)

(GIJO AS 지식베이스용 — 2026-07 인터넷 리서치 + 국내 유지보수 실무 관행 기반. 출처: 국내 정보보안점검 체크리스트(법제처 부록)·유지관리 실무 점검표·벤더 공식 명령 레퍼런스)

## 1. 월간 정기점검 체크리스트 (방화벽·IPS/IDS·WAF·VPN·EDR·DLP·NAC 공통 7항목)

**방화벽 월간 정기점검 절차**를 물으면 이 7항목이 답이다 — 장비 종류가 무엇이든(방화벽, IPS,
WAF, VPN 게이트웨이, EDR, DLP, NAC) 월간 점검에서 확인할 것은 같다.

> ⚠ **「방화벽 정책 정기 점검」과 다른 절차다.** 그쪽은 룰셋을 손보는 일(무적중 룰 정리·최소권한
> 검토)이고, 여기는 **장비가 건강한지** 보는 일(자원·이중화·시그니처·인증서·백업·로그·펌웨어)이다.
> 월간 점검 보고서에 들어가는 것은 이 7항목이다.

국내 유지보수 계약의 표준은 월간(또는 분기) 정기점검 + 점검 보고서 제출이다. 공통으로 확인할 7가지:

1. **자원 상태**: CPU·메모리 사용률, 동시 세션 수, 디스크(로그 파티션) 용량. 평시 대비 급증 여부를 본다.
2. **이중화(HA) 상태**: Active/Standby 정상 여부, 최근 절체(failover) 이력, 설정 동기화 상태. 절체 이력이 있으면 원인을 반드시 규명한다.
3. **시그니처·패턴 최신성**: IPS/AV 시그니처 버전과 배포일, 업데이트 라이선스 만료일. (FortiGate=FortiGuard, Palo Alto=Dynamic Updates, 국산 장비=자체 업데이트 서버)
4. **펌웨어/OS 버전**: 현재 버전, 벤더 권고 버전, EoS(단종)·EoL 일정. 보안 패치 미적용 방화벽은 그 자체가 취약점이다.
5. **정책·설정 백업**: 설정 백업 파일 최신본 확보(변경 작업 전후 필수), 정책 변경 이력 검토(불필요·중복 정책 정리).
6. **로그 수신·저장 상태**: syslog/관제 전송 정상 여부, 로그 유실·시간 불일치 확인. **NTP 시간동기**가 어긋나면 침해사고 때 로그 대조가 불가능해진다.
7. **이상 이벤트 리뷰**: 차단 로그 상위 출발지(스캔 시도), 허용 트래픽 급증, 관리자 로그인 실패 반복 등.

## 2. 장비별 점검 명령 요약

| 점검 항목 | FortiGate | Palo Alto(PAN-OS) | Cisco ASA |
| --- | --- | --- | --- |
| 버전·라이선스 | get system status | show system info | show version |
| 자원(CPU·세션) | get system performance status | show system resources | show cpu usage / show conn count |
| 이중화(HA) | get system ha status | show high-availability all | show failover |
| 설정 백업 | execute backup config | Export named config snapshot | copy running-config |
| 시그니처 갱신 | FortiGuard 자동/수동 | request content upgrade | (Firepower 정책 배포) |

국산 장비(SECUI MF2·TrusGuard·SNIPER)는 웹 관리콘솔의 시스템 상태·업데이트 메뉴에서 동일 항목을 확인하며, 세부 명령은 장비별 관리자 매뉴얼을 따른다.

## 3. 장애 대응 표준 절차 (5단계)

장비가 갑자기 죽었을 때, 다운됐을 때, 먹통이 됐을 때, 응답이 없을 때, 통신이 안 될 때 — 즉 방화벽·IPS 등 보안 장비 장애가 발생하면 아래 5단계 순서로 대응한다. 당황해서 바로 재부팅하는 것이 가장 흔한 실수다.

1. **증상 기록**: 발생 시각, 영향 범위(전체 통신 두절인지 특정 구간인지), 직전 변경 작업 유무.
2. **로그 확인**: 장비 이벤트 로그(하드웨어 오류·프로세스 재시작·HA 절체)와 콘솔 메시지를 확보한다. 재부팅 전에 로그부터 백업한다 — 재부팅하면 원인 증거가 사라지는 경우가 많다.
3. **이중화 절체 확인**: HA 구성이면 Standby로 절체됐는지, 서비스가 살아있는지 먼저 확인(서비스 복구가 최우선).
4. **유지보수사·벤더 접수**: 유지보수 계약 번호·장비 시리얼·증상·로그를 갖춰 기술지원(TAC) 접수. 하드웨어 불량이면 RMA(교체) 절차.
5. **조치 보고**: 원인·조치 내용·재발 방지책을 장애 보고서로 남기고, 같은 원인의 재발 여부를 다음 정기점검에서 확인한다.

## 4. 유지보수 계약 관리 요소

- 계약 정보: 유지보수사·계약 기간·요율·대응 SLA(예: 장애 접수 후 4시간 내 현장 도착).
- 자산 정보: 모델·시리얼·설치 위치·도입일·**EoS/EoL 일정**(단종 장비는 교체 계획 수립).
- 이력 관리: 정기점검 보고서(월간/분기), 장애 이력, 펌웨어 업그레이드 이력, 정책 변경 승인 이력.

## 5. GIJO AS와의 연계 (제품에서 어떻게 쓰나)

- **유지보수 메뉴**: 장비별 계약·점검 일정·이력을 등록하면 만기·점검 도래 알림을 받는다.
- **보안제품 등록부**: 장비 대장(모델·시리얼·EoS) 관리 지점.
- **분석 허브**: 장비 syslog·정기점검 리포트를 올리면 3소스(스캐너·로그·운영리포트) 상관분석에 들어간다.
- **하드닝 점검(kisa_net)**: 네트워크 장비 설정 점검을 원격 CLI로 자동화 — 정기점검의 4·5번 항목을 자동 수행.
- **원격 정기점검 스케줄**: 하드닝 스케줄러에 장비 IP를 등록하면 주기 점검·관제 대시보드 반영.
